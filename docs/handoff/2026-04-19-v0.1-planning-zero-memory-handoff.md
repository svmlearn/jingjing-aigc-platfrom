## 2. 当前阶段结论

已经完成的核心判断：

- `social-auto-upload` 最适合承担发布执行层
- `AIWriteX` 最适合借内容工作流、模板系统、文章管理思路
- `MediaCrawler` 最适合承担内部版内容导入能力参考，尤其是 `detail / creator / comments`

当前版本前提已调整为：

- **先按内部自用版设计**
- 不按正式面向第三方 SaaS 的严格商业化版本设计

这带来的直接影响：

- `MediaCrawler` 的 `creator / detail / 评论抓取` 在当前阶段可以先保留为内部工具链能力
- 但未来如果走正式商用产品，需要重新评估或替换

## 4. 当前共识

### 4.1 V0.1 的核心不是“全网自动抓取平台”

而是跑通这条闭环：

1. 导入对标内容
2. 提取标题 / 结构 / 口播 / 评论角度
3. 基于商家画像改写
4. 发布到自己的小红书 / 抖音账号

### 4.2 当前阶段保留的导入能力

当前已确认保留：

- `detail` 导入
- `creator` 导入
- 评论抓取

但当前不做：

- 全自动批量抓某个博主全部历史内容
- 长期无人值守监控式抓取

### 4.3 商家知识库的定义

当前已统一成：

- **商家画像**

它不是泛泛的品牌库，而是用于改写输入的业务画像层，至少包含：

- 商家信息
- 门店信息
- 目标客群画像
- 主打项目 / 服务
- 卖点
- 地域信息
- 语气风格
- 禁用词
- CTA

### 4.4 当前版本最值得真正接入的开源能力

优先级最高的是：

- `social-auto-upload` 的发布执行层

当前对另外两个项目的态度：

- `AIWriteX`：借工作流和模板化思路，不直接拿来当产品壳
- `MediaCrawler`：当前内部验证版可保留 `creator / detail / comment` 能力，但不要把它直接当未来正式商用底座

## 5. 当前 V0.1 功能清单摘要

`V0.1` 文档已经落下，当前功能清单可以概括为：

### 必做

- 对标内容导入
- 评论抓取与查看
- 商家画像知识库
- 内容拆解与改写
- 内容草稿中心
- 审核与发布准备
- 小红书 / 抖音多账号发布
- 发布任务记录

### 可选增强

- 关键词搜索导入
- 热点辅助输入
- 评论总结为改写提示

### 明确不做

- 全自动批量全历史抓取
- 数字人链路
- 镜头级分镜拆解
- 正式多租户 SaaS
- 团队权限系统
- 泛平台扩展

- `AudienceProfile`

- `ContentVariant`
- `PublishingAccount`
- `PublishJob`

目标：

- 先定“够用的最小数据模型”

### 6.3 `Supabase + Vercel` 方案评估

这个主题已经明确列入下一轮议程，但本轮还没有展开详细评估。

下一轮建议讨论时聚焦这 3 个问题：

1. `Vercel` 是否只承载管理后台和轻 API
2. `Supabase` 是否承载认证、数据库、对象存储
3. 采集和发布这类任务是否需要单独 Worker 层

当前先不要直接下最终结论。

更好的方式是：

- 先结合页面与数据模型
- 再看 `Supabase + Vercel` 是否匹配
