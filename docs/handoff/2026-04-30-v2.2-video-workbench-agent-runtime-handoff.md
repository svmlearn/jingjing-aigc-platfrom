## 2026-05-01 13:54 最新补充：确认脚本假镜头与 COS 上传停滞

本轮用户反馈：

- 确认脚本前，第一镜是正常的 `00:00-00:03`。
- 点击“确认脚本”后，额外出现一个 `00:00-00:05` 镜头，内容是标题、目标时长、钩子、CTA。
- 上传素材时，“领凭证”很快结束，但上传百分比会卡住，例如 `18%` 停三四分钟。
- 用户担心之前调试过很多次上传，是否服务器或 COS 有旧队列一直排队。

本轮结论：

- `00:00-00:05` 假镜头不是模型生成的，是确认脚本后结构化镜头 `productionScenes` 丢失，前端退回解析 `scriptText`，旧解析器把脚本文本前言当成第一镜。
- 素材上传没有应用服务器队列。链路是浏览器直传 COS：领凭证 -> COS SDK 上传 -> complete 登记。仓库里没有素材上传 worker 或 pending upload queue。
- 之前调试上传不会在本应用服务器里堆积旧上传队列来阻塞新上传。COS 侧可能存在未完成 multipart 分片，但通常不阻塞新上传；需要时可单独在腾讯云侧清理。

本轮改动：

- `app/src/components/merchant/video-workbench.tsx`
  - 确认脚本时把接口返回 variant 与当前 selected variant 合并。
  - 当接口返回没有 `productionScenes` 时，保留确认前结构化镜头。
  - `parseScriptTextToScenes` 解析纯文本前，先跳过第一个 `Scene n |` / `镜头 n：` / `【镜头 n】` 之前的前言。
- `app/src/lib/ui/video-workflow.ts`
  - COS 上传增加 90 秒无实际进度停滞超时。
  - COS 上传增加 10 分钟总超时。
  - 通过 `onTaskReady` 保存 taskId，超时时尽量调用 `cancelTask` 取消当前浏览器 COS 任务。

## 2026-05-01 补充：二轮对话 Content variant not found

现象：

- 用户先成功生成初版脚本。
- 随后在左侧继续追问“只有 5 秒太少，应该几分钟”。
- 页面报 `Content variant not found.`。

结论：

- 这是普通聊天被过期或不属于当前 draft 的 `variantId` 硬校验拦住。
- 普通聊天应允许使用 `draftId` 兜底读取当前选中脚本。
- 只有明确覆盖修改脚本 / 确认脚本 / 创建视频任务这类动作，才必须绑定具体 variant。

修复：

- `app/src/server/api/content-generation-service.ts`
  - 新增当前脚本软解析逻辑：先试 `contentVariantId`，失败时按 `draftId` 找当前 `selectedVariant`。
  - `intent = revise` 时仍保持更严格要求。
- `app/src/components/merchant/video-workbench.tsx`
  - 只在 `contentVariantId` 属于当前 `draftId` 时发送它。
  - 避免 URL/localStorage 残留旧 variant 影响本轮聊天。
