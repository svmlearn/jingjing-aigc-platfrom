# V2.3 Team 内容日历驱动生成实施计划

状态：`已实现，待验收 / 待合并`
分支：`codex/v2.3-calendar-content-prd`
来源 PRD：`docs/产品文档/V2.3-内容日历驱动图文视频生成PRD.md`
长任务门禁：`2026-05-10 16:42 Asia/Shanghai` 已通过，Completion Gate 可交付。

## 1. 核心判断

不新起项目，在现有项目基础上改。

原因：

- 现有项目已经具备登录、商家资料、知识库、素材中心、咨询台、图文草稿、视频脚本、视频任务、COS 和 worker 链路。
- 新需求不是推翻底座，而是把现有“咨询驱动内容日历”调整为“team 管理员咨询台策划 + team 成员今日任务流生成”。
- 最小实现可以把当前 `merchant_profiles` 视为 team 载体，避免先做完整多团队后台。

## 2. 目标产品链路

```text
team 管理员登录
-> 在咨询台与 Agent 聊近期选题
-> Agent 生成 / 更新 team 内容日历
-> team 成员通过小程序 / H5 / 轻客户端登录
-> 进入今日 / 本周任务流
-> 系统基于 team 内容日历 + 共享知识库 + 共享素材生成个人任务
-> 成员生成图文或视频脚本
-> 成员按脚本上传素材并点击 AI 一键剪辑
-> 图文 / 脚本 / 视频任务 / 成片进入我的内容
```

## 3. 数据改造

### 3.1 Team 载体

V1 不新增独立 `teams` 表。

默认规则：

- `merchant_profiles.id` 即 team id。
- `merchant_profiles.owner_user_id` 是 team 管理员。
- 新增成员表表达“某个 auth user 属于哪个 merchant/team”。

### 3.2 成员表

新增表建议：

```text
merchant_team_members
- id
- merchant_id
- user_id
- role: owner | member
- status: active | disabled
- display_name
- invited_by_user_id
- created_at
- updated_at
```

兼容规则：

- migration 需要为现有 `merchant_profiles.owner_user_id` 自动补一条 `owner` 成员记录。
- 所有读取 merchant 的服务层，从“只能按 owner_user_id 找 merchant”升级为“按 user_id 找 active team membership”，owner 兼容旧逻辑。

### 3.3 Team 内容日历

短期不一定新增独立 team calendar 表。

第一阶段可复用：

- `merchant_strategy_assets.strategy_snapshot.contentCalendarDraft`

它已经是 merchant 级策略资产，天然适合作为 team 内容日历来源。

如果实现中发现需要记录确认状态和版本，再新增：

```text
team_content_calendars
- id
- merchant_id
- source_session_id
- date_from
- date_to
- title
- status
- calendar_snapshot
- created_by_user_id
- confirmed_at
- created_at
- updated_at
```

### 3.4 成员今日任务

建议新增表：

```text
daily_content_tasks
- id
- merchant_id
- user_id
- task_date
- team_calendar_source
- theme
- article_task
- video_task
- knowledge_refs
- material_refs
- status
- created_at
- updated_at
```

唯一约束：

```text
merchant_id + user_id + task_date
```

目的：

- 用户刷新后任务不变。
- 管理员更新 team 日历后，不覆盖成员已经生成的当天任务。

## 4. 服务层改造

### 4.1 Merchant / Team 访问解析

新增统一方法：

```text
getOperationalMerchantForUser(userId)
```

职责：

- owner 用户按旧逻辑取自己的 merchant。
- member 用户按 `merchant_team_members` 找所属 merchant。
- 返回 merchant profile、team role、membership id。

替换重点：

- dashboard layout 权限校验。
- merchant profile API。
- consultation service。
- content generation service。
- knowledge service。
- material service。
- video job service。

### 4.2 咨询台作为 team 选题入口

不需要重写咨询台。

改造重点：

- 管理员发送咨询消息后，继续让 Agent 更新 `strategySnapshot.contentCalendarDraft`。
- UI 文案从“AI 咨询诊断”调整为“团队选题”。
- 内容日历侧栏说明改为“确认后会影响团队成员今日任务”。
- 普通成员默认不进入咨询台。

### 4.3 今日任务服务

新增服务：

```text
getOrCreateDailyContentTasksForUser(userId, date)
```

生成依据：

- 用户所属 merchant/team。
- `merchant_strategy_assets.strategySnapshot.contentCalendarDraft`。
- merchant profile。
- merchant knowledge chunks。
- material library。
- 当天日期。
- 用户 id，用于稳定分配差异化角度。

输出：

- 今日图文任务。
- 今日视频任务。
- 未来 7 天预览。

### 4.4 图文生成

现状问题：

- `POST /api/content/article-drafts` 要求 `sessionId`。

改造：

- schema 支持 `source = daily_task`。
- `sessionId` 改为 daily task 模式下可选。
- 生成上下文从 daily task 和 merchant strategy asset 组装。
- `input_snapshot` 记录 `dailyTaskId`、`teamTheme`、`teamCalendarSource`、`knowledgeRefs`、`materialRefs`。

### 4.5 视频脚本生成

现状问题：

- 视频工作台 agent 没有 session 时会提示回咨询台。

改造：

- 支持 `source = daily_task`。
- 没有 session 时，用 daily task + merchant strategy asset + knowledge refs 组装脚本 brief。
- 保留现有素材上传、脚本确认、创建 video job 链路。

## 5. 页面改造

### 5.1 Web 商家端

Web 商家端主要服务 team 管理员和少数核心销售，不是最终成员端。

管理员 / 核心销售 Web 导航建议：

```text
团队选题 | 今日任务预览 | 图文工作台 | 视频工作台 | 素材中心 | 我的内容 | 用户信息
```

Web 今日任务页用于内测和接口验收，不能把完整 Web dashboard 当作中介成员的最终产品形态。

### 5.2 成员轻客户端

成员端优先按小程序 / H5 / 轻客户端设计。

成员只需要：

```text
今日 | 本周 | 上传素材 | 我的内容
```

成员端能力：

- 查看今日图文 / 视频任务。
- 查看未来 7 天营销日历。
- 复制图文内容包。
- 查看视频脚本、拍摄提示和所需素材。
- 上传口播和现场素材。
- 点击 AI 一键剪辑。
- 查看视频任务状态和成片。

### 5.3 `/dashboard`

改成今日任务流预览，主要用于 Web 内测。

页面必须展示：

- 今日团队主题。
- 今日图文任务。
- 今日视频任务。
- 未来 7 天预览。
- 生成图文入口。
- 生成视频脚本入口。
- 资料不足降级提示。

### 5.4 咨询台入口

将旧咨询台保留到：

```text
/dashboard/consultation
```

或作为管理员专属“团队选题”入口。

### 5.5 图文 / 视频工作台

继续复用现有页面，但支持：

- `dailyTaskId`
- `source=daily_task`
- 无 `sessionId`

### 5.6 API 优先级

因为成员端可能不是 Web，实现优先级应为：

1. team / 成员 / 今日任务数据模型。
2. 今日任务 API。
3. 图文生成 API 支持 `dailyTaskId`。
4. 视频脚本 API 支持 `dailyTaskId`。
5. 素材上传 API 复用现有媒体链路。
6. 一键剪辑 API 复用现有 `video_edit_jobs`。
7. Web 页面作为内测预览和管理员工作台。

## 6. 验证标准

必须通过：

- `cd app && pnpm typecheck`
- `cd app && pnpm lint`
- `cd app && pnpm build`
- 相关单测或新增最小测试。

手动验收：

- owner 能进入团队选题。
- 成员能通过 API 获取今日任务和未来 7 天日历。
- 无咨询 session 能生成图文。
- 无咨询 session 能生成视频脚本。
- 视频脚本仍能走上传素材和一键创建剪辑任务。
- 我的内容能看到生成结果。

## 7. 风险

- 现有 RLS 多处使用 `merchant_profiles.owner_user_id = auth.uid()`，成员账号会被挡住；服务端 admin client 路径可先跑通，但长期需要补 RLS。
- 当前注册邀请码会创建新 merchant，不适合作为成员加入同一 team；需要新增 team invite 或后台创建成员机制。
- `merchant_memberships` 已存在但语义是订阅会员，不应用作团队成员表。
- 如果没有真实素材 URL 或 COS 资产，图文配图和视频素材匹配只能先做降级提示。

## 8. 本轮实现结果

本轮已在当前分支完成 V2.3 最小闭环：

- 新增 `merchant_team_members`、`daily_content_tasks` migration。
- 新增团队成员 / owner 工作区解析，保留旧 owner 逻辑，同时允许成员按 team 读取商家上下文。
- 新增 `/api/daily-content-tasks`，可按用户稳定生成今日任务和未来 7 天任务。
- 新增 `content_drafts.created_by_user_id` 与 `video_edit_jobs.created_by_user_id`，把“我的内容”从 merchant 级收窄到成员个人级。
- 将商家端首页改为“今日任务预览”，并保留 `/dashboard/consultation` 作为“团队选题”入口。
- 新增 `/member` H5 轻客户端预览入口，用于证明成员端不需要完整 Web dashboard。
- 图文生成支持 `source = daily_task`，`sessionId` 在今日任务模式下可为空。
- 视频脚本 Agent 支持 `source = daily_task`，无咨询 session 时使用今日任务 + 共享策略资产组装脚本上下文。
- 视频工作台继续复用已有脚本确认、素材上传、创建 video job、worker 剪辑链路。
- 内容列表、内容详情、视频任务列表/详情/重试/取消、素材上传 owner 校验均按当前 `userId` 过滤，避免同一 team 成员串内容。
- 本地 demo 成功视频任务返回 placeholder result asset；真实渲染资产仍由 Supabase + COS + video worker 负责。
- Web 入口只作为管理员 / 内测预览；成员端产品形态仍按小程序 / H5 / 轻客户端理解。
