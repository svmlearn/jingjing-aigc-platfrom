### 3.0 当前资源判断结论

基于 2026-05-13 staging 服务器监控和 worker 运行日志，当前判断需要从“先拆两台服务器”调整为“先买一台相对稳的国内服务器混跑验证”。

已知事实：

- 当前 staging 是 2 核 4G，能跑通单个视频任务，但 CPU 峰值已到 `96.933%`，内存峰值已到 `3275.333MB / 95.206%`。
- 现有 worker 代码默认并强制 `WORKER_MAX_CONCURRENCY = 1`，当前成功任务也是排队一条一条跑，不是并发跑。
- OpenStoryline / FireRed 不跑本地大模型，不需要 GPU；但仍会消耗 Docker、FFmpeg、CPU torch、转场/切镜、ASR/embedding、临时文件、对象存储上传下载等资源。
- 当前卡住和超时不一定只靠加机器解决，还要补任务耗时拆解、超时策略、重试、日志和 signed URL 刷新。

结论：

```text
2 核 4G：只能证明单个视频链路能跑通，已贴边，不建议承载 Web/API + worker。
4 核 8G：可以低成本验证单并发 worker + Web/API，但视频任务期间仍可能影响前台访问。
8 核 16G：建议作为第一阶段国内验证服务器，Web/API + worker + FireRed 单机混跑，先按单并发跑稳。
16 核 32G：适合后续认真验证 2-3 个视频任务并发，或当 8 核 16G 压测数据显示 CPU/内存/IO 贴边时升级。
```

第一阶段推荐购买：

```text
1 台国内服务器：8 核 16G
系统盘：100G 起
数据盘：300G SSD 起，500G 更从容
公网带宽：10Mbps 起
系统：Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS
用途：Next.js / Node API / Nginx / Docker / video-worker / FireRed
```

暂不建议一开始就买四台机器，也不建议为了“测试/灰度/正式”马上拆成多套。验证期先一台阿里云 ECS 混跑服务器 + 阿里云 RDS PostgreSQL 基础系列 + 阿里云 OSS，开发测试可以靠 staging 配置、分支、队列和小流量数据隔离。

### 3.2 什么时候再拆 Worker / FireRed 服务器

第一阶段不强制单独购买 worker 服务器。只有出现下面情况时，再拆第二台：

- 视频任务执行时，Web/API 明显变慢或 5xx 增多。
- 8 核 16G 单机在单并发下 CPU、内存或磁盘 IO 长时间贴边。
- 需要把 worker 并发从 1 提到 2 或 3。
- 视频生成耗时明显变长，队列等待时间影响业务体验。
- 需要让 Web/API 和 worker 独立发布、独立扩容、独立回滚。

后续拆分时推荐结构：

```text
Web/API 服务器：4 核 8G 起
Worker 服务器：8 核 16G 起；2-3 并发建议 16 核 32G 起
```

## 7. 风险和注意事项

### 7.1 只用 IP 的限制

只用 IP 可以验证主链路，但不适合正式使用。

限制：

- PWA 安装体验不完整。
- HTTPS 不方便。
- Cookie、回调、CORS 配置不如域名稳定。
- 用户信任感差。

因此：

```text
IP 阶段只做技术验证。
正式 PWA 仍然需要域名和 HTTPS。
```

### 7.2 国内服务器不等于自动稳定

国内化能解决跨境访问、上传和下载问题，但不能自动解决：

- worker 卡死。
- AI / VLM / TTS provider 慢。
- FireRed 渲染失败。
- 任务状态不回写。
- 数据库锁或连接泄漏。

所以必须补：

```text
heartbeat
timeout
retry
failure_reason
log_payload
阶段耗时
```

### 7.3 不要一次性迁全量

第一批只迁视频主链路。

不要让这些内容阻塞验证：

- 完整后台。
- 完整咨询 agent。
- 完整知识库。
- 完整批量内容日历。
- 所有历史数据。

### 10.3 产品内必须落地的同意和风控

- 上传声音前，单独勾选声音克隆授权。
- 上传自拍视频 / 图片素材前，确认素材是本人或已经获得合法授权。
- 明确禁止冒用他人肖像、声音进行虚假宣传、诈骗、冒充、侵权或违法营销。
- 提供素材删除、音色删除或停用入口。
- 后台记录用户授权时间、协议版本、授权范围、撤回记录。
- AI 生成 / AI 合成内容需要显式标识；后续导出文件按监管要求补隐式标识或元数据方案。
- RunningHub、阿里云 RDS、阿里云 OSS 等第三方处理方写入隐私政策和第三方共享清单。

### 10.4 数据存放原则

```text
自拍视频 / 图片素材 / 声音音频 / 成片视频：放 OSS
```
