## 2. 当前核心判断

`ba-ba-ke.com` 已确认是国内公司主体，之前担心“域名可能挂在香港公司、无法转国内主体”的前提不成立。当前只是部署 / 解析在新加坡服务器，这不影响后续迁到大陆服务器、大陆对象存储和大陆 PostgreSQL。

目标用户主要是国内房产中介时，大陆服务器 + 大陆对象存储 + 大陆数据库是长期更稳的方案。香港方案保留为快速试运营备选，但不再是当前优先路线。

当前判断：

| 条件 | 推荐路线 |
| --- | --- |
| `ba-ba-ke.com` 已是国内公司主体，可走备案路径 | 优先走阿里云大陆 ECS、大陆备案、阿里云 OSS、阿里云 RDS PostgreSQL |
| 只是 phase1 技术验证，不急正式上线 | 先用 IP 跑通链路，暂不被域名 / ICP / HTTPS 卡住 |
| 大陆备案材料或采购流程临时受阻，又要尽快试运营 | 香港服务器、香港 COS/OSS、香港 PostgreSQL 可作为备选 |
| 后续要给国内中介规模化长期使用 | 尽量回到大陆备案路线 |

后续待确认：

1. 国内公司是否可以作为 ICP 备案主体，并承担后续云账号、域名、服务器实名一致性。
2. 域名注册商控制权和 DNSPod 解析权限是否在手里。
3. 备案材料是否齐全。
4. phase1 是否先买 1 个月 IP 验证资源，备案型服务器时长后置到正式备案阶段。

选择阿里云的当前理由：

- 公司已有阿里云企业账号，采购、发票、实名、备案主体更容易统一。
- 阿里云 8 核 16G ECS 当前购买页价格低于已记录的腾讯云 CVM 配置。
- ECS、RDS PostgreSQL、OSS、ICP备案入口统一在阿里云，后续排障、账单、权限和工单更清楚。
- 现有腾讯 COS 链路可以作为历史 staging 事实保留；国内正式资源新建时统一换成阿里云 OSS。

### 8.3 香港方案的边界

香港服务器不用大陆 ICP 备案的前提是：

```text
域名解析到香港服务器
对象存储在香港
数据库在香港
不使用中国大陆服务器作为 Web 接入
不使用中国大陆 CDN 节点加速
不把对象存储自定义域名接到大陆需要备案的资源上
```

香港方案可以配 HTTPS，也可以做 PWA。PWA 需要的是 HTTPS 安全上下文，不是必须 ICP。

但香港方案不能顺手解决大陆 CDN 加速问题。如果要使用中国大陆 CDN 节点给国内用户加速，通常仍然需要域名完成 ICP 备案。也就是说，香港方案的优势是快和免大陆备案，不是国内访问质量最优。

对国内用户的实际影响：

| 链路 | 香港方案可用性 |
| --- | --- |
| 手机打开 PWA 页面 | 通常可用 |
| 登录 / API 请求 | 通常可用 |
| 上传视频素材 | 可用，但跨境链路可能慢或波动 |
| 下载生成视频 | 可用，但跨境链路可能慢或波动 |
| 国内 CDN 加速 | 不应作为免备案方案的一部分 |

### 8.4 香港 vs 大陆的取舍

| 方案 | 优点 | 风险 / 代价 |
| --- | --- | --- |
| 香港服务器 + 香港对象存储 + 香港数据库 | 不等大陆 ICP，最快可试运营；适合 `ba-ba-ke.com` 无法转国内主体时使用 | 国内用户跨境访问，视频上传下载稳定性不如大陆；不能直接解决大陆 CDN 加速 |
| 大陆服务器 + 大陆对象存储 + 大陆数据库 | 国内用户体验更稳，适合长期给中介规模化使用 | 需要国内公司主体、域名实名、ICP 备案、服务器购买时长满足备案要求 |

当前建议：

1. `ba-ba-ke.com` 已确认是国内公司主体，当前优先走大陆路线。
2. 香港路线只保留为大陆备案或采购流程临时受阻时的快速试运营备选。
3. phase1 可以先用 IP 跑通技术链路；正式域名 / HTTPS / PWA 安装体验放到备案和域名切换阶段。
4. 无论大陆还是香港，都尽量同一家云闭环：服务器、对象存储、PostgreSQL 不要跨云混搭。
