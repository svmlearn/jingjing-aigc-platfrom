### 2. agent-assets-api 新 API 未 await 异步后台鉴权

`codex/v2.2-agent-assets-api` 初次临时集成 lint/build 通过，但发现新增 Agent / Skill / Knowledge Set API 调用：

```ts
assertPlatformAdminAccess(request);
```

在 auth/RBAC 合入后，`assertPlatformAdminAccess` 已是异步函数；不 `await` 会导致未登录/无权限请求可能继续执行 service-role repository 写操作。

处理：

- 将新增 API 中的调用统一改为：

```ts
await assertPlatformAdminAccess(request);
```

- 补做无 cookie 冒烟，抽测新增 API 返回 `401 UNAUTHORIZED`

修复提交：

- `53dbbe6 Fix agent assets API admin guard awaits`

### 3. admin-console-ui 初次集成覆盖了 RBAC UI 语义

`codex/v2.2-admin-console-ui` 初次临时 merge 到 main 出现 4 个冲突文件：

- `app/src/app/platform-admin/settings/page.tsx`
- `app/src/components/platform-admin/platform-admin-content.tsx`
- `app/src/components/platform-admin/platform-admin-shell.tsx`
- `app/src/components/platform-admin/platform-settings-editor.tsx`

关键问题不是单纯样式冲突，而是 UI 分支覆盖了 auth/RBAC 分支的权限语义：

- `currentAdmin` 未继续传入后台壳子/系统配置页
- `canManageSettings` 被弱化
- `PlatformAdminUsersPanel` 有丢失风险
- 邀请码 `canManageInvitationCodes` / `canManage` 有丢失风险

处理：

- UI 分支合入最新 main 并解决冲突
- 保留暗色后台 UI
- 同时保留：
  - `PlatformAdminShell currentAdmin`
  - 角色展示
  - `PlatformSettingsEditor currentAdmin`
  - `canManageSettings`
  - admin 只读、super_admin 可保存
  - `PlatformAdminUsersPanel`
  - 邀请码 `canManageInvitationCodes`
  - `InvitationCodeStatusAction canManage`

修复提交：

- `7ef2b65 Merge branch 'main' into codex/v2.2-admin-console-ui`
