# V2.1 商家知识库与记忆录入实现记录

日期：2026-04-29

分支：`codex/v2.1-merchant-knowledge-memory`

工作区：`/Users/wy/Desktop/静境/静境4.0/v2.1-merchant-knowledge-memory`

## 本轮目标

把《V2.1-商家知识库与咨询上下文补强-PRD》中的商家侧能力落到可运行实现：

1. 商家设置内新增「商家知识库」入口。
2. 商家侧支持「知识库上传」和「记忆录入」两类输入。
3. 知识库上传仅支持 `.txt` / `.md` 文件，并要求命名。
4. 记忆录入作为用户可编辑的商家 memory，和文件上传分开建模。
5. 咨询上下文组装时检索平台方法论与商家上下文，并把 RAG 命中片段插入回复链路。

## 已完成

### 后端 API

- 新增 `GET /api/merchant-knowledge/documents`：列出当前商家的知识库文档与商家记忆。
- 新增 `POST /api/merchant-knowledge/documents`：
  - `action=document`：上传 `.txt` / `.md`，要求 `title`。
  - `action=memory`：新建商家记忆，要求 `title` 与 `textContent`。
- 新增 `PATCH /api/merchant-knowledge/documents/[documentId]`：
  - 文件类知识仅允许改标题。
  - 记忆类内容允许改标题与正文，并重新入库。
- 新增 `DELETE /api/merchant-knowledge/documents/[documentId]`。
- 新增 `POST /api/merchant-knowledge/documents/[documentId]/retry`。

### 服务层与数据规则

- 商家知识库文档使用 `scope=merchant` 与当前商家绑定。
- 文件上传的 metadata 使用：
  - `sourceType=file`
  - `contentKind=merchant_document`
  - `chunkPolicy=auto`
- 记忆录入的 metadata 使用：
  - `sourceType=memory`
  - `contentKind=merchant_memory`
  - `chunkPolicy=single`
  - `sourceText=<用户录入正文>`
- 记忆录入当前限制为 1000 个可见字符。
- `queued` 的 UI 文案落为「队列中」。
- 商家侧暂不引入 `knowledge_sets`。

### 商家端 UI

- 在商家设置中新增「商家知识库」tab。
- 新增 `MerchantKnowledgeLibrary` 组件：
  - 左侧/顶部操作区提供「知识库上传」和「记忆录入」。
  - 文件上传要求标题与文件。
  - 记忆录入要求标题与正文，并显示 1000 字计数。
  - 列表支持状态展示、编辑、重试、删除。

### 咨询上下文

- 咨询链路的工具卡从单纯知识检索改为「检索平台方法论与商家上下文」。
- RAG 命中结果保留 `scope`，可区分平台方法论与商家上下文来源。
- 命中片段会作为 knowledge context 注入咨询回复。

### 平台方法论边界

- 平台后台知识入口命名收口为「平台方法论知识库」。
- 平台后台知识文档列表只返回 `scope=platform`、`merchantId=null` 的平台方法论文档。
- 平台后台上传接口强制写入 `scope=platform`，不再允许客户端通过 `scope=merchant` 或 `merchantId` 代维护商家知识库。
- 平台后台设置页的咨询工具文案改为「检索平台方法论与商家上下文」。

## 注意事项

- 本轮未引入商家侧 `knowledge_sets`。
- 大文件、图片、视频等 COS 存储仍属于后续文件资产链路，本轮只覆盖 `.txt` / `.md` 文件与文本记忆。
- 记忆正文当前存在 `metadata.sourceText` 中，方便编辑和 retry；RAG chunk 仍落在现有 `knowledge_chunks` 数据结构。
- 为让 `npm run lint` 通过，本轮在两个既有组件中补了最小范围的 lint 说明，未改动业务行为。
- 当前本地 demo ingestion 是同步处理，通常直接从 `uploaded` 进入 `processing` 再到 `indexed/failed`；UI 已覆盖 `queued=队列中` 文案，但真正异步队列流转属于后续 worker 化范围。
