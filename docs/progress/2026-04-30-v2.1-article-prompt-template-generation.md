# V2.1 图文工作台提示词模板生成实现记录

日期：2026-04-30

分支：`codex/v2.1-article-prompt-templates`

工作区：`/tmp/v2.1-article-prompt-templates`

## 本轮目标

把《V2.1 图文工作台提示词模板生成 PRD》落成第一版可运行实现：

1. 图文工作台不引入 CrewAI，不做后台 prompt 配置。
2. 通过代码内置 prompt 直接调用现有 OpenAI-compatible LLM runtime。
3. 支持 `createPrompt`、`rewritePrompt`、`revisePrompt` 三种模式。
4. 生成结果继续写入 `content_drafts` 和 `content_variants`。
5. LLM 不可用或 JSON 不可解析时保留模板 fallback，并在 trace 中明确记录。

## 已完成

### Prompt 模块

- 新增 `app/src/server/api/article-prompt-templates.ts`。
- 固定 `ARTICLE_PROMPT_VERSION=article-workbench-v20260430`。
- 内置图文 system prompt，约束角色、事实边界、风险表达、参考素材使用规则和 JSON 输出格式。
- 支持：
  - `create`：从内容日历和咨询策略生成 2 到 3 个小红书图文版本。
  - `rewrite`：基于参考素材改写，但只借鉴结构、钩子、节奏和 CTA。
  - `revise`：基于当前版本和自然语言修改意见追加 1 个新版本。
- JSON 解析会清洗标题、正文、hashtags、CTA，并限制 hashtags 最多 8 个。

### 图文生成 API

- 改造 `POST /api/content/article-drafts`。
- 请求 schema 新增 `toneStyle`。
- 生成时组装：
  - `selectedCalendarItem`
  - `strategySnapshot`
  - `merchantProfile`
  - `materialContext`
  - `contentGoal`
  - `extraRequirement`
  - `toneStyle`
- 有 LLM key 时调用 `createChatCompletion`。
- 无 key、runtime 错误或 parse 错误时使用现有模板 fallback。
- `content_drafts.input_snapshot` 新增：
  - `promptMode`
  - `promptVersion`
  - `llmTrace`
  - `riskNotes`
  - `toneStyle`
- `comment_insights` 记录 prompt mode/version 和 risk notes。
- 服务端强制：`mode=rewrite` 时必须存在参考素材。

### 图文修订 API

- 新增 `POST /api/content/article-drafts/revisions`。
- 新增 `reviseArticleDraftForUser`。
- 修订流程：
  - 校验当前 variant 属于当前商家。
  - 校验 variant 类型为 `note`。
  - 读取所属 draft 的 `input_snapshot` 作为原上下文。
  - 使用 `revisePrompt` 生成 1 个新版本。
  - 通过 `appendContentVariantToDraft` 追加新版本，不覆盖旧版本。
  - 新版本自动成为 `selected_variant_id`。
- 修订 trace 追加到 `content_drafts.input_snapshot.revisionTraces`。

### 图文工作台 UI

- 左侧新增「已带入日历卡片」，展示日历卡片 `dayLabel`、`strategyTag`、标题和摘要。
- `平台风格与口吻` 从静态 chip 改为可点击选择，并传给 API。
- 改写模式下没有参考素材时，前端阻断生成并提示先选择素材。
- 生成 fallback 时展示用户可理解提示：
  - `AI 生成服务暂不可用，已先生成一版可编辑草稿。`
- 右侧新增「自然语言修改」区域。
- 点击「按要求修改」会调用修订 API，并追加新版本到当前版本列表。

### 数据访问 helper

- 新增 `assertContentVariantAccess`，用于按商家校验任意内容版本，并可限定 `variantType`。
- 新增 `appendContentDraftRevisionTrace`，用于不改表结构地把修订 trace 写回 `input_snapshot.revisionTraces`。

### SiliconFlow runtime 兜底

- 本地联调发现：即使存在 `SILICONFLOW_API_KEY`，如果 runtime 默认值或 Supabase 旧设置仍指向 `https://api.openai.com/v1`，服务端会用硅基流动 key 请求 OpenAI 默认地址并 fallback。
- 已将默认 LLM runtime 改为 SiliconFlow：
  - `https://api.siliconflow.cn/v1`
  - `Qwen/Qwen3-32B`
  - `Qwen/Qwen3-14B`
- 当当前 key 来源为 `SILICONFLOW_API_KEY` 且 Supabase 旧存 OpenAI 默认地址时，会自动归一到 SiliconFlow 默认 baseUrl/model。
- 详细追溯记录见 `docs/progress/2026-04-30-siliconflow-runtime-defaults-and-supabase-override.md`。
