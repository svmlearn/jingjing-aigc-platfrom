## 背景

依据：

- `docs/产品文档/V2.2-视频工作台脚本协作Agent重构PRD.md`

目标是把视频工作台脚本 Agent 从“每轮强制 JSON 生成器 / 伪工具语义”改成：

## 21:54 后续本地报错修复

用户在本地 `localhost:3000` 视频工作台点击“生成视频脚本”后反馈两类错误：

- 这只说明本地专用 DeepSeek 配置不支持原生 tools；云端 Vercel/Supabase 如未配置 `VIDEO_WORKBENCH_LLM_*`，会走平台通用硅基流动 / Qwen 配置，属于另一套运行环境。

  - local real-chain 同步改成本地可选同步。
  - `LOCAL_REAL_CHAIN_DB_URL` 指向的本地 DB 没启动时，不再阻断内存草稿创建和脚本画布更新。
  - 仍会在 server console 输出 warning，方便需要本地真链路时排查。

## 2026-05-01 三轮修复：修订落库兜底 + 默认脚本长度约束

用户复测后仍出现：

```text
Content variant not found.
```

进一步结论：

- 这不是提示词直接导致的错误，而是当前脚本版本绑定仍有残留硬校验。
- 前一轮已经让 Agent 入口可以按 `draftId` 兜底读取选中脚本，但 `set_video_script(mode = revise)` 真正落库时仍会调用 `updateContentVariantScript(contentVariantId)`，内部再次校验旧 `variantId`。
- 如果前端/URL/localStorage 残留的 `variantId` 与当前 draft 不一致，或旧版本已失效，就会在落库阶段再次报错。
- 另外，提示词和工具说明确实偏弱：原 schema 允许 `scenes.min(1)`，工具说明也没有默认 45-60 秒、5-8 镜头要求，所以模型可能合法地返回 1 个 5 秒镜头。

修复：

- `app/src/server/api/content-generation-service.ts`
  - 修订落库新增 `updateVideoScriptVariantWithDraftFallback`。
  - 先按当前 `contentVariantId` 更新。
  - 若更新时仍 404，则按 `draftId` 重新读取当前 draft 的选中 `video_script` 再更新。
  - 如果 draft 还在但没有可用 `video_script`，则在同一 draft 下创建一个新的 `video_script` 版本，避免普通追问/修订链路被旧 id 卡死。
  - 当请求里的 `contentVariantId` 属于另一个 draft 时，普通聊天不再信旧 variant，明确 revise 才返回可恢复中文提示。
- `app/src/server/api/video-workbench-agent-runtime.ts`
  - system prompt 明确默认生成 45-60 秒完整短视频脚本。
  - 默认 5-8 个镜头，用户要求一分钟时按 60 秒和 6-8 镜头组织。
  - 用户说“太短 / 只有 5 秒 / 一分钟 / 多生成一点”时，要求调用 `set_video_script` 的 `revise` 模式覆盖右侧画布。
  - tool schema 新增 `targetDurationSeconds`，并把 `scenes.minItems` 从 1 提高到 3；默认说明仍要求 5-8 镜头，给极短脚本保留最低 3 镜头空间。
- `app/src/components/merchant/video-workbench.tsx`
  - 加载 draft 时，如果本地缓存的 `selectedVariantId` 不存在于当前 draft，自动丢弃并切到当前 draft 的选中版本。
  - `CONTENT_VARIANT_NOT_FOUND` / `VIDEO_SCRIPT_REVISION_TARGET_REQUIRED` 映射为中文可恢复提示。
- `app/src/server/api/video-workbench-agent-runtime.test.ts`
  - 补充默认脚本长度和多镜头约束测试。

## 2026-05-01 13:54 补充：确认脚本多出 00:00-00:05 与 COS 上传卡进度

现象：

- 用户生成脚本后，正常第一镜为 `00:00-00:03`。
- 点击“确认脚本”后，画布顶部多出一个 `00:00-00:05` 镜头。
- 多出的镜头内容不是模型新生成的镜头，而是脚本文本前言：标题、目标时长、前 3 秒钩子、CTA。
- 上传素材时，“领凭证”阶段 2-3 秒结束，随后卡在上传百分比，例如 `18%` 三四分钟。

确认脚本问题结论：

- Supabase 当前 `content_variants` 表没有持久化 `productionScenes`。
- 前端生成脚本后，`productionScenes` 暂存在当前页面状态里。
- 点击“确认脚本”后，接口返回的是 DB 中的 variant，缺少 `productionScenes`。
- 前端发现结构化镜头为空，就退回 `parseScriptTextToScenes(scriptText)`。
- `scriptText` 由 `buildScriptTextFromSetVideoScript` 拼接，开头有标题、目标时长、钩子、CTA，后面才是 `Scene` / `镜头表`。
- 旧解析器会把 `Scene 1` 之前的前言当成第一个 block，并给它套用 fallback `00:00 - 00:05`，所以出现假的第一镜。

修复：

- `app/src/components/merchant/video-workbench.tsx`
  - “确认脚本”后将接口返回的 approved variant 与当前 selected variant 合并。
  - 如果接口返回没有 `productionScenes`，保留确认前的 `productionScenes`。
  - `parseScriptTextToScenes` 增加前言剥离：从第一个 `Scene n |`、`镜头 n：` 或 `【镜头 n】` 开始解析。
  - 防止标题、目标时长、CTA 等前言再被当成镜头。

COS 上传卡进度结论：

- 当前素材上传链路不是应用服务器排队上传：
  1. `/api/media/upload-intents` 领取 COS 临时凭证。
  2. 浏览器使用 `cos-js-sdk-v5` 直传 COS。
  3. `/api/media/complete` 登记素材资产。
- 仓库内没有素材上传队列或后台上传 worker。
- 之前多次调试上传，不会在本应用服务器里堆积“旧上传队列”来阻塞新上传。
- 如果浏览器当前标签页里有卡住的上传请求，它只影响当前请求；刷新页面或超时后会结束前端状态。
- COS 自身可能存在未完成的 multipart upload 分片，但它们通常不会排队阻塞新的 object 上传；如需清理，需要在腾讯云 COS 控制台或 SDK 层查看/abort multipart uploads。

修复：

- `app/src/lib/ui/video-workflow.ts`
  - 上传阶段已显示为 `领凭证` / 百分比 / `登记素材`。
  - 对 COS 直传增加停滞保护：90 秒没有实际上传进度就失败，并提示“素材上传到 COS 已长时间没有进度，请检查网络后重试。”

  - 尽量通过 COS SDK 的 `onTaskReady` 获取 taskId，失败时调用 `cancelTask` 取消当前浏览器上传任务。
