## 3. 测试策略

### 3.1 覆盖原则

测试用例按 PRD 用户故事和状态机拆分，至少覆盖：

- 主流程：初始化配置、Agent 配置、Skill / Knowledge 维护、调试运行、商家端运行、审计记录。
- 分支流程：多 Agent enabled、默认 Agent 切换、Prompt 草稿 / 发布 / 回滚、Knowledge Set 挂载 / 取消、Skill 依赖提示。
- 异常流程：无 active Prompt、默认绑定异常、知识集未选择、知识索引失败、积分不足、LLM / 工具失败、无 enabled Agent。

### 3.2 执行分层

- 浏览器验收：验证真实线上页面和核心可操作流程。
- 接口 / 数据验收：验证线上 API 返回、测试记录、运行摘要和关键数据落库。
- 代码自动化验证：覆盖不适合直接在线上制造破坏性异常的数据边界和补偿逻辑。
- 受控数据验证：对会影响线上 staging 配置的用例，先记录原始状态，执行后恢复默认入口，并保留 disabled 测试 Agent 作为证据。

### 3.3 状态定义

- `通过`：本轮已在浏览器、接口 / 数据、受控配置或自动化测试中完成验证。
- `自动化验证通过`：已有自动化测试覆盖，但本轮未在线上浏览器复现破坏性异常。
- `未执行`：本轮未执行，需要后续专项测试。
- `不通过`：实际结果不符合预期。
- `阻塞`：因环境、权限、依赖服务不可用导致无法验证。
