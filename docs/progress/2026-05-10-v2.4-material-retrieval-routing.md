# 2026-05-10 V2.4 内容检索与媒体素材分层路由实现记录

## 背景

本轮按 `docs/产品文档/V2.4-内容检索与媒体素材分层路由PRD.md` 推进，目标是先把现有“素材中心 / 图文生成 / 视频脚本 / video worker payload”里的素材混用问题收敛到可执行规则：

- 文案和脚本只拿文本知识与爆款内容做表达依据。
- 图文配图只拿图片素材，缺图片时降级为图片 brief/prompt。
- 视频脚本只输出画面需求，不提前绑定具体剪辑片段。
- video worker 的 `input_assets` 只允许可剪辑视频素材，不再混入图片或爆款文案。

本轮不做真实账号发布，不做完整多模态视频理解 worker，不做图片生成链路。

## 已完成

### 1. 素材用途和检索目标类型

新增代码级合同：

- `MaterialUsageType`
  - `text_knowledge`
  - `viral_reference`
  - `image_asset`
  - `video_asset`
- `MaterialRetrievalTarget`
  - `copy_context`
  - `script_context`
  - `article_image_asset`
  - `video_edit_asset`

新增 `app/src/lib/material-routing.ts`，集中判断素材用途和允许进入的检索目标。

当前规则：

- 爆款图文 / 爆款视频统一作为 `viral_reference`，只能用于 `copy_context` 和 `script_context`。
- 项目图片作为 `image_asset`，只进入 `article_image_asset`。
- 项目视频作为 `video_asset`，只有 `ready` 后才进入 `video_edit_asset`。
- `parsing` / `failed` / `archived` 的视频素材不会进入 worker 可用池。

### 2. 素材入库路由元数据

修改：

- `app/src/lib/db/material-library-repository.ts`
- `app/src/server/api/material-library-service.ts`
- `app/src/contracts/material.ts`
- `app/src/server/api/schemas.ts`
- `app/src/app/api/materials/route.ts`

当前行为：

- 外部链接上传和 TikHub 对标结果标记为 `viral_reference`。
- 项目图片上传标记为 `image_asset`，状态为 `ready`。
- 项目视频上传标记为 `video_asset`，状态先为 `parsing`，为后续多模态理解 / 切片预留。
- `/api/materials` 支持按 `retrievalTarget` 查询，供后续页面和服务端检索复用。

### 3. 图文生成检索分层

修改：

- `app/src/server/api/content-generation-service.ts`
- `app/src/server/api/article-prompt-templates.ts`
- `app/src/server/api/daily-content-task-service.ts`
- `app/src/components/merchant/article-workbench.tsx` 未直接改逻辑，但继续读取 `matchedProjectMaterials`。

当前行为：

- 图文生成会收集：
  - `copy_context`：文本知识库命中 + 爆款内容参考。
  - `article_image_asset`：项目图片素材。
- `input_snapshot.materialRetrieval` 保留本次检索留痕。
- `matchedProjectMaterials` 改为只写入图片素材引用。
- 没有图片素材时，生成图片 brief/prompt，不阻塞文案生成。
- 图文 prompt 明确：`copyContextRefs` 是文本依据，`imageAssetRefs` 只用于配图建议，不能把视频素材当图文配图。

### 4. 视频脚本检索分层

修改：

- `app/src/server/api/content-generation-service.ts`
- `app/src/server/api/video-workbench-agent-runtime.ts`
- `app/src/server/api/video-growth-context.ts`

当前行为：

- 视频脚本生成会收集 `script_context`，包含文本知识库和爆款内容参考。
- 视频脚本上下文会写入 `materialRetrieval`，包含降级提示。
- 只有允许 `script_context` 的素材才作为脚本可用素材摘要。
- 视频工作台 prompt 明确：爆款内容只作为 hook / 节奏 / 结构参考，不能作为 worker 输入素材；项目图片不能当作可剪辑视频片段。

### 5. AI 剪辑 worker 输入只保留视频素材

修改：

- `app/src/server/api/video-job-payload.ts`
- `app/src/server/api/video-edit-jobs-service.ts`
- `app/src/server/api/video-job-payload.test.ts`

当前行为：

- `video_edit_jobs.input_payload.input_assets` 只保留 `assetType === "video"` 的 COS 素材。
- 图片素材会记录到 `materialContext.excludedAssetIds`，不进入 worker input。
- `materialContext.retrievalTarget = "video_edit_asset"`。
- 没有视频素材时，`materialContext.missingVideoAssetHints` 从脚本画面需求中提取缺失提示。
- 只有真正允许 `video_edit_asset` 的素材中心引用才进入 worker material references，爆款内容不会因为被送入视频工作台而触发“缺少可下载视频素材”的错误。

### 6. 入库页显示

修改：

- `app/src/components/merchant/merchant-knowledge-library.tsx`

当前行为：

- 项目媒体素材列表按 `usageType` 识别图片 / 视频素材。
- 视频素材处于 `parsing` 时显示“识别中”。
- 图片素材显示“可用于图文配图”；ready 视频素材后续可显示“可用于AI剪辑”。

```bash
cd app
node --test src/lib/material-routing.test.ts src/server/api/video-job-payload.test.ts src/server/api/article-prompt-templates.test.ts src/server/api/video-workbench-agent-runtime.test.ts
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm build
cd ..
python3 -m compileall workers/video-worker/openstoryline/app workers/video-worker/worker/app
python3 .codex/skills/long-task-gate/scripts/check.py
```

测试结论：

- 爆款视频不会进入 `video_edit_asset`。
- 项目图片只进入 `article_image_asset`。
- 项目视频在 `parsing` 状态不会进入 `video_edit_asset`，`ready` 后才进入。
- worker payload 只保留视频资产，并排除图片资产。
- 长任务 Completion Gate 已通过，独立 verifier 返回 `status: complete`。
