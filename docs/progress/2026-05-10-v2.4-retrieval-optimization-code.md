# 2026-05-10 V2.4 检索优化代码落地记录

## 背景

本轮接续 `docs/产品文档/V2.4-内容检索与媒体素材分层路由PRD.md` 中 `3.4 检索优化原则`、`3.5 典型场景的检索拆分`、`3.6 后续索引建设建议`，目标是把“按生成场景拆小检索”的产品原则落到代码。

上一轮已经完成 `retrievalTarget` 分层路由，本轮重点补齐：

- 素材列表支持 query 召回和重排。
- 图文生成的“文案依据”和“配图素材”分开检索。
- 视频脚本生成按脚本上下文检索文本知识和爆款参考。
- 视频剪辑 payload 带上分镜画面需求和素材匹配计划。
- 检索结果在 `analysisPayload.materialRetrieval` 中保留 score、queryTerms 和 matchReasons。

## 已完成

### 1. 新增素材检索排序模块

新增：

- `app/src/lib/material-retrieval.ts`
- `app/src/lib/material-retrieval.test.ts`

核心能力：

- `rankMaterialLibraryItemsForRetrieval`
  - 先按 `retrievalTarget` 过滤。
  - 再从素材标题、描述、创作者、互动标签、`analysisPayload` 中生成轻量搜索文本。
  - 再按 query 命中、素材用途、来源优先级、近期入库进行重排。
  - 最后把 `score`、`queryTerms`、`matchReasons` 写回 `analysisPayload.materialRetrieval`。
- `tokenizeMaterialRetrievalQuery`
  - 支持中文连续文本的二到四字滑窗召回。
  - 例如 `刚需买房避坑` 会扩展出 `刚需`、`买房`、`避坑` 等关键词。

### 2. 素材列表 API 接入 query

修改：

- `app/src/lib/db/material-library-repository.ts`
- `app/src/server/api/material-library-service.ts`
- `app/src/server/api/schemas.ts`
- `app/src/app/api/materials/route.ts`

当前行为：

- `/api/materials?retrievalTarget=...&query=...` 可按场景检索素材。
- Demo 内存素材和 Supabase 素材都会走同一套排序逻辑。
- Supabase 当前仍复用 `source_items`，先扩大候选数量到最多 160，再在服务端做轻量召回与重排。
- 本轮未新增 embedding 表或数据库 migration。

### 3. 图文生成拆成两个小检索

修改：

- `app/src/server/api/content-generation-service.ts`

当前行为：

- `copyQuery` 用于文案依据：
  - 当前日历任务
  - 内容目标
  - 用户补充要求
  - 项目卖点
  - 目标客群
  - 策略标签
- `imageQuery` 用于配图素材：
  - 当前主题
  - 项目关键场景
  - 项目卖点
  - 策略标签
- `retrievalContext.retrievalQueries` 会写入本次图文生成输入快照。
- `copyContextRefs` 保留知识库和爆款内容的 score / matchReasons。
- `imageAssetRefs` 保留图片素材的 retrievalTrace。

### 4. 视频脚本检索接入 query

修改：

- `app/src/server/api/content-generation-service.ts`

当前行为：

- `script_context` 检索会使用脚本任务、目标客群、项目卖点、CTA、可用场景生成 query。
- 视频脚本阶段仍只拿文本知识库和爆款参考作为依据，不把视频素材提前绑定为 worker input。

### 5. 今日任务素材提示按主题检索

修改：

- `app/src/server/api/daily-content-task-service.ts`

当前行为：

- 今日任务先确定日历主题，再基于主题、图文/视频日历卡、项目卖点、目标客群、关键场景生成检索 query。
- `materialHints`、`knowledgeRefs`、`materialRefs` 不再只是按最近素材取数，而是按当天任务主题重排。

### 6. 视频剪辑 payload 增加分镜素材匹配计划

修改：

- `app/src/server/api/video-job-payload.ts`
- `app/src/server/api/video-job-payload.test.ts`

当前行为：

- `materialContext.sceneAssetQueries`
  - 优先从 `productionScenes` 中读取 `shotRequirement`、`visual`、`materials`。
  - 没有结构化分镜时，从脚本文本中的 `画面`、`镜头要求`、`所需画面`、`素材` 行提取。
- `materialContext.assetMatchPlan`
  - 如果没有视频资产，标记 `missing: true` 和 `reason: no_video_asset`。
  - 如果文件名 / storage key 命中 query 关键词，标记 `filename_keyword_match`。
  - 如果有视频资产但缺少分镜级索引，诚实标记 `draft_video_assets_available_no_scene_index`，交给 worker 做后续选择。
- `missingVideoAssetHints` 会优先使用分镜画面需求，给用户可操作的补素材提示。

```bash

node --test src/lib/material-retrieval.test.ts src/lib/material-routing.test.ts src/server/api/video-job-payload.test.ts src/server/api/article-prompt-templates.test.ts src/server/api/video-workbench-agent-runtime.test.ts

python3 -m compileall workers/video-worker/openstoryline/app workers/video-worker/worker/app
```

验证结论：

- 素材检索会先按 `retrievalTarget` 过滤，避免混池。
- 中文 query 能扩展关键词，相关素材可以压过单纯近期素材。
- 图文、脚本、今日任务均已把 query 传入素材检索。
- worker payload 仍只发送视频资产，同时新增分镜素材 query 和匹配计划。
- Next build、TypeScript、ESLint 和 worker Python compile 均通过。
