## 故障点

### P0-01 生成团队内容链路卡在 pending，没有常驻消费器

现象：

- 页面点击“生成团队本周内容”后显示：
  - `批次 pending`
  - `任务 7`
  - `排队 7`
  - `运行 0`
  - `成功 0`
  - `失败 0`
- 服务器只有以下 service：
  - `jingjing-domestic-app.service`
  - `jingjing-firered-openstoryline.service`
  - `jingjing-openstoryline-engine.service`
  - `jingjing-video-worker.service`
- 未发现常驻 `content-generation-worker` 服务。

数据库证据：

```text
batch_id=48bb2d49-0d0d-4fe5-8c46-acd6280720a2
status=pending
jobs=pending/queued x 7
```

影响：

- PRD 阶段四“用户点击生成团队内容 -> Dify 生成图文与视频脚本 -> 成员端任务执行”无法自然闭环。

### P0-02 点击生成团队内容时没有使用当前咨询台日历隐藏上下文

现象：

- 本次咨询会话里的 7 条 calendar item 已包含 `guidance.knowledgeRefs`、`retrievalTrace` 等隐藏上下文。
- 但点击“生成团队本周内容”创建的 batch 只记录：

```json
{"date":"2026-05-20","days":7,"source":"daily_content_tasks"}
```

- 生成的 jobs：
  - `calendar_item_id = null`
  - `input_snapshot.calendar_task_json = null`
  - `input_snapshot.fallback_knowledge_text` 为空
- 新落到 `daily_content_tasks` 的任务仍是旧的 `merchant_strategy_asset` 来源：
  - `team_calendar_source.calendarGuidance = null`
  - `knowledgeRefs = 0`
  - `retrievalTrace = 0`
  - `theme = 今日项目内容`

影响：

- 违反 PRD US-03 / US-04：
  - “日历 item 成为上下文资产”
  - “生成团队内容时完整日历上下文进入现有 Dify 输入”
- 即使 worker 开始消费，Dify 也拿不到本次咨询刚生成的日历隐藏上下文。

### P1-01 Agentic RAG 没有按 PRD 进行多轮 query 深挖

现象：

- 用户明确要求分别检索：
  - 项目优势
  - 如何选好一套房
  - 客户异议/转化话术
- 实际 tool card 只有 2 项：
  - `retrieve_knowledge_base`：命中 3 个受控片段
  - `update_content_calendar`：写入 7 条日历
- `retrievalTrace` 只有 3 个 chunk，且同一组 trace 被复制到所有 7 条日历 item。

影响：

- 不符合 US-01 的“读类工具可多轮调用”验收目标。
- 不符合 US-02 的“围绕项目事实、方法论、话术、素材边界组织检索策略”目标。

### P1-02 生成内容仍存在素材和事实支撑不足

生成内容中出现了以下表达：

- `客户签约画面`
- `客户购房案例`
- `AI生成周边项目对比数据（单价/配套/政策）`
- `最新政策文件`
- `客户访谈素材`
- `老业主亲测`
- `100万如何在光明区选到高回报项目`
- `开发商不说的真相`
- `错过即损失`

当前隐藏上下文里：

- `shotConstraints = []`
- `materialHints = ["测试区域"]`
- `assetCapabilityHints` 主要来自旧策略资产：`图文内容`、`AI视频`、`测试区域` 等，不是真实素材能力摘要。

影响：

- 视频方向仍可能写出素材库无法支撑的画面。
- 事实表达存在过度扩写风险，尤其是价格、回报率、政策、真实客户案例、老业主反馈。

### P1-03 日历 hidden guidance 质量偏弱且污染了无关测试信息

现象：

`mustUseFacts` 和 `sellingPointHints` 中混入：

- `用于验证成员端登录、邀请码注册和团队加入链路。`
- `测试区域`
- `图文内容`
- `AI视频`

这些来自早期测试策略资产，不是本次“房地产选题/买房干货/素材边界”的有效事实。

影响：

- 后续 Dify 即使接收到 guidance，也会被低质量上下文干扰。
- 日历 item 虽有隐藏字段，但“上下文资产”的质量还不稳定。

### P2-01 内容日历 UI 仍有旧链路文案

现象：

- “查看全部内容”面板中的卡片按钮显示：
  - `内测视频工作台`
  - `内测图文工作台`
- 右侧卡片显示：
  - `内测入口`

影响：

- 和当前产品链路不一致。用户已确认：生成营销日历后，不再通过用户端图文/视频工作台，而是在内容日历直接“生成团队内容”，再到成员端。

### P2-02 日历卡片标题重复

现象：

卡片中重复显示同一个标题，例如：

```text
周一 · 东洲项目实拍大揭秘：为何光明区客户更愿意选择我们？
东洲项目实拍大揭秘：为何光明区客户更愿意选择我们？
```

影响：

- UI 可读性下降。
- 与 PRD “轻量日历卡片，只显示用户决策和执行需要的信息”不完全一致。

### P2-03 成员端页面可见区域为空，但 API 有数据

现象：

- 打开 `/member/calendar`，页面可见文案只有：

```text
AI
静境成员端
MOBILE EXECUTION
项目
日历
内容
团队
```

- 但同一登录态下：
  - `/api/member/tasks/week` 返回 200
  - `/api/member/tasks/today` 返回 200
  - 返回内容仍是旧的“今日项目内容”任务，不是本次 7 条新选题。

影响：

- 成员端执行页面疑似客户端渲染失败或没有正确展示任务数据。
- 即使 API 有数据，也没有呈现给执行成员。

## 其他观察

1. 由于浏览器自动化无法稳定触发 React 受控 textarea 的 submit 状态，本次消息发送通过同一已登录页面上下文调用 `/api/consultation/sessions/{id}/messages` 完成；后续页面刷新后，UI 能展示该会话和日历结果。
2. 本轮没有清理测试会话、批次或 pending jobs，便于继续复现。
3. 本轮只记录故障，没有改代码。

## 建议修复顺序

1. 先修 P0-02：让“生成团队本周内容”从当前咨询会话的 `contentCalendarDraft` 或已沉淀的 strategy asset 中读取完整 calendar item，而不是回退到旧 `daily_content_tasks`。
2. 再修 P0-01：部署并守护 `content-generation-worker`，或在当前阶段明确“生成团队内容”按钮同步触发 run-next。
3. 修 P1-01：把“多 query 检索策略”从 prompt 愿望升级成 agent loop 可执行策略，至少对用户明确列出的检索维度逐项检索。
4. 修 P1-02 / P1-03：素材能力摘要必须来自真实素材或明确可补拍信息，不能从旧策略资产的泛字段硬凑。
5. 修 P2 UI：移除旧工作台入口文案、去掉重复标题、排查成员端页面空白。
