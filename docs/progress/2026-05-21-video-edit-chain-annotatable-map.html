先看 State：这条链路里到底在传什么

白话理解：State 就是一张不断被补全的“剪辑任务单”。刚开始只有脚本，后面会陆续补上镜头需求、成员素材、商家素材库素材、声音方案、剪辑参数、成片结果和失败原因。

脚本状态 已确认的脚本文本、口播段落、分镜提示、是否锁定。
素材需求 每一镜需要什么画面，例如真人口播、门头、环境、产品特写。
素材结果 成员上传了什么，商家素材库命中了什么，哪些镜头还缺素材。
声音字幕 系统配音、个人克隆音色、字幕来源、是否需要口型同步。
剪辑任务 video_edit_jobs.input_payload、worker 本地文件、FireRed 时间线。
结果状态 成片、封面、字幕、预览链接、失败阶段和重试建议。
例子：脚本里写“开头真人口播介绍小院，后面展示庭院环境和座位”。State 会先记下这句话，再拆出“真人口播视频”“庭院环境素材”“座位特写素材”“配音和字幕策略”，最后变成 worker 能执行的剪辑任务。

失败边：不是所有失败都一样

LangGraph 里失败也应该是一条明确的边，而不是一句“生成失败”。当前链路已经记录 failure_stage，可以把失败拆成素材失败、声音失败、口型同步失败、渲染失败、上传失败。

  • 素材缺失：通常是 failed_manual，需要成员或商家补素材。
  • 对象存储上传或下载失败：通常可归为 failed_retryable，适合后台重试。
  • lip-sync 输入不合规：应提示“口播视频不适合对口型”，不能假装成功。
  • render 没有消费 retalked timeline：必须失败，这是 lip-sync 验收关键点。

建议新增的产品节点：素材确认

现有后端已经能从脚本和素材库拼 payload，但产品体验上可能还需要一个“确认将使用这些素材”的节点。它可以放在 N3 素材汇合之后、N4 声音策略之前。

  • 用户看到每个镜头将使用哪个素材。
  • 用户可替换素材、标记必用素材、删除不合适素材。
  • 确认后再进入声音和剪辑任务创建，减少出片后返工。

例子 A：普通商家素材库出片

适合首版稳定链路：没有个人克隆音色，不做 lip-sync，主要靠商家素材库补画面。

  1. START：脚本定稿，“介绍一个适合周末放空的咖啡小院”。
  2. N1：拆出“门头、庭院、座位、饮品、结尾 CTA”。
  3. N2：判断这些都可以走商家素材库，不要求真人口播。
  4. N3B：从素材库命中 6 条视频，筛出 4 条可剪辑片段。
  5. N4：没有个人音色，使用系统配音和脚本字幕。
  6. N5 到 N7：创建 job，worker 下载素材，FireRed 生成配音、规划时间线并渲染。
  7. END：上传 final.mp4，前端展示预览和下载。
已有真实成功类型

例子 B：真人口播 + 克隆音色 + lip-sync

适合更像真人 IP 的链路：需要成员上传正脸视频，还要有 ready 的个人音色，最后尝试对口型。

  1. START：脚本定稿，“大家好，今天带你看一个适合周末放空的院子”。
  2. N1：第 1 镜标记为真人口播，后续镜头为庭院 B-roll。
  3. N2：真人口播走成员素材，庭院 B-roll 走商家素材库。
  4. N3A：成员上传一段正脸口播视频；N3B：素材库补庭院镜头。
  5. N4：读取 ready voice_profile，生成克隆音频，并启用 lip-sync。
  6. N7：VideoRetalk 对口播段做口型同步，再和 B-roll 一起进最终时间线。
  7. END：只有当最终 render 确认消费了 retalked 片段，才算真正成功。
已发布能力，但真实全链路仍需验收

七、素材选择细则：worker 到底先用谁、后找谁

这里把素材来源拆清楚，避免“成员上传了素材但系统又用了素材库素材”这种体验争议没有规则。

素材来源分层

  • 成员任务素材：成员为当前 daily task / draft 上传，ownerType 多为 content_draft。
  • 个人声音素材：成员参考音频，ownerType 为 voice_profile，不作为普通视频素材。
  • 商家项目素材库：source_items + asset_objects 中标记 materialLibrary / video_edit_asset 的素材。
  • worker 本地临时素材：下载到工作目录，仅供本次剪辑，不是长期真相源。
  • FireRed 运行时素材：镜头切分、BGM、TTS、render 中间产物，最终必须回写对象存储。

当前素材优先级建议

  1. 用户明确选择 / 锁定的素材最高优先级。
  2. 分镜要求 requiresUserUpload 或 talking_head 时，优先成员上传口播素材。
  3. 普通项目镜头优先从商家素材库按脚本 query 检索。
  4. 没有匹配素材时，记录缺素材提示，不应静默编造业务事实。
  5. 成员临时上传素材默认不进入团队素材库，除非产品明确设计授权入库。

典型场景怎么选素材

场景 当前系统会怎么做 产品风险 建议批注
开头真人口播 识别 talking_head / requiresUserUpload，使用成员上传口播素材，必要时启用 voice_profile 和 lip_sync。 成员上传侧脸、多人、画质差时 lip-sync 容易失败。 是否需要上传前质量检测和示例引导。
楼盘 / 门店 B-roll worker 根据脚本文本和 sceneAssetQueries 从商家素材库补项目素材。 自动匹配可能语义接近但不是用户想要的镜头。 是否要 AI 剪辑前确认候选素材。
成员上传了多个视频 payload 里保留 inputAssetIds，worker 作为用户输入下载。 用户不知道哪个视频会出现在第几个镜头。 是否要支持拖拽排序、镜头绑定、锁定素材。
素材库没有命中 materialContext 记录 missingVideoAssetHints；脚本或任务仍可能走 fallback。 成片可能偏“泛素材”或节奏不自然。 是否阻断剪辑，还是允许先出草稿版。
成员临时素材很优质 当前不自动转入团队素材库。 后续不能复用，商家素材库成长慢。 是否增加“授权入库/运营审核入库”。

九、真人口播、克隆声音、口型替换和字幕细节

这块是当前最新但还没真实全链路验收的能力，专门拆给你判断是否继续投入、怎么验收。

三种字幕来源怎么理解

字幕来源 适合场景 风险 当前口径
script 普通视频，系统按锁定脚本生成字幕。 如果真人原声与脚本不同，会音画不一致。 非口播默认路径。
script_audio_alignment 新真人口播主路径：克隆音频读锁定脚本，再按音频/脚本对齐字幕。 需要 clone TTS 和 lip-sync 都真实可用。 lip-sync 分支目标默认。
asr_original_audio 显式回退：识别原视频人声做字幕/时间线辅助。 脚本已锁定时，ASR 原声可能和脚本不一致。 保留为回退，不应作为 lip-sync 主路径。

VideoRetalk 输入要求

  • 音频支持 wav/mp3/aac，文件小于 30MB，时长 2s - 120s。
  • 视频支持 mp4/avi/mov，文件小于 300MB，时长 2s - 120s。
  • 视频帧率 15-60fps，编码 H.264/H.265，宽高各边 640-2048 像素。
  • 画面需要清晰、近景、正脸、单人，避免遮挡、多人脸、强运动模糊。
  • 供应商需要可访问的 video_url / audio_url，本地路径不合法。

真实验收清单

  • 成员成功上传真实 MP3/M4A，生成 ready voice_profile。
  • 创建 job 时 payload 包含 voice_profile、ref audio asset、talking_head asset。
  • FireRed 产出 clone voiceover artifact，且音频格式/大小/时长合格。
  • lip_sync 只处理 talking_head_segments，不处理 B-roll。
  • render_video 真实消费 retalked timeline，不允许假成功。
  • final.mp4 上传对象存储，app preview/download 都 200。
  • 失败日志能定位到 clone_tts 或 lip_sync，不是混成 render。

失败回退策略待定

当前架构倾向 fail closed：lip-sync 失败就明确失败，不跳过后伪造成片成功。但产品上可以决定是否允许“降级出普通 TTS 成片”。这个决定会影响用户体验和技术日志。

  • 严格模式：lip-sync 失败则任务失败，要求用户换视频或重录。
  • 降级模式：lip-sync 失败后出普通 TTS/B-roll 版，标记为降级成片。
  • 人工模式：失败进入运营后台，由运营决定重试、降级或退回成员。

十、需要你精准指导的拍板点

这些是我从链路里提出来的高杠杆批注位。你可以直接在这里写结论，也可以回到上面的具体节点写更细。

1. 前端到底叫“COS素材库”还是“项目素材库”

D1

技术底层已从 COS 过渡到 OSS 默认，继续在前端叫 COS 会让非技术用户误解。建议产品层叫项目素材库，技术层注明对象存储。

2. 成员临时素材是否进入团队素材库

D2

当前规则是：成员任务上传素材只作为草稿输入，不自动进团队素材库，不长期切片打标。这样更安全，但复用效率较低。

3. 真人口播口型替换的验收标准

D3

lip-sync 已发布但未真实跑通。要继续推进，需要先定“什么算通过”：口型自然度、字幕准确度、是否保留原人声、失败时是否回退。

4. AI 剪辑前是否需要素材确认页

D4

当前 worker 会自动补商家素材库素材。如果你希望更可控，可以在点击 AI 剪辑前让用户确认“将使用这些素材”。

5. 失败后让用户怎么处理

D5

worker 已能区分合同错误和可重试错误。产品上还要决定：显示技术原因、给替换素材入口、自动重试、还是交给运营处理。

6. 成片发布前的审核责任

D6

当前链路到预览/下载为主。真实发小红书/抖音前必须确认商家、门店、平台、账号、测试/正式环境，避免“内容对了，账号错了”。
