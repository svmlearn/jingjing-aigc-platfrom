视频剪辑链路节点图：输入、处理过程、输出、判断条件

这一页专门看“脚本 -> 素材 -> 剪辑”的节点链路。主页面负责总览服务器、素材库、成员端和接口；本页负责把每个链路节点拆成可批注的四块：输入、处理过程、输出、判断条件。

批注会和主页面使用同一份本地保存空间，方便来回跳转后继续写。

总览 START N1 脚本拆镜 N2 素材判断 N3A 成员素材 N3B 素材库 N3C 素材确认 N4 声音字幕 N5 创建任务 N6 worker N7 剪辑引擎 引擎字段字典 F0-F10 引擎步骤 音乐链路 END 成片 失败边 例子

一、节点总览

点击任一节点可跳到详细说明。黄色代表判断节点，绿色代表素材节点，紫色代表剪辑引擎，红色代表失败分流。

START脚本已确认，任务可以开始。 N1把脚本拆成镜头需求。 N2判断素材从哪里来。 N3A成员上传素材。 N3BCOS/OSS 商家素材库。 N3C确认每个镜头用什么素材。 N4声音、字幕、lip-sync。 N5创建 video_edit_jobs。 N6worker 领取并下载素材。 N7OpenStoryline / FireRed 剪辑。 F0-F10剪辑引擎内部每一步。 END上传成片并回写前端。 FAIL失败归因和重试/人工处理。

二、节点详解

每个节点都固定拆成输入、处理过程、输出、判断条件，方便直接批注。

START：脚本已经确认，可以开始剪辑

S

通俗解释：这一步像剪辑师收到定稿文案。脚本没定，后面的素材、配音和剪辑都会反复变化，所以要先确认脚本版本。

输入

content_variants 里的脚本文本、关联的 draftId、dailyTaskId、商家和成员身份。

处理过程

检查脚本是否为空，确认是否已审核/锁定，把脚本版本固定下来，避免 worker 自己改文案。

输出

lockedScript、variantId、draftId，作为后续 Graph State 的起点。

判断条件

脚本为空或未确认：回到脚本制作；脚本已确认：进入 N1 拆镜。

例子：脚本为“开头真人口播：今天带你看一个周末放空的小院。”这个版本被锁定后，后续剪辑都围绕它找素材和配音。

N1：ScriptToScenes，把脚本拆成镜头需求

N1

通俗解释：脚本是给人看的，剪辑系统需要的是“第几秒用什么画面”。这个节点把文案翻译成一组镜头需求。

输入

锁定脚本、productionScenes、内容类型、目标平台、商家/门店上下文。

处理过程

按句子和意图拆镜，标记每个镜头需要真人、环境、门头、产品、字幕还是 CTA。

输出

sceneRequirements、sceneAssetQueries、缺素材提示 missingAssetHints。

判断条件

出现“我带你看/大家好/真人口播”倾向成员素材；出现“庭院/门头/户型/产品”倾向商家素材库。

例子：“开头真人说一句，后面展示庭院和咖啡座位”会被拆成：1. 真人口播；2. 庭院环境；3. 座位细节；4. 结尾 CTA。

N2：MaterialRoute，判断每个镜头的素材从哪里来

N2

通俗解释：这一步像给每个镜头贴标签。哪些必须成员上传，哪些从商家素材库找，哪些缺素材要拦住，都在这里决定。

输入

N1 产出的镜头需求，例如 user_talking_head、merchant_broll、product_closeup。

处理过程

按镜头角色分流：真人/口播走成员素材，门店/环境/项目展示走素材库，缺关键画面则记录阻断原因。

输出

memberAssetNeeds、libraryAssetNeeds、blockingMissingAssets。

判断条件

必须真人但无成员视频：进入 N3A 等待补素材；素材库镜头：进入 N3B 检索；可替代镜头：允许降级或继续。

例子：“真人开场”走成员上传；“庭院空镜”和“座位特写”走 COS/OSS 商家素材库。

N3A：CollectMemberAssets，收集成员上传素材

N3A

通俗解释：如果镜头需要成员本人出现，比如真人口播，这个节点就去草稿下面找成员上传的视频、图片或音频。

输入

inputAssetIds、asset_objects ownerType=content_draft、上传文件的 role/tags/metadata。

处理过程

检查文件类型、大小、时长和可读性，识别哪些是开头口播、结尾口播、普通 B-roll 或补充证明材料。

输出

userInputAssets、talkingHeadAssets、成员素材缺失列表。

判断条件

必需成员素材缺失：提示补素材；素材可读且符合角色：进入素材确认；素材不可读：失败或要求重传。

例子：成员上传一段 20 秒正脸视频，系统标记为“开头真人口播”，后续 lip-sync 才可能使用它。

N3B：RetrieveMerchantLibraryAssets，检索 COS/OSS 商家素材库

N3B

通俗解释：这里就是“COS 素材库”的核心路径。产品上可继续叫 COS 素材库；当前国内生产默认对象存储是阿里云 OSS，同时兼容历史 Tencent COS 口径。

输入

merchantId、场景 query、素材库记录 source_items + asset_objects、素材标签和对象存储 key。

处理过程

按门店、场景、标签、横竖屏、质量和可用性检索，给每个镜头挑一个或多个候选素材。

输出

merchantMaterialAssets、素材来源说明、候选素材排序、缺素材提示。

判断条件

命中高质量素材：进入确认；无命中：提示商家补素材、允许低保真预览或阻断，取决于产品规则。

例子：query “庭院 安静 座位”命中 4 条商家实拍视频，系统优先选竖屏、清晰、近期上传的片段。

N3C：MaterialConfirm，确认每个镜头到底用哪段素材

N3C

通俗解释：这是建议新增的产品节点。后端可以自动匹配素材，但用户最好能在出片前看到“每个镜头将用什么”，减少成片后返工。

输入

N3A 的成员素材、N3B 的商家素材库候选、N1 的镜头需求。

处理过程

把“镜头需求”和“候选素材”一一绑定，允许用户替换、锁定必用素材、删除不合适素材。

输出

confirmedSceneAssets、mustUseAssets、forbiddenAssets、素材确认记录。

判断条件

用户确认：进入声音策略；用户替换：回到素材检索；关键镜头无素材：阻断并提示补素材。

例子：第 2 镜“庭院环境”自动匹配了 A 视频，但运营认为 B 视频更好，可以在这里替换并锁定 B 视频。

N4：VoiceAndSubtitleRoute，决定声音、字幕和 lip-sync

N4

通俗解释：画面素材准备好以后，还要决定“谁来念脚本”。没有个人音色就用系统配音；有个人音色可以用克隆音色；有合格真人口播视频才可能做口型同步。

输入

确认后的素材、脚本文本、voice_profiles、参考音频、口播视频、平台字幕要求。

处理过程

选择系统配音或个人克隆音色，确定字幕来源，判断真人视频是否满足 lip-sync 条件。

输出

productionConfig.voiceover、subtitlePolicy、lipSyncConfig。

判断条件

无 ready 音色：系统配音；有音色但无合格口播：克隆配音不对口型；音色和口播都合格：可启用 lip-sync。

例子：成员有 ready 音色且上传了清晰正脸视频，则设置 voiceover.mode=voice_profile、lipSync.enabled=true。

N5：AssembleVideoEditJob，创建剪辑任务

N5

通俗解释：这一步像把剪辑任务单正式交给后台排队。脚本、素材、声音、字幕和输出要求都会写进 input_payload。

输入

锁定脚本、确认素材、声音策略、字幕策略、lip-sync 配置、输出比例和平台目标。

处理过程

组装 video_edit_jobs.input_payload，写入数据库，建立 app 和 worker 之间的稳定合同。

输出

jobId、input_payload、初始状态 pending/queued。

判断条件

合同字段完整：进入 worker 队列；缺关键字段：failed_manual 或阻止创建。

例子：一个 job 会带上 script、productionDirective、materialContext、input_assets、productionConfig。

N6：WorkerClaimAndPrepare，worker 领取任务并准备素材

N6

通俗解释：app 创建任务后，真正跑剪辑的是服务器上的 video-worker。它会抢任务、下载素材、检查本地文件，再交给剪辑引擎。

输入

video_edit_jobs 队列、input_payload、对象存储 key、数据库素材记录。

处理过程

用队列锁领取任务，更新 heartbeat，下载成员素材和素材库素材到本地临时目录，校验文件。

输出

runtime_payload、本地素材路径、状态 preparing/running、worker 日志。

判断条件

下载失败：多为 failed_retryable；文件不可读或合同错误：多为 failed_manual。

例子：素材库里是 oss://bucket/materials/courtyard.mp4，worker 下载为 /tmp/video-worker/.../courtyard.mp4。

N7：OpenStoryline / FireRed，真正剪辑和渲染

N7

通俗解释：这里才是真正剪视频的节点。worker 把任务交给 OpenStoryline，OpenStoryline 再把它转成 FireRed 能执行的生产指令。

输入

本地素材路径、脚本、声音配置、字幕配置、lip-sync 配置、目标视频规格。

处理过程

这里先作为总入口，内部继续拆成 F0-F10：适配合同、加载素材、切片、理解素材、配音、字幕、时间线、lip-sync、渲染和校验。

输出

交给后续 END 节点的 final.mp4、封面、字幕文件、时间线 metadata、引擎日志。

判断条件

任一内部 F 节点失败，都要带着明确阶段返回；lip-sync 启用时，最终 render 必须消费 retalked 片段。

F0适配 worker 合同 F1加载素材 F2切镜头/切片 F3理解素材内容 F4补检索/候选素材 F5生成配音 F6字幕/对齐 F7规划时间线 F8可选口型同步 M0-M5音乐/BGM 链路 F9渲染视频 F10校验产物
例子：系统配音版会走 F0-F7-F9-F10；真人口播 lip-sync 版会在 F8 把 talking-head 段替换成对口型后的视频，再进入 F9 渲染。

剪辑引擎字段字典：这些字段到底是什么要求

字段

通俗解释：下面这张表是 N7/F0-F10 会反复用到的核心字段。产品批注时可以直接指出“这个字段要不要前端可见”“这个字段是否必填”“这个字段失败时怎么提示”。

字段 类型 / 是否必填 来源 用途 通俗解释和要求
job_id 字符串，必填 video_edit_jobs.id 串起 worker、OpenStoryline、FireRed、日志和输出目录。 每次剪辑任务的身份证。没有它，后面无法知道哪个成片属于哪个任务。
merchant_id 字符串，必填 商家上下文 隔离商家素材、输出路径、权限和日志。 防止素材和成片串到别的商家。真实发布链路里这是安全边界。
draft_id / content_variant_id 字符串，必填 草稿和脚本版本 把成片回写到正确草稿、正确脚本版本。 同一个草稿可能有多个版本，成片必须能追溯到哪一版脚本。
workspace_dir 本地路径，必填 worker 创建 FireRed 临时工作目录。 引擎运行时的工作台，放中间文件、临时结果和运行记录。
output_dir 本地路径，必填 worker 创建 约定输出 final.mp4、cover.jpg、subtitles.srt、metadata。 END 节点会从这里拿文件上传对象存储。这个目录不对，后面就找不到成片。
input_assets[].local_path 本地路径，必填 N6 下载素材后写入 F1 加载素材的真实文件路径。 这是云端素材下载到服务器后的路径，不是 OSS/COS key。必须文件存在且可读。
input_assets[].asset_type 字符串，必填 素材记录 区分 video、image、audio 等素材类型。 剪辑用视频/图片，克隆音色用音频。类型错了，后面会走错节点。
input_assets[].role 字符串，建议必填 成员上传或素材匹配 区分 talking_head、B-roll、项目素材等。 lip-sync 判断最依赖这个字段。真人口播没有标出来，就可能不会进入 F8。
input_assets[].tags / labels / metadata 数组/对象，可选但很重要 素材库标签、上传元数据、匹配结果 帮助 F3/F4 理解素材和匹配镜头。 这些是“素材说明书”。越清楚，越不容易乱选素材。
script_text 字符串，必填 锁定脚本 给配音、字幕、时间线规划使用。 这是成片要表达的核心内容。为空就不该继续剪。
production_directive.desired_outputs 字符串数组，默认 ["final_video"] app payload 告诉引擎需要 final、cover、subtitles 哪些产物。 如果产品要求封面和字幕也必须有，这里要写清楚，F10 才能校验。
production_config.voiceover.mode system 或 voice_profile，必填 N4 声音策略 决定 F5 走系统配音还是个人克隆音色。 系统配音更稳；个人音色更像真人，但必须有音色和参考音频。
production_config.voiceover.provider 枚举，系统配音必填 N4 声音策略 系统配音 provider，例如 bytedance_bigtts、minimax、302。 选择谁来念。provider 不支持会在创建任务或 F5 失败。
production_config.bgm.enabled 布尔值，必填，默认 true N4 / 创建任务配置 决定是否进入音乐/BGM 链路。 关掉时不应该要求 music_rec 作为时间线依赖，避免无音乐任务卡住。
production_config.bgm.userRequest 字符串，可为空 脚本策略、产品配置或用户选择 告诉 select_bgm 想要什么音乐风格。 例如“轻盈、温暖、有一点节奏感”。为空时由素材和默认策略选择。
production_config.bgm.include/exclude 对象，可选 产品配置或用户筛选 筛选或排除音乐标签。 只允许 mood、scene、genre、lang、id 这些 key。
production_config.bgm.volume 数字，0 到 3，默认 0.25 产品配置 控制 BGM 混音音量。 这是背景音乐的音量倍数。口播视频一般要低一点，避免盖住人声。
voiceProfileId / refAudioAssetId 字符串，voice_profile 模式必填 voice_profiles 和声音资产 F5 克隆配音找到成员音色和参考音频。 个人音色模式没有这两个字段，就不能生成克隆配音。
production_config.subtitles.talkingHeadSource script / script_audio_alignment / asr_original_audio N4 字幕策略 决定 F6 字幕来自哪里。 脚本锁定时建议用脚本或脚本音频对齐；保留真人原声时才考虑 ASR。
production_config.lip_sync.enabled 布尔值，必填 N4 lip-sync 判断 决定是否进入 F8。 开了就必须严格校验；不能开了但最后没用 retalked 片段。
production_config.lip_sync.scope 固定 talking_head_segments app 归一化 限定 lip-sync 只处理真人口播段。 非常重要：不能把整条成片或 B-roll 都送去口型同步。
production_config.lip_sync.inputRequirements 对象，启用 lip-sync 时必看 app 归一化 F8 输入校验：音频/视频格式、大小、时长、fps、人脸要求。 视频要求 mp4/avi/mov、2-120 秒、15-60fps、清晰正脸；音频要求 wav/mp3/aac、2-120 秒、清晰语音。
production_config.render.aspectRatio 当前固定 9:16 N4/N5 渲染配置 F9 渲染成片比例。 当前只支持竖屏短视频。传别的比例会被视为不支持。
service_config 对象，F0 生成 OpenStoryline settings + production_config 把 TTS、ASR、lip-sync provider 的运行配置注入 FireRed。 这里会包含 provider、model、timeout 等，但页面和日志不能暴露密钥。
lip_sync.plan_timeline 对象，F8 成功时必有 F8 lip_sync 给 F9 使用的“替换过口播段”的新时间线。 lip-sync 真成功的关键不是 provider 返回成功，而是最终渲染真的用了这条新时间线。

F0-F10：剪辑引擎内部每一步

F*

通俗解释：N7 是大门，F0-F10 是门里面真正发生的动作。前端进度、失败归因、质量验收，最好都能落到这些内部步骤上，而不是只说“剪辑中”。

输入

N6 准备好的本地素材、worker 标准合同、脚本、声音、字幕、lip-sync 开关。

处理过程

从合同适配开始，依次完成素材加载、切片、理解、配音、字幕、时间线、口型同步、渲染和校验。

输出

可被 END 上传的成片文件，以及每个内部步骤的结构化日志和失败阶段。

判断条件

任何 F 节点失败都要明确归因；关键产物缺失时不能继续伪造成片成功。

F0：Adapter，把 worker 合同转成 FireRed 生产指令

F0

通俗解释：worker 的任务单是平台自己的格式，FireRed 有自己的执行格式。F0 就是翻译官，把平台任务翻译成 FireRed 能执行的请求。

输入

RunRequest、ProductionDirective、productionConfig、本地素材路径。

处理过程

构造 FireRed /api/worker/runs 请求，注入 provider key、输出目录、素材列表、脚本和配置。

输出

FireRed run payload、run id、引擎调用上下文。

判断条件

缺 FireRed base URL 或 provider key：直接失败；合同字段缺失：回到 worker 合同错误。

例子：video_edit_jobs.input_payload 里有脚本、素材和声音策略，F0 把它转换成 FireRed 的 script / media / production_config。
本步骤重点字段
  • job_id：必填，用来串日志和输出目录。
  • workspace_dir / output_dir：必填，本地路径，不能是云存储 key。
  • production_directive：必填，告诉引擎目标平台、输出项和锁定字段。
  • production_config：必填，声音、字幕、lip-sync、渲染规则都在这里。
字段解释

F0 不做创意判断，它只负责把平台字段翻译给 FireRed。这里字段缺失，后面 F1-F10 再聪明也会跑偏，所以缺关键字段要早失败。

F1：load_media，读取本地素材

F1

通俗解释：这里不是去云上下载素材，下载已经在 N6 做完。F1 是 FireRed 读取 worker 放到本地目录里的视频、图片和音频。

输入

本地文件路径、素材 role、文件类型、素材来源说明。

处理过程

扫描并打开素材，确认文件存在、格式可读、基础 metadata 可取。

输出

FireRed 可使用的 media 列表、素材路径映射、不可读素材列表。

判断条件

关键素材不可读：失败；非关键素材不可读：按产品规则跳过或降级。

例子：/tmp/video-worker/.../courtyard.mp4 被读取为一个可剪辑素材；如果文件不存在，失败应归因到素材准备/加载。
本步骤重点字段
  • input_assets[].local_path：必填，文件必须存在且可读。
  • input_assets[].asset_type：必填，常见为 video、image、audio。
  • input_assets[].file_name：可选，用于展示和日志排查。
  • input_assets[].metadata：可选但重要，保留来源、存储 key、时长等信息。
字段解释

local_path 是服务器本地文件路径，不是 OSS/COS 地址。F1 只认本地能打开的文件；如果还只是云端 key，说明 N6 没准备好。

F2：split_shots，把素材切成可用片段

F2

通俗解释：一条视频可能很长，不能整条直接塞进成片。F2 会把素材切成多个镜头片段，后面才能挑哪些片段好用。

输入

F1 的 media 列表、视频时长、镜头变化检测配置、单素材 fallback 规则。

处理过程

按镜头边界或兜底规则切片，把长视频拆成多个 clip。

输出

split_shots.clips，每个 clip 有来源、起止时间、路径或引用。

判断条件

没有切出任何片段：失败或使用整段兜底；单素材场景要避免卡在分组。

例子：2026-05-19 真实成片记录里，FireRed evidence 显示 split_shots 输出 clips count 14。
本步骤重点字段
  • input_assets[].asset_type=video：只有视频素材才需要切片。
  • input_assets[].role：影响切片后是否保留 talking-head 语义。
  • metadata.duration：建议有，用于判断是否需要切片和是否超时。
  • split_shots.clips[]：输出字段，后续 F3/F7 都依赖。
字段解释

F2 的目标是把“素材文件”变成“可剪辑片段”。如果 role 在这里丢了，后面就很难知道哪个 clip 是真人口播。

F3：understand_clips，理解每段素材在拍什么

F3

通俗解释：切出来的片段还只是文件，系统需要知道它是门头、环境、人物、产品还是无效片段，才能和脚本镜头匹配。

输入

F2 的 clips、缩略帧、已有素材标签、脚本镜头需求。

处理过程

对 clip 做内容理解和质量判断，给出场景、主体、可用性和美观度描述。

输出

understand_clips 结果、clip 标签、质量分、和脚本需求的匹配线索。

判断条件

理解失败或质量过低：剔除或降权；关键镜头没有可用 clip：回到素材缺失。

例子：一段庭院视频被标为“安静庭院、座位、适合 B-roll”，就能匹配脚本里的“周末放空的小院”。
本步骤重点字段
  • split_shots.clips[].source_path：clip 来源文件。
  • input_assets[].tags / labels：已有素材标签。
  • materialContext.sceneAssetQueries[]：脚本对画面的需求。
  • understand_clips[].description：输出，描述 clip 拍了什么。
字段解释

F3 是把机器文件变成“人能理解的素材说明”。字段越完整，后面 F7 排时间线时越不容易把不相关素材塞进去。

F4：search_media / candidate match，补检索和候选素材匹配

F4

通俗解释：如果现有素材不够，或某个镜头需要更多候选，FireRed 这一层可能会做补检索。本项目更希望它优先使用 worker 已经选好的私有素材，不让它随意找外部素材。

输入

脚本镜头需求、F3 clip 理解结果、私有素材库候选、Pexels 兼容检索配置。

处理过程

优先匹配本地/私有素材；必要时通过兼容接口补候选，但不能越过商家权限边界。

输出

每个镜头的候选素材池、匹配理由、缺素材列表。

判断条件

私有素材足够：不外检；缺素材但禁止外检：提示补素材；允许外检：记录来源。

例子：worker 已从 source_items + asset_objects 补到庭院素材，F4 应优先使用这些私有素材，而不是重新找公共素材。
本步骤重点字段
  • materialContext.merchantMediaMatches[]：商家素材库命中结果。
  • materialContext.assetMatchPlan[]：镜头和素材的匹配计划。
  • service_config.search_media：可选，私有 Pexels 兼容检索配置。
  • materialContext.excludedAssetIds[]：被用户排除的素材。
字段解释

如果产品规定只用私有素材，F4 就不能自由找公共素材。excludedAssetIds 代表用户明确不要的素材，不能再次被选中。

F5：generate_voiceover，生成系统配音或克隆配音

F5

通俗解释：视频需要有人把脚本念出来。F5 会根据 N4 的声音策略生成配音；没有个人音色用系统配音，有个人音色用克隆配音。

输入

脚本文本、口播段落、系统 TTS 配置、voice_profile、参考音频。

处理过程

调用配音 provider，生成每段 voiceover，记录音频路径、时长和 provider 信息。

输出

配音音频，通常是 .wav 主产物；音频时长；voiceover metadata。

判断条件

无 ready 音色走系统配音；clone TTS 失败归因到 clone_tts 或 voiceover 阶段。

例子：2026-05-19 成功记录里 generate_voiceover 使用 minimax；克隆音色链路已发布但还未真实全链路验收。
本步骤重点字段
  • production_config.voiceover.enabled：是否生成配音。
  • production_config.voiceover.mode：system 或 voice_profile。
  • provider：系统配音 provider，支持 bytedance_bigtts、minimax、302。
  • voiceProfileId / refAudioAssetId：个人音色模式必填。
  • speed：可选，0.5 到 2；volume：0 到 3，默认 2。
字段解释

系统配音看 provider；克隆音色看 voice profile 和参考音频。用户想要“像本人说话”，就必须走 voice_profile 且字段完整。

M0-M5：音乐 / BGM 链路

M*

通俗解释：音乐不是一个装饰项，它会影响节奏、转场、音量混合和最终观感。当前系统里 BGM 由 production_config.bgm 控制，FireRed 通过 select_bgm 选择音乐，再进入时间线和渲染。

输入

production_config.bgm、BGM 资源目录 resource/bgms、音乐标签 meta.json、脚本和素材风格。

处理过程

判断是否启用 BGM，按用户要求和标签筛选候选音乐，选择一首，分析节拍和能量，再放入时间线。

输出

selected_bgm / music_rec.bgm、BGM track、混音音量、最终成片里的背景音乐。

判断条件

BGM 关闭则跳过；资源目录缺失或选择超时要明确失败或降级；口播场景要避免音乐盖住人声。

音乐链路关键字段
  • bgm.enabled：是否启用音乐，默认 true。
  • bgm.userRequest：用户或产品想要的音乐描述。
  • bgm.include/exclude：音乐标签筛选，只允许 mood、scene、genre、lang、id。
  • bgm.volume：BGM 音量，0 到 3，默认 0.25。
  • music_rec.bgm.path：选中的本地音乐文件。
  • music_rec.bgm.bpm/beats：节奏信息，供时间线卡点使用。
已知风险

2026-05-21 有真实诊断：FireRed 已到 select_bgm，但模型采样 450 秒超时，最终 worker 2700 秒超时失败。所以音乐链路需要明确“超时降级/跳过/失败”的产品规则。

M0：BgmConfig，决定要不要配音乐

M0

通俗解释：不是每条视频都必须有音乐。M0 先决定这条视频要不要 BGM，以及音乐应该是什么气质。

输入

production_config.bgm.enabled、userRequest、include、exclude、volume。

处理过程

校验字段是否合法，判断音乐是否启用，整理用户的音乐风格要求。

输出

标准化后的 BGM 配置，供 M1/M2 使用。

判断条件

enabled=false：跳过 M1-M4；volume 超出 0-3：任务配置错误。

例子：口播带货视频可以设置 userRequest="轻快但不抢人声"，volume=0.18。

M1：BgmResourceReady，检查音乐资源库

M1

通俗解释：要选音乐，服务器上必须有音乐库。FireRed 默认看 resource/bgms 和里面的 meta.json 标签。

输入

project.bgm_dir、resource/bgms、resource/bgms/meta.json。

处理过程

确认目录存在、是目录、有音频文件、有可用标签库。

输出

候选音乐库和标签索引。

判断条件

目录不存在、不是目录、无音频文件：音乐链路失败或降级跳过，取决于产品规则。

例子：ready 检查曾显示 runtime_assets.bgms=true，说明服务器 BGM 资源目录存在。

M2：FilterCandidates，按标签筛选候选音乐

M2

通俗解释：音乐库里可能有很多首，M2 先按标签筛一轮，比如情绪、场景、曲风、语言、指定 id。

输入

bgm.include、bgm.exclude、音乐标签库。

处理过程

include 多个维度按 AND，同一维度多个值按 OR；exclude 命中的候选会被排除。

输出

候选音乐列表。

判断条件

没有候选：失败或回退默认音乐；filter key 不支持：任务配置错误。

例子：include.scene=["Cafe"]、include.mood=["Chill"] 会优先找咖啡馆、放松感音乐。

M3：select_bgm，选择一首背景音乐

M3

通俗解释：M3 会结合用户要求和候选音乐，选出最适合的一首。当前实现会调用模型做选择，模型失败时可能降级选第一个候选。

输入

userRequest、候选音乐 entries、select_bgm prompt。

处理过程

模型从候选中选一首；如果模型输出不是合法 JSON 或没有 path，则降级选择候选第一首。

输出

选中的音乐 JSON，至少需要 path，通常还有 id。

判断条件

模型采样超时：当前有真实失败记录；需要决定 fail-fast、跳过 BGM 还是 deterministic fallback。

例子：2026-05-21 失败记录显示任务卡在 select_bgm，模型采样 450 秒超时，最后 worker 2700 秒超时。

M4：AnalyzeMusicMetrics，分析节拍、时长和能量

M4

通俗解释：选中音乐后，还要知道它多长、节奏多快、哪里有节拍，这样时间线才能卡点，渲染时也能循环或截断。

输入

选中的音乐文件 path、采样率、frame/hop 配置。

处理过程

用 librosa 读取音频，计算 duration、bpm、beats、energy_mean、dynamic_range_db。

输出

bgm_id、path、duration、bpm、beats、energy_mean、dynamic_range_db。

判断条件

文件不存在、ffmpeg/librosa 读不了、音乐太短：失败或换候选。

例子：如果音乐长度短于成片，后续 render 会循环；如果长于成片，会截断到视频长度。

M5：BgmTrackToTimeline，音乐进入时间线和最终混音

M5

通俗解释：选好的音乐不是单独存在，它要被放进时间线的 BGM 轨道，最后在 render_video 里和人声、原声一起混成最终音频。

输入

M4 的 music_rec.bgm、F7 时间线、bgm.volume、最终视频时长。

处理过程

构建 tracks.bgm，按视频长度循环或截断音乐，渲染时用 bgm_volume_scale 控制音量。

输出

带 BGM track 的时间线、最终混音后的 final.mp4。

判断条件

真人口播/配音存在时，BGM 音量不能盖住人声；缺 BGM 轨时 render 应允许无音乐出片或按规则失败。

例子：bgm.volume=0.18 适合口播为主的视频；纯环境展示视频可以更高，但仍要防止刺耳。

F6：subtitle / alignment，生成字幕和音频对齐

F6

通俗解释：字幕不能只是把脚本贴上去，它要和声音时间对上。F6 决定字幕来自脚本、ASR，还是脚本和音频对齐结果。

输入

脚本文本、F5 配音音频、ASR 配置、字幕策略 subtitlePolicy。

处理过程

生成字幕时间戳，必要时跑 ASR 或脚本音频对齐，把文本切成适合展示的字幕段。

输出

字幕 segments、subtitles.srt、脚本音频对齐 metadata。

判断条件

脚本锁定且使用 TTS：优先脚本对齐；真人原声：可用 ASR；ASR 失败要明确归因。

例子：真人口播目标路径里，字幕可以来自 script_audio_alignment，避免 ASR 把营销文案识别错。
本步骤重点字段
  • production_config.subtitles.enabled：是否输出字幕。
  • production_config.subtitles.style：platform_default 或 bold_caption。
  • talkingHeadSource：script、script_audio_alignment、asr_original_audio。
  • service_config.asr：当走 ASR 时需要 provider、model、sample_rate 等运行配置。
字段解释

script_audio_alignment 更适合“脚本已锁定 + TTS/克隆配音”；asr_original_audio 更适合保留真人原声的情况。

F7：plan_timeline / plan_timeline_pro，规划最终时间线

F7

通俗解释：前面已经有素材、配音和字幕，F7 要决定最终成片里每一秒放哪段素材、哪段声音、哪句字幕。

输入

F3/F4 候选素材、F5 配音、F6 字幕、脚本镜头需求、目标时长和比例。

处理过程

选择每个镜头使用的 clip，安排起止时间，组合音频、字幕、B-roll 和 talking-head 段。

输出

plan_timeline 或 plan_timeline_pro，包含 tracks、segments、素材路径和时间戳。

判断条件

时间线缺关键轨道：失败；无 voiceover/BGM 时要移除可选依赖，避免卡住。

例子：2026-05-19 记录显示 plan_timeline_pro succeeded；lip-sync 场景会先产生普通时间线，再交给 F8 替换 talking-head 段。
本步骤重点字段
  • production_directive.desired_outputs：决定要不要封面、字幕等输出。
  • production_config.render.aspectRatio：当前固定 9:16。
  • production_config.render.maxDurationSeconds：可选，15 到 180 秒。
  • plan_timeline.tracks / segments：输出，F8/F9 直接消费。
字段解释

F7 是“排片表”。它决定每一秒用哪个素材、哪段音频和哪句字幕。后续 lip-sync 和 render 都不能脱离这张表。

F8：lip_sync，只对真人口播段做口型同步

F8

通俗解释：lip-sync 不是把整条视频都丢给 VideoRetalk，而是只处理真人口播片段。B-roll 和项目素材不该被口型同步。

输入

F7 时间线里的 talking-head segments、F5 克隆音频、VideoRetalk 配置、可访问的视频/音频 URL。

处理过程

筛选真人口播段，必要时切段，调用 VideoRetalk，生成 retalked 片段，再写回新的 lip_sync.plan_timeline。

输出

lip_sync.segments、retalked 视频片段、只替换口播段的新时间线。

判断条件

未启用 lip-sync：跳过；缺 URL/人脸不合格/音频不合格：失败在 lip_sync，不能假成功。

例子：只有第 1 镜真人口播会被替换成 retalked 视频；庭院 B-roll 保持原素材不变。
本步骤重点字段
  • production_config.lip_sync.enabled：是否进入 F8。
  • production_config.lip_sync.provider：当前 aliyun_videoretalk。
  • production_config.lip_sync.scope：固定 talking_head_segments。
  • inputRequirements.audio：wav/mp3/aac，2-120 秒，清晰语音。
  • inputRequirements.video：mp4/avi/mov，2-120 秒，15-60fps，清晰正脸。
字段解释

F8 的硬规则是“只替换真人口播段”。如果没有合格视频 URL、音频 URL 或正脸条件，不允许跳过后伪造成片成功。

F9：render_video，渲染 final.mp4

F9

通俗解释：F9 把时间线真正合成为视频文件。素材、配音、字幕、BGM、口型同步后的片段都在这里合到一起。

输入

普通 plan_timeline 或 F8 产出的 lip_sync.plan_timeline、字幕、音频、输出规格。

处理过程

按时间线调用渲染能力，合成视频轨、音频轨、字幕和封面。

输出

final.mp4、封面图、字幕文件、渲染 metadata。

判断条件

lip-sync 开启时必须读取 F8 的 retalked 时间线；缺 final.mp4 或未消费 retalked 片段必须失败。

例子：2026-05-21 release 已要求 render_video 优先读取 lip_sync.plan_timeline，并记录 lip_sync_segments_consumed。
本步骤重点字段
  • plan_timeline：普通渲染输入。
  • lip_sync.plan_timeline：lip-sync 开启时优先使用。
  • production_config.render.includeOriginalAudio：是否保留原声。
  • production_config.render.preserveTalkingHeadOriginalAudio：是否特别保留口播原声。
  • output_dir/final.mp4：渲染主产物。
字段解释

lip-sync 开启后，F9 不能再用旧的普通时间线。它必须用 lip_sync.plan_timeline，否则嘴型替换没有真正进入成片。

F10：ValidateEngineOutputs，校验引擎产物

F10

通俗解释：渲染结束不等于可交付。F10 要检查成片文件是否真实存在、大小是否合理、字幕和封面是否齐全，lip-sync 是否真的被消费。

输入

F9 输出文件、metadata、引擎日志、lip-sync 消费记录。

处理过程

检查文件存在、大小、路径、必要 metadata、关键输出项和 lip-sync 验收字段。

输出

可交给 END 上传的产物清单、校验通过/失败原因、最终引擎结果。

判断条件

final.mp4 缺失：失败；lip-sync 开启但未消费 retalked segments：失败；非关键输出缺失按产品规则处理。

例子：如果 F8 生成了 retalked 片段，但 F9 仍用旧口播视频渲染，F10 必须拦住，不能让 END 上传假成功成片。
本步骤重点字段
  • final_video_path：必填，必须存在且是有效视频。
  • cover_image_path：可选或按 desired_outputs 决定。
  • subtitle_path：可选或按 desired_outputs 决定。
  • metadata_path：必填，用来排查引擎执行结果。
  • lip_sync_segments_consumed：lip-sync 验收关键字段。
字段解释

F10 是防假成功的最后一道门。尤其是 lip-sync，必须确认 retalked segments 被渲染消费，而不是只看 provider 有没有返回结果。

END：UploadResultAndPreview，成片上传并回写前端

END

通俗解释：剪完以后，worker 把成片、封面、字幕上传回对象存储，并写入数据库。前端看到的预览和下载都来自这里。

输入

FireRed 输出文件、封面、字幕、metadata、本地日志。

处理过程

校验文件，上传到对象存储，写入 asset_objects 和 result_payload，更新 job 状态。

输出

成片 asset id、封面 asset id、字幕 asset id、前端 preview/download 路由。

判断条件

上传成功：succeeded/completed；上传失败：failed_retryable；产物缺关键文件：按产品规则决定成功或失败。

例子：上传 video-results/<merchantId>/<jobId>/final.mp4，前端 preview/download 返回 200。

FAIL：失败分流和下一步动作

FAIL

通俗解释：失败不能只显示“生成失败”。要告诉用户卡在素材、声音、口型同步、渲染还是上传，以及下一步是自动重试还是人工补东西。

输入

各节点抛出的错误、failure_stage、worker 日志、引擎日志、对象存储错误。

处理过程

把失败归类为可重试或需人工处理，并生成用户能看懂的诊断文案。

输出

failed_retryable、failed_manual、失败阶段、推荐动作、可重试入口。

判断条件

网络/对象存储/临时超时：可重试；缺素材、口播不合格、合同错误：人工处理。

例子：VideoRetalk 输入视频不合格时，提示“口播视频不适合对口型，请上传清晰正脸视频”，而不是泛化成“系统繁忙”。

三、两条典型链路例子

把上面的节点串起来看，方便判断哪条是主路径，哪条是增强路径。

例子 A：普通商家素材库出片

  • START：脚本定稿，“介绍一个适合周末放空的咖啡小院”。
  • N1：拆出门头、庭院、座位、饮品、结尾 CTA。
  • N2：判断这些都可以走商家素材库，不要求真人口播。
  • N3B：从素材库命中 6 条视频，筛出 4 条可剪辑片段。
  • N4：没有个人音色，使用系统配音和脚本字幕。
  • N5 到 N6：创建 job，worker 下载素材。
  • N7 内部：F0 适配合同，F1 加载素材，F2 切片，F3 理解素材，F5 生成系统配音，M0-M5 选择并混入 BGM，F6 生成字幕，F7 规划时间线，F9 渲染，F10 校验。
  • END：成片上传对象存储，结果回写前端。
已有真实成功类型

例子 B：真人口播 + 克隆音色 + lip-sync

  • START：脚本定稿，“大家好，今天带你看一个适合周末放空的院子”。
  • N1：第 1 镜标记为真人口播，后续镜头为庭院 B-roll。
  • N2：真人口播走成员素材，庭院 B-roll 走商家素材库。
  • N3A/N3B：成员上传正脸口播，素材库补环境镜头。
  • N4：读取 ready voice_profile，生成克隆音频，并启用 lip-sync。
  • N7 内部：F5 生成克隆音频，M0-M5 选择低音量 BGM，F6 做字幕/对齐，F7 规划普通时间线，F8 只对 talking-head 段做 VideoRetalk。
  • F9/F10：render 必须消费 retalked 时间线，校验通过后才交给 END。
  • END：成片上传对象存储，结果回写前端。
