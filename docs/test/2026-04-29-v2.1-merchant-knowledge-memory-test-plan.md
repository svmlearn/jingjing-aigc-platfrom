# V2.1 商家知识库与商家记忆测试计划

日期：2026-04-29
状态：开工前测试文档
对应开发清单：`docs/handoff/2026-04-29-v2.1-merchant-knowledge-memory-dev-checklist.md`

## 1. 测试目标

验证 `商家设置 > 商家知识库` 的 V1 能力：

1. 商家可上传 `txt / md` 商家资料。
2. 商家可手动录入可编辑的商家记忆。
3. 商家资料和商家记忆严格按商家隔离。
4. 只有 `indexed / 可用于咨询` 的内容进入咨询上下文。
5. 不出现商家侧 `knowledge_sets` 概念。

## 2. 自动验证

在 `app/` 目录执行：

```bash
npm run lint
npm run typecheck
npm run build
```

通过标准：

- 三条命令退出码均为 0。
- 不引入新的 lint、类型或构建错误。

## 3. 页面与交互测试

### 3.1 商家知识库入口

- [ ] 登录商家账号后访问 `/dashboard/settings`。
- [ ] 页面出现 `商家知识库` Tab。
- [ ] Tab 内存在两个明确动作：`知识库上传`、`记忆录入`。
- [ ] 空状态能说明当前还没有商家资料或商家记忆。
- [ ] 页面不出现 `knowledge_sets`、知识集、Agent 绑定等平台管理概念。

### 3.2 知识库上传

- [ ] 未填写资料名称时提交被阻断，提示名称必填。
- [ ] 上传 `.txt` 文件成功创建商家资料。
- [ ] 上传 `.md` 文件成功创建商家资料。
- [ ] 上传非 `txt/md` 文件被阻断，并提示当前格式不支持。
- [ ] 上传超过 `10MB` 的文件被阻断，并提示单文件大小上限。
- [ ] 上传后列表显示名称、类型、状态、更新时间。
- [ ] 文件型资料编辑态只允许改名，不允许在线替换正文。
- [ ] 文件型资料处理失败时可以改名、删除，若实现 retry 则可以重新处理。

### 3.3 记忆录入

- [ ] 未填写记忆名称时提交被阻断，提示名称必填。
- [ ] 记忆正文为空时提交被阻断。
- [ ] 记忆正文 `1000` 个可见字符以内可提交。
- [ ] 记忆正文超过 `1000` 个可见字符被阻断。
- [ ] 新建商家记忆后列表类型显示为 `商家记忆`。
- [ ] 商家记忆可改名。
- [ ] 商家记忆可编辑正文。
- [ ] 商家记忆正文修改保存后重新进入处理流程。
- [ ] 商家记忆删除后不再出现在列表。

### 3.4 状态显示

- [ ] `uploaded` 显示为 `已上传，待处理`。
- [ ] `queued` 显示为 `队列中`。
- [ ] `processing` 显示为 `处理中`。
- [ ] `indexed` 显示为 `可用于咨询`。
- [ ] `failed` 显示为 `处理失败`。
- [ ] 失败状态展示商家可理解的失败原因。

## 4. API 与数据测试

### 4.1 商家隔离

准备商家 A 和商家 B。

- [ ] 商家 A 上传资料后，商家 B 列表不可见。
- [ ] 商家 B 上传资料后，商家 A 列表不可见。
- [ ] 商家 A 使用商家 B 的 documentId 调用编辑接口，应返回 403 或 404。
- [ ] 商家 A 使用商家 B 的 documentId 调用删除接口，应返回 403 或 404。
- [ ] API 不接受客户端传入任意 `merchantId` 来指定目标商家。

### 4.2 Supabase 记录

检查 `knowledge_documents`：

- [ ] 商家侧内容 `scope = merchant`。
- [ ] 商家侧内容 `merchant_id` 为当前商家。
- [ ] 商家资料 metadata 包含 `sourceType = file`、`contentKind = merchant_document`、`chunkPolicy = auto`。
- [ ] 商家记忆 metadata 包含 `sourceType = memory`、`contentKind = merchant_memory`、`chunkPolicy = single`。
- [ ] 商家记忆原文保存在 Supabase 可恢复位置，例如 `metadata.sourceText`。

检查 `knowledge_chunks`：

- [ ] 商家记忆仅生成 1 个 chunk。
- [ ] `txt / md` 文件按现有自动切分逻辑生成 1 个或多个 chunk。
- [ ] chunk 记录关联正确 documentId。

## 5. 咨询链路测试

### 5.1 可用内容参与咨询

- [ ] 商家 A 有一条 `indexed` 商家记忆，内容中包含独特关键词。
- [ ] 商家 A 发起包含该关键词或相关意图的咨询。
- [ ] 咨询检索结果可命中当前商家的商家记忆。
- [ ] 回复生成上下文包含商家记忆内容。
- [ ] 工具卡片或摘要文案不再只写平台侧知识，推荐显示 `检索平台方法论与商家上下文`。

### 5.2 未完成内容不参与咨询

- [ ] `uploaded` 内容不参与咨询上下文。
- [ ] `queued` 内容不参与咨询上下文。
- [ ] `processing` 内容不参与咨询上下文。
- [ ] `failed` 内容不参与咨询上下文。

### 5.3 混排 topK

- [ ] 平台方法论知识库和当前商家知识库共同参与检索。
- [ ] 检索结果按现有 topK 混排。
- [ ] 不读取其他商家的商家资料或商家记忆。

## 6. 回归测试

- [ ] 平台后台原有知识库上传、列表、删除仍可用。
- [ ] 商家设置基础信息保存仍可用。
- [ ] 咨询会话创建仍可用。
- [ ] 咨询消息发送和回复仍可用。
- [ ] 未登录访问商家设置仍显示既有登录引导或认证处理，不暴露裸技术错误。

## 7. 非目标确认

本轮测试不要求通过：

- 商家侧知识集分组。
- 商家侧 Agent 绑定管理。
- 平台运营代维护商家资料。
- PDF / DOCX / 图片 / 音频上传。
- 批量上传。
- 图文工作台读取商家知识库。
- 视频工作台读取商家知识库。
