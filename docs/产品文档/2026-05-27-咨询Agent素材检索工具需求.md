# 2026-05-27 咨询 Agent 素材检索工具需求

## 结论

当前咨询 Agent 还缺两个关键业务工具：

1. 从商家视频素材库中检索已上传/已打标视频素材的工具。
2. 从已沉淀的社交媒体爆款内容库中检索内容的工具。

这两个工具是“让 Agent 基于真实素材和真实爆款内容生成内容日历”的前提。否则 Agent 在用户要求“参考我已有的视频素材和爆款内容库”时，只能靠用户口头描述和已有策略资产推断，不能真实说明“我检索了哪些素材、用了哪些爆款参考”。

## 需要补的两个工具

### 1. `search_project_video_materials`

建议语义：

- 从当前商家的视频素材库检索 ready 视频素材。
- 主要读取 `merchant_media_clips`，必要时沿用 private media repository 的检索能力。
- 用于回答：
  - “我现有视频素材能拍什么内容？”
  - “哪些素材适合做夜宵、烤串、工业园、工友下班等选题？”
  - “你刚才规划内容日历到底参考了哪些视频？”

建议参数：

```json
{
  "query": "烤串 工业园 工友 下班 夜宵",
  "limit": 8,
  "orientation": "landscape|portrait 可选",
  "minDurationSeconds": "可选",
  "maxDurationSeconds": "可选"
}
```

建议返回给 Agent 的字段：

- `clipId`
- `assetId`
- `title` 或简短描述
- `description`
- `tags / sceneTags / shotTags / peopleTags / qualityTags`
- `width / height / orientation / durationSeconds`
- `matchReason`

不要把 OSS key、bucket、下载 token、签名 URL 直接暴露给模型；模型只需要素材语义和可引用 ID。

### 2. `search_saved_viral_materials`

建议语义：

- 从当前商家已经沉淀的社交媒体爆款内容库里检索。
- 不调用外部 TikHub。
- 不新增 provider 结果。
- 只读当前已有 `source_items` / `imported_comments` / `asset_objects` 中的 ready 爆款内容。

用于回答：

- “你参考了哪些爆款内容？”
- “这个烧烤摊可以借鉴哪些开头、标题、评论痛点？”
- “我已有的爆款内容库里有没有和工业园、夜宵、酱料相关的内容？”

建议参数：

```json
{
  "query": "烧烤 夜宵 工业园 下班 工友 独家酱料",
  "platform": "douyin|xiaohongshu 可选",
  "limit": 8
}
```

建议返回给 Agent 的字段：

- `materialId`
- `platform`
- `title`
- `materialType`
- `description/bodyText/scriptText`
- `engagementLabel`
- `structureSummary`
- `topComments`
- `originalUrl`
- `matchReason`

返回内容要紧凑，避免把 raw TikHub payload 整包塞进上下文。

## 为什么这是 P0/P1 级缺口

这不是“锦上添花”。

用户已经在真实业务路径里要求：

> 我这里有很多自己上传的视频素材了，还有一些社交媒体的爆款内容库，你参考他们的来帮我规划，帮我建议。

Agent 随后生成了内容日历建议，但在用户追问“你都检索了什么爆款内容，或者什么视频素材”时，只能承认没有工具。

这会造成三个问题：

1. 生成内容日历时没有真实证据链。
2. Agent 不能解释“为什么这个选题适合你现有素材”。
3. 用户无法相信它真的利用了素材库和爆款库。

所以明天修复时，核心验收不是“工具列表里多两个名字”，而是 Agent 能在咨询里真实调用、真实返回、真实引用。
