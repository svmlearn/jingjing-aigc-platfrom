# 小红书抖音矩阵获客平台 V0.1 功能清单

## 1. 当前版本定位

### 1.1 当前前提

这个版本先按 **邀请码制试点版** 设计，不做公开开放注册。

这意味着：

- 可以优先追求“链路跑通”
- 可以先保留部分内部工具型能力
- 不必一开始就把所有授权、分发、商业化边界都做到最终形态
- 长期方向仍按多租户 SaaS 设计，但第一版先控流

### 1.2 V0.1 核心目标

用最短路径跑通这条链路：

1. 找到对标账号内容
2. 把内容导进来
3. 提取标题/结构/口播/评论角度
4. 基于商家画像改写成自己的版本
5. 发布到自己的小红书/抖音账号

### 1.3 V0.1 一句话定义

一个邀请码制试点的“小红书 / 抖音内容仿写与发布工作台”。

---

## 2. V0.1 最小可验证价值

如果这个版本做成，至少要证明一件事：

**我们可以把一个对标账号的内容，较稳定地转成“适合某个商家自身情况”的内容，并成功发到自有账号。**

换句话说，V0.1 不是验证“全网抓取能力”，而是验证：

- 对标内容导入是否足够有用
- 商家画像驱动的改写是否足够有效
- 小红书/抖音发布是否足够顺手

---

## 3. V0.1 必做功能

下面这些是第一版建议直接做的。

### 3.1 对标内容导入

#### 必做功能

- 手动输入小红书 / 抖音内容链接导入
- 手动输入 creator 主页链接或 ID 导入
- 支持导入单条内容详情
- 支持导入 creator 下的一批内容列表

#### 为什么要做

- 这是最接近你真实需求的入口
- 比“全自动批量全网抓取”更可控
- 也是对 `MediaCrawler` 现成能力最合理的用法

#### V0.1 的边界

- 不做全自动长期监控某个博主
- 不做无限量批量抓取
- 不做无人值守全量同步

### 3.2 评论抓取与查看

#### 必做功能

- 支持导入内容时同时带回评论
- 支持查看一级评论
- 如当前链路允许，支持查看二级评论
- 评论支持按热度或时间查看

#### 为什么要做

- 评论区是提炼用户痛点、常见问题、钩子文案的重要来源
- 对健身、瑜伽、门店类内容来说，评论往往比正文更能体现转化角度

#### V0.1 的边界

- 不做复杂评论分析面板
- 不做情绪分类、自动总结报告
- 先做“能看、能复制、能作为改写输入”

### 3.3 商家画像知识库

这里我们把你说的“品牌知识库”收敛成更实用的说法：

- **商家画像**

#### 必做功能

- 创建商户档案
- 维护目标客群画像
- 维护主打项目 / 服务
- 维护卖点
- 维护地域信息
- 维护地址
- 维护联系人
- 维护联系电话
- 维护语气风格
- 维护禁用词 / 不可说内容
- 维护常用 CTA

#### 为什么要做

- 改写不是简单洗稿，必须让内容落到“这个商家自己的用户画像”
- 这是你后面做数字人、脚本、批量内容时的基础层

### 3.4 内容拆解与改写

#### 必做功能

- 提取原内容标题
- 提取原内容正文 / 口播文案
- 提取内容结构
- 支持一键生成“小红书版本”
- 支持一键生成“抖音口播脚本版本”
- 支持生成多个改写版本
- 支持人工编辑

#### 为什么要做

- 这是 `AIWriteX` 最值得借的部分
- 也是这套系统区别于“纯发布工具”的核心

#### V0.1 的边界

- 不追求全自动镜头级分镜还原
- 不追求极强的视频脚本拆镜
- 先把“标题 + 结构 + 口播/正文”改写做好

### 3.5 内容草稿中心

#### 必做功能

- 草稿列表
- 查看原始导入内容
- 查看提取结果
- 查看改写版本
- 编辑草稿
- 保存平台版本

#### 为什么要做

- 采集结果、改写结果、发布结果如果分散在不同脚本里，实际不好用
- 第一版就要有一个统一“草稿中心”

### 3.6 审核与发布准备

#### 必做功能

- 选择商户
- 选择发布平台
- 选择发布账号
- 手动调整标题、正文、标签
- 选择立即发布或定时发布

#### 为什么要做

- 第一版不能黑箱自动发
- 发布前一定要有人审一下

### 3.7 多账号发布

#### 必做功能

- 小红书账号登录
- 抖音账号登录
- 账号状态检查
- 单账号发布
- 定时发布
- 任务结果记录

#### 为什么要做

- 这是 `social-auto-upload` 最成熟的价值
- 也是第一版最硬核的可用能力

#### V0.1 的边界

- 不做复杂账号权限系统
- 不做团队协作审批
- 不做跨平台十几个渠道一起发

### 3.8 发布任务记录

#### 必做功能

- 发布中
- 发布成功
- 发布失败
- 失败原因查看
- 任务日志查看

#### 为什么要做

- 第一版只要一发失败，若没有记录，基本就不可用

## 4. V0.1 可选增强功能

这些不是必须，但如果实现成本低，可以放进 `V0.1+`。

### 4.1 关键词搜索导入

- 通过关键词搜索对标内容
- 适合做灵感发现

结论：

- 可做，但优先级低于 `detail` 和 `creator`

### 4.2 热点辅助输入

- 接 AIWriteX 的热榜能力
- 作为选题补充

结论：

- 可以后置，不作为第一版核心

### 4.3 评论总结为改写提示

- 从评论中自动提取痛点、疑问、反对点

结论：

- 值得做，但可放到 V0.2

## 5. V0.1 明确不做

这些内容要明确写出来，避免范围蔓延。

- 不做全自动批量抓某个对标博主全部历史内容
- 不做无人值守的长期监控抓取
- 不做完整的数字人生成链路
- 不做镜头级分镜拆解
- 不做复杂评论分析大屏
- 不做完整多租户权限 / 计费体系
- 不做团队协作、权限审批体系
- 不做公众号、知乎、百家号等额外渠道
- 不做复杂 BI 看板

---

## 6. 替代“全自动批量抓全部内容”的方案

你前面说得很对，当前阶段我们暂时做不到“全自动批量抓对标博主的全部内容”，所以第一版需要更现实的替代方案。

### 6.1 替代方案 A：手动 creator 导入

做法：

- 手动填一个 creator 主页
- 系统拉取该 creator 的一批内容列表
- 用户自己勾选需要进入改写池的内容

优点：

- 已经足够接近真实需求
- 风险和工程复杂度都更低

### 6.2 替代方案 B：detail 链接导入

做法：

- 直接贴某条小红书 / 抖音链接
- 导入该条内容与评论

优点：

- 最稳
- 最容易先跑通

### 6.3 替代方案 C：关键词搜索导入

做法：

- 输入关键词，例如“健身房减脂打卡”“瑜伽体态改善”
- 导入一批搜索结果

优点：

- 更适合做灵感池

缺点：

- 不如 creator 精准

### 6.4 V0.1 推荐顺序

建议优先顺序：

1. `detail`
2. `creator`
3. `search`

## 7. V0.1 页面清单

第一版建议至少有这 6 个页面 / 模块。

### 7.1 导入页

功能：

- 贴链接导入
- 填 creator 导入
- 可选关键词搜索导入

### 7.2 内容池 / 导入结果页

功能：

- 看导入到的内容列表
- 看标题、平台、作者、评论数量
- 选择进入改写

### 7.3 商家画像页

功能：

- 编辑商户信息
- 编辑服务项目
- 编辑用户画像
- 编辑风格与 CTA

### 7.4 改写工作台

功能：

- 查看原文
- 查看评论
- 生成小红书版本
- 生成抖音脚本版本
- 多版本切换与编辑

### 7.5 账号管理页

功能：

- 登录小红书账号
- 登录抖音账号
- 检查账号状态

### 7.6 发布任务页

功能：

- 选择账号发布
- 定时发布
- 查看任务状态与日志

## 9. V0.1 验收标准

这个版本做完，至少要满足下面这些判断标准：

### 9.1 导入链路

- 能成功导入一条小红书或抖音内容
- 能成功导入一个 creator 的内容列表
- 能成功看到评论

### 9.2 改写链路

- 能根据商家画像生成至少 2 个改写版本
- 能分别生成小红书版和抖音口播版
- 能人工编辑并保存

### 9.3 发布链路

- 能登录至少 1 个小红书账号
- 能登录至少 1 个抖音账号
- 能成功发布至少 1 条内容
- 能看到失败日志和成功记录

### 9.4 整体闭环

- 选一个健身或瑜伽对标账号
- 导入内容
- 结合一个商户画像改写
- 发布到自有账号

如果这条闭环能稳定跑通，V0.1 就算成立。
