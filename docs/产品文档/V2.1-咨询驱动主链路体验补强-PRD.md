# 小红书抖音矩阵获客平台 V2.1 咨询驱动主链路体验补强 PRD

## 1. 文档定位

这份文档用于记录当前阶段已经拍板的产品取舍，并把下一轮需要补强的需求收敛成一版可执行 PRD 草案。

命名采用 `V2.1`：

- `V2`：代表当前产品形态已经从早期 `V0.1` 的“导入到改写”试点，进入“咨询驱动的内容生产平台”阶段。
- `.1`：代表该大版本下的第一轮体验补强，不重新定义整个产品，只补当前主链路中的缺口。

本稿是对现有实现与产品判断的补充，不推翻以下事实：

- 主链路必须是 `咨询驱动`。
- 不做矩阵分发。
- 不做账号发布。
- 对标导入已经存在，不作为本 PRD 的新增建设重点。
- 效果回流需要记录，但优先级后置。

## 2. 当前代码与产品现状

### 2.1 当前商家端主入口

当前商家端主导航已经围绕咨询驱动组织：

```text
+--------------------------------------------------------------------------------+
| 咨询诊断 | 图文工作台 | 视频工作台 | 素材中心 | 我的内容 | 商家设置          |
+--------------------------------------------------------------------------------+
```

其中：

- `/dashboard`：AI 咨询诊断。
- `/dashboard/article`：图文工作台。
- `/dashboard/video`：视频工作台。
- `/dashboard/content`：素材中心。
- `/dashboard/history`：我的内容。
- `/dashboard/settings`：商家设置。

`/dashboard/import` 当前已不再作为商家主入口，而是重定向到 `/dashboard`。

### 2.2 对标导入现状

对标导入不是本轮新增项，当前代码中已经存在两层能力：

第一层是早期导入链路：

```text
POST /api/import-jobs
GET  /api/import-jobs
POST /api/import-jobs/:id/run
GET  /api/source-items
GET  /api/source-items/:id
GET  /api/source-items/:id/comments
```

对应数据与执行能力包括：

- `import_jobs`
- `source_items`
- `imported_comments`
- `ApifyProviderAdapter`
- 小红书 detail / creator / comments
- 抖音 detail / comments

第二层是当前商家端素材中心：

```text
素材中心
-> 上传素材
-> 找对标
-> 对标库 / 用户上传
-> 送入图文工作台或视频工作台
```

对应 API 包括：

```text
GET  /api/materials
POST /api/materials
POST /api/materials/benchmark-search
POST /api/materials/:materialId/send-to-workbench
```

因此，本 PRD 不再定义“从零建设对标导入”。后续重点是把对标素材自然接进咨询、图文和视频工作台，而不是另开一条主链路。

## 3. V2.1 产品目标

V2.1 的目标不是扩大功能面，而是把当前已经成立的咨询驱动闭环打磨成可连续使用的工作流。

当前主链路应收敛为：

```text
商家资料
-> AI 咨询诊断
-> 策略快照 / 内容日历 / 图文 brief / 视频 brief
-> 素材中心补充对标素材或上传素材
-> 图文工作台生成并 AI 修改
-> 视频工作台生成脚本并恢复任务状态
-> 我的内容沉淀咨询、草稿、脚本、视频任务
```

V2.1 要解决的核心问题：

1. 图文生成后，用户不能只“重新生成”，还要能让 AI 按指令修改。
2. 视频任务刷新后，工作台应能恢复最新任务状态。
3. 视频链路不能长期停留在 skeleton 保底轨，需要向真实视频执行能力升级。
4. 未登录状态不能露出技术错误，要给用户清楚的登录、注册或邀请码引导。
5. 知识库要从平台级文本知识，继续扩展到商家可用的资料体系。
6. Agent 要继续从固定工具链升级为更接近真实 planner 的业务 Agent。
7. 心跳和插话中断需要进入规划，但优先级低于主链路补强。
8. 效果回流先记录为后续版本，不进入 V2.1 主交付。

## 4. 非目标

V2.1 明确不做：

- 不做矩阵分发。
- 不做账号发布。
- 不做小红书 / 抖音账号授权。
- 不做发布排期。
- 不做账号健康检测。
- 不做多账号角色分工。
- 不重建一套新的对标导入系统。
- 不把效果回流作为本轮必须上线项。

## 5. 用户旅程地图

### 阶段一：商家准备上下文

商家进入系统
-> 注册或登录
-> 补全商家设置
-> 维护品牌定位、服务项目、客群、语气、禁用词、默认 CTA
-> 系统将这些资料作为咨询、图文、视频的共同上下文

### 阶段二：用咨询确定内容方向

商家进入 AI 咨询诊断
-> 输入当前经营问题或内容目标
-> Agent 读取商家资料、历史内容、平台知识库
-> Agent 更新策略快照和内容日历
-> Agent 生成图文 brief 与视频 brief
-> 商家确认当前方向是否可用于创作

### 阶段三：补充素材和对标参考

商家进入素材中心
-> 上传自己的素材链接或文本
-> 通过关键词或主页找对标素材
-> 选中一条素材
-> 送入图文工作台或视频工作台
-> 素材成为本次生成或修改的参考输入

### 阶段四：图文生成与 AI 修改

商家进入图文工作台
-> 系统带入咨询策略、素材参考、商家资料
-> 用户生成图文草稿
-> 系统保存多个版本
-> 用户选择其中一个版本
-> 用户输入修改要求
-> AI 基于选中版本生成新版本
-> 用户继续修改、保存或归档

### 阶段五：视频脚本与视频任务

商家进入视频工作台
-> 系统带入视频 brief、咨询策略和素材参考
-> 用户生成视频脚本
-> 用户创建视频任务
-> 系统写入视频任务并交给 worker
-> 页面轮询任务状态
-> 用户刷新页面后仍能看到最近任务
-> 任务完成后展示成片、封面、字幕或失败原因

### 阶段六：内容沉淀与后续复用

系统把咨询、图文、视频脚本、视频任务统一沉淀
-> 用户在我的内容查看历史
-> 用户可重新进入相关工作台继续编辑
-> 后续 Agent 可读取这些内容作为历史上下文

## 6. 用户故事

### US-01 图文生成后支持 AI 修改

作为商家运营人员，我希望图文生成后可以直接告诉 AI “哪里要改”，而不是每次只能重新生成整篇内容。

当前问题：

- 图文工作台已经能生成草稿和多个标题方案。
- 但用户生成后缺少自然语言修改入口。
- “重新生成”容易丢掉用户已经认可的部分。

需求描述：

- 图文工作台在生成结果后，必须提供 `AI 修改` 入口。
- 用户可以选择一个已生成版本作为修改对象。
- 用户输入修改指令，例如：
  - 更像小红书口吻。
  - CTA 轻一点。
  - 加强本地感。
  - 不要制造焦虑。
  - 保留标题，重写正文。
- 系统根据原版本、修改指令、商家资料、咨询策略和素材参考生成新版本。
- 新版本必须保存为新的 `ContentVariant`，不能覆盖原版本。
- 用户可以在版本之间切换、对比、继续修改。

建议状态：

```text
generated
-> ai_editing
-> edited_variant_saved
-> selected
```

验收标准：

- 已生成图文草稿后，页面出现 AI 修改入口。
- 用户输入修改要求后，系统生成一个新版本。
- 原版本仍保留。
- 新版本能在内容中心和我的内容中回显。
- 修改失败时提示明确原因，不丢失用户输入。

优先级：P0

### US-02 视频工作台刷新后恢复任务状态

作为商家运营人员，我希望创建视频任务后，即使刷新页面，也能看到刚才创建的任务状态和结果。

当前问题：

- 视频任务可以创建。
- Worker 可以处理任务。
- 历史页能看到任务结果。
- 但视频工作台刷新后不一定恢复当前任务展示。

需求描述：

- 视频工作台加载时，如果存在当前咨询会话或当前视频脚本关联的最新任务，应自动拉取并展示。
- 如果 URL 中有 `sessionId`、`draftId`、`variantId` 或 `jobId`，优先使用更精确的上下文恢复。
- 如果没有明确 ID，则展示最近一个与当前商家相关且未归档的视频任务摘要。
- 页面应继续轮询 `pending / queued / preparing / running` 状态。
- 成功后展示成片预览、封面、字幕摘要。
- 失败后展示失败原因和重试入口。

验收标准：

- 创建视频任务后刷新页面，仍能看到该任务。
- 任务完成后刷新页面，仍能看到成功状态和结果资产。
- 任务失败后刷新页面，仍能看到失败原因。
- 不再只依赖前端临时 state。

优先级：P0

### US-03 视频链路从 skeleton 保底轨升级

作为商家运营人员，我希望视频任务不只是生成一条保底 MP4，而是逐步接近真实可用的视频生产链路。

当前问题：

- 当前 worker 可产出真实 MP4。
- 但 `openstoryline-engine` 仍是 skeleton 保底轨。
- 当前视频结果更适合作为 smoke 和 demo，不足以代表真实剪辑质量。

需求描述：

- 保留 skeleton 作为兜底模式，但需要新增真实执行模式。
- 视频任务应区分：
  - `script_only_fallback`
  - `material_based_render`
  - `openstoryline_render`
- 如果用户没有素材，允许走脚本保底轨，但页面要明确说明这是保底生成。
- 如果用户提供素材，应优先进入素材驱动的视频执行链路。
- 任务结果需要记录引擎类型、输入素材数量、输出资产、失败阶段。

验收标准：

- 视频任务详情能看到当前使用的执行模式。
- 有素材任务与无素材任务在页面上有不同提示。
- Worker 成功结果能区分 skeleton 和真实执行引擎。
- 失败日志能定位到素材下载、脚本解析、渲染、上传、回写中的具体阶段。

优先级：P1

### US-04 未登录状态提供友好入口

作为新用户或验收人员，我希望打开商家端页面时，如果没有登录，系统告诉我应该登录、注册或使用邀请码，而不是显示技术错误。

当前问题：

- 未登录时部分页面会显示类似 `Please sign in first.` 或按钮不可用。
- 用户容易误以为页面卡住。

需求描述：

- 商家端所有需要登录的页面必须统一处理未登录状态。
- 页面应显示明确入口：
  - 登录。
  - 邀请码注册。
  - 返回首页或联系管理员。
- 咨询页的 `新开对话`、`发送消息` 等按钮在未登录时不应静默 disabled。
- API 错误需要转成用户可理解的状态。

验收标准：

- 未登录访问 `/dashboard` 时，能看到清晰的登录或注册引导。
- 未登录访问图文、视频、素材中心、我的内容、商家设置时，展示一致的引导状态。
- 不出现裸露技术错误。
- 用户知道下一步该做什么。

优先级：P0

### US-05 知识库扩展为平台知识与商家资料双层

作为商家和平台管理员，我希望知识库既能承载平台方法论，也能承载某个商家自己的资料，让 Agent 和内容生成更贴合真实业务。

当前问题：

- 当前已经支持平台级文本知识上传、切块、embedding 和检索。
- 暂不支持 PDF / Word。
- 暂不支持多文件批量上传。
- 商家级知识还没有形成完整产品入口。

需求描述：

- 知识库需要明确分成两层：
  - 平台知识：由平台管理员维护，适用于所有商家。
  - 商家资料：由商家或运营人员维护，只服务当前商家。
- 商家资料可包括：
  - 门店介绍。
  - 项目介绍。
  - 老板或主理人经历。
  - 活动说明。
  - 常见问答。
  - 成交异议。
  - 真实案例。
- 支持文本粘贴和文本类文件继续保留。
- PDF / Word、多文件上传、异步入库进入 V2.1 后续拆分项。
- 所有知识入库必须保留状态、失败原因、重试入口。

验收标准：

- 平台知识和商家资料在产品概念上区分清楚。
- 咨询 Agent 检索时能同时使用平台知识和当前商家资料。
- 商家资料不会泄露给其他商家。
- 入库失败可重试。
- 非文本文件如果暂不支持，要有明确提示。

优先级：P1

### US-06 Agent 从固定工具链升级为业务 planner

作为商家，我希望 Agent 不只是每轮固定执行同一串工具，而是能根据当前问题判断该做什么。

当前问题：

- 当前 Agent 已经不是简单 mock。
- 它具备 system prompt、工具开关、RAG、事件记录和有界工具链。
- 但工具顺序仍是后端固定 planner，不是真正由模型根据上下文选择工具。

需求描述：

- 保留当前固定工具链作为兜底。
- 新增业务 planner 模式：
  - 模型根据当前会话、商家资料、历史内容、知识命中判断需要哪些工具。
  - 输出结构化 tool-call plan。
  - 后端做 schema 校验。
  - 校验失败时尝试 repair。
  - 超过预算或失败时回退到固定工具链。
- 工具仍必须是受控业务工具，不开放文件、shell、浏览器、外部任意 MCP。
- 工具执行结果继续写入可见卡片和事件表。

验收标准：

- 后台能配置 planner 模式开关。
- planner 模式下，Agent 不必每轮执行所有工具。
- 工具调用有预算限制。
- planner 失败时系统能降级，不影响用户收到回复。
- 事件记录能区分 planner 选择、工具执行、降级原因。

优先级：P1

### US-07 Agent 运行中心跳与插话中断

作为商家，我希望 Agent 长时间思考或执行工具时，页面能告诉我它正在做什么；如果我临时补充一句，也能被系统接住。

当前问题：

- 当前咨询接口更接近同步请求。
- 长任务期间缺少持续心跳。
- 用户运行中插话还没有清晰机制。

需求描述：

- 新增 Agent run 概念，记录：
  - queued
  - running
  - waiting_for_tool
  - waiting_for_user
  - completed
  - failed
  - interrupted
  - cancelled
- 后端定期写入 heartbeat。
- 前端显示当前步骤，例如：
  - 正在读取商家资料。
  - 正在检索知识库。
  - 正在生成内容策略。
  - 正在生成回复。
- 插话分两种模式：
  - `排队补充`：当前 run 完成后进入下一轮。
  - `引导中断`：在安全点把用户补充纳入当前判断。

验收标准：

- 长时间生成时，用户能看到当前执行步骤。
- 超过心跳阈值时，页面提示可继续等待或取消。
- 用户运行中补充消息不会丢失。
- 插话是否立即生效，需要有明确提示。

优先级：P2

### US-08 效果回流记录为后续版本

作为平台经营者，我希望未来能知道哪些内容有效，但这不是 V2.1 的主交付。

需求描述：

- 先记录效果回流方向，不进入 V2.1 必做。
- 后续可考虑记录：
  - 内容是否被使用。
  - 商家是否采纳 AI 修改版本。
  - 内容是否被复制、下载或外部发布。
  - 人工录入曝光、互动、咨询量。
  - 每条内容对应的策略类型和素材来源。
- 因为当前不做账号发布，所以效果回流不能依赖平台发布 API。
- 第一版效果回流更适合从“人工记录 + 内容使用行为”开始。

建议版本：

- `V2.2`：轻量效果记录与内容使用行为。
- `V2.3`：经营复盘与策略建议。

优先级：P3

## 7. 优先级汇总

| 优先级 | 需求 | 说明 |
|---|---|---|
| P0 | 图文生成后 AI 修改 | 直接影响图文工作台可用性 |
| P0 | 视频任务刷新恢复 | 当前已知体验断点 |
| P0 | 未登录友好入口 | 影响验收和新用户进入 |
| P1 | 视频真实执行模式 | 当前 skeleton 只能作为保底 |
| P1 | 平台知识与商家资料双层知识库 | 提升咨询与生成质量 |
| P1 | Agent 业务 planner | 提升 Agent 判断能力，但需保留兜底 |
| P2 | Agent 心跳与插话中断 | 需要规划，但优先级靠后 |
| P3 | 效果回流 | 记录方向，后续版本进入 |

## 8. 与现有模块的关系

### 咨询诊断

继续作为主入口，不被素材中心、对标导入或工作台替代。

### 素材中心

承接对标素材和用户上传素材。它是主链路的补充输入，不是主链路本身。

### 图文工作台

从“生成草稿”升级为“生成、选择、AI 修改、多版本沉淀”。

### 视频工作台

从“脚本加任务创建”升级为“脚本、任务恢复、执行模式可见、结果回看”。

### 我的内容

继续作为历史沉淀入口。后续效果回流可以从这里切入，但不进入 V2.1 必做。

### 商家设置

继续作为商家长期上下文入口。商家资料型知识库可以从这里或独立入口进入，后续需要再定页面形态。

## 9. 数据对象影响草案

本节只记录方向，不作为最终数据库设计。

可能需要新增或扩展：

- `content_variants`
  - 增加 AI 修改来源、parent variant、edit instruction。
- `video_edit_jobs`
  - 增加恢复查询所需的 session / draft / variant 关联。
  - 增加 render mode、engine type、stage failure 信息。
- `knowledge_documents`
  - 明确 platform scope 与 merchant scope。
  - 增加文件解析状态与失败原因。
- `agent_runs`
  - 记录 Agent 单轮运行状态、心跳、当前步骤。
- `agent_run_events`
  - 记录 planner、工具、模型、插话、取消等事件。
- `agent_pending_inputs`
  - 记录运行中补充消息。
- 后续效果回流候选：
  - `content_usage_events`
  - `content_performance_notes`
  - `strategy_review_snapshots`

## 10. 待确认问题

这些问题不阻塞先记录 PRD，但进入实现前需要确认：

1. 图文 AI 修改是否允许一次修改多个版本，还是只允许修改当前选中版本。
2. 图文 AI 修改结果是否自动设为选中版本。
3. 商家资料型知识库入口放在 `商家设置` 里，还是放在 `素材中心` 里。
4. 视频真实执行模式优先接现有 OpenStoryline，还是先做更稳的素材拼接保底升级版。
5. Agent planner 是否先只在 staging 打开，还是直接进入主流程。
6. 效果回流的下一版是否命名为 `V2.2`。

## 11. 当前结论

V2.1 的主线不是“新增更多入口”，而是补齐咨询驱动工作流里的关键断点。

最小成立标准：

```text
咨询诊断能给出策略
-> 素材中心能补充对标或自有素材
-> 图文能生成并 AI 修改
-> 视频能生成脚本、创建任务、刷新后恢复状态
-> 未登录用户知道如何进入系统
-> 平台知识与商家资料开始形成双层上下文
```

账号发布、矩阵分发不进入本版本。效果回流记录为后续版本方向。
