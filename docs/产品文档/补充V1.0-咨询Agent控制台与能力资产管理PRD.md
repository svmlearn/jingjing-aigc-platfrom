# 补充 V1.0 咨询 Agent 控制台与能力资产管理 PRD

## 1. 文档定位

这份文档是 `V2.2-咨询Agent控制台与能力资产管理PRD` 的前置补充。

它不重新展开 V2.2 的 Agent、Skill、Knowledge、测试台、快照等详细需求，只补充一个问题：

> 咨询 Agent 控制台不是孤立页面，它应该长在已有的平台管理台框架里。

因此，本文件用于说明平台管理台已有的基础模块、导航结构和本次 Agent 控制台应该接入的位置。

给设计 AI 或开发 AI 时，建议一起提供：

1. `docs/designs/DESIGN.md`
2. `docs/产品文档/V2.2-咨询Agent控制台与能力资产管理PRD.md`
3. 本文件

## 2. 背景

平台目前已经存在平台管理台的基础框架，用于平台内部管理。

已有平台管理台不是专门为 Agent 配置而建的，它原本承担这些职责：

- 平台总览
- 邀请码管理
- 商户管理
- 平台知识库管理
- 系统配置
- 平台管理员登录 / 访问保护

V2.2 要新增的「咨询 Agent 控制台与能力资产管理」应作为平台管理台里的新能力域接入，而不是替代原来的平台管理台。

## 3. 产品目标

本补充 PRD 的目标是把平台管理台的底层框架补充清楚，使后续设计和开发不会漏掉已有后台能力。

具体目标：

1. 明确平台管理台已有一级模块。
2. 明确 V2.2 新增 Agent 能力域的接入位置。
3. 明确哪些能力保留在系统配置，哪些能力迁移到 Agent 配置。
4. 给零上下文设计 AI 一个最小可理解的后台框架。

## 4. 非目标

本补充 PRD 不做：

- 不重新定义 V2.2 Agent 控制台详细需求。
- 不展开完整管理员 RBAC。
- 不展开完整会员支付和积分扣费系统。
- 不重新设计商家端工作台。
- 不替代 `V2.2-咨询Agent控制台与能力资产管理PRD`。

## 5. 平台管理台基础信息架构

平台管理台推荐保持以下一级导航：

```text
平台管理台
├── 总览
├── 邀请码管理
├── 商户管理
├── 知识管理
├── Agent 配置
├── 技能管理
├── Agent 调试
├── 系统配置
└── 管理员管理（后置）
```

说明：

- `总览 / 邀请码管理 / 商户管理 / 知识管理 / 系统配置` 是已有后台框架的基础模块。
- `Agent 配置 / 技能管理 / Agent 调试` 是 V2.2 新增的 Agent 能力资产模块。
- `管理员管理` 可以保留入口或占位，但不是本期重点。

## 6. 既有模块说明

### 6.1 总览

用于平台管理员快速查看平台运行状态。

页面应包含：

- 核心业务摘要。
- 管理员操作日志。
- 系统告警。

注意：

- 部分指标可以先是占位或演示态。
- 不要因为 V2.2 新增 Agent 控制台，就删除总览入口。

### 6.2 邀请码管理

用于控制新商家进入平台。

页面应包含：

- 邀请码列表。
- 新建邀请码。
- 邀请码状态。
- 最大使用次数。
- 已使用次数。
- 过期时间。
- 渠道标签 / 备注。

### 6.3 商户管理

用于平台侧查看和治理商户。

页面应包含：

- 商户列表。
- 商户详情。
- 商户状态。
- 会员档位。
- owner 信息。
- 基础使用情况。

商户状态至少包括：

- `active`：正常可用。
- `disabled`：平台临时禁用。
- `archived`：归档。

会员档位当前基础为：

- `free`
- `plus`
- `pro`

后续可扩展：

- `max`

### 6.4 知识管理

已有知识库管理用于维护平台级知识。

V2.2 后，知识管理需要从“单篇知识文档”升级为：

```text
知识管理
├── 知识集
└── 知识文档
```

核心规则：

- 上传知识时必须选择知识集。
- Agent 挂载知识集，不直接挂载单篇文档。
- 一个 Agent 可以挂载多个知识集。
- 多个知识集不区分优先级，合并检索。
- 知识集关闭时，依赖它的 Skill 仍允许启用，但后台和测试台要提示依赖未满足。

### 6.5 系统配置

系统配置保留平台级参数，不再承担 Agent 详细配置职责。

应保留：

- LLM runtime。
- 导入 runtime。
- 会员与积分默认规则。
- 平台级安全和全局开关。

应迁移到 Agent 配置：

- Agent system prompt。
- Agent 挂载的 Skill。
- Agent 挂载的 Knowledge Set。
- Agent 草稿 / 发布 / 快照。
- Agent 线上绑定。

## 7. V2.2 新增模块接入方式

### 7.1 Agent 配置

Agent 配置是新增一级模块。

它负责：

- Agent 列表。
- Agent 基础信息。
- Agent system prompt。
- 挂载 Skill。
- 挂载 Knowledge Set。
- Agent 状态。
- Agent 复制。
- Agent 发布与配置快照。
- 当前线上咨询 Agent 绑定。

关键原则：

- System Prompt 属于 Agent 容器，不是独立脚本库。
- 复制 Agent 时只复制配置，不复制启用状态和线上绑定。
- 新复制的 Agent 默认为草稿或禁用。

### 7.2 技能管理

技能管理是新增一级模块。

Skill 是管理员配置的能力说明 / 行为策略 / 场景方法论，本质是可控 prompt 片段。

技能管理负责：

- 创建 Skill。
- 编辑 Skill 名称、描述、正文。
- 启用 / 禁用 Skill。
- 可选绑定工具。

关键原则：

- Skill ID 是系统内部字段，不需要在界面显著暴露。
- tools 是代码层能力，不开放给管理员自由创建。
- 不做 Skill 冲突检测。

### 7.3 Agent 调试

Agent 调试是新增一级模块。

它负责：

- 选择任意 Agent 进行测试。
- 输入模拟用户问题。
- 查看 Agent 回复。
- 查看工具调用、知识检索命中和依赖缺失提示。
- 保存测试记录。

关键原则：

- 测试台不写入真实咨询历史。
- 测试台不消耗商家真实 LLM 配额。
- 测试台可以用于验证新 Agent / 新 Skill / 新 Knowledge Set。

## 8. 页面关系草图

```text
┌──────────────────────────────────────────────────────────────┐
│ 平台管理台                                                    │
├──────────────┬───────────────────────────────────────────────┤
│ 总览         │ 当前模块内容                                   │
│ 邀请码管理   │                                               │
│ 商户管理     │ 例如：Agent 配置 / 技能管理 / 知识管理 / 调试台 │
│ 知识管理     │                                               │
│ Agent 配置   │                                               │
│ 技能管理     │                                               │
│ Agent 调试   │                                               │
│ 系统配置     │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

## 9. 对设计稿的要求

设计平台管理台时，不要只画 Agent 新功能。

至少要体现：

- 平台管理台整体导航。
- 原有后台模块仍然存在。
- V2.2 Agent 能力域作为新模块接入。
- 知识管理从文档管理升级为知识集管理。
- 系统配置和 Agent 配置职责分离。

视觉规范以 `docs/designs/DESIGN.md` 为准。

## 10. 与 V2.2 PRD 的关系

本文件解决“Agent 控制台长在哪里”的问题。

`V2.2-咨询Agent控制台与能力资产管理PRD` 解决“Agent 控制台具体怎么用、怎么发布、怎么测试、怎么追溯”的问题。

两份文档应一起阅读：

- 先读本文件，理解平台管理台基础框架。
- 再读 V2.2 PRD，理解 Agent 能力资产的详细需求。
