## 当前硬口径

- Supabase Cloud 是过往架构，当前正式运行和新开发不再使用 Supabase。
- 当前数据库主线是自建 / 国内 PostgreSQL：app 使用 `APP_DATABASE_URL` / `DATABASE_URL`，worker 使用 `WORKER_DATABASE_URL`。
- 当前部署主线是国内云服务器自托管 Next.js / Node API、content-generation worker、video-worker、OpenStoryline / FireRed。
- 当前对象存储新写入默认使用 `aliyun_oss`。`tencent_cos` / COS 和 `supabase_storage` 只作为旧数据、旧文档、兼容读取或回滚参考。
- `progress/` 和 `handoff/` 默认是过程记录，表示“当时发生了什么”，不自动代表“现在应该怎么做”。

## 判断优先级

当文档之间发生冲突时，按以下顺序取信：

1. `docs/README.md`
2. `app/db/README.md`
3. 2026-05-20 之后的 release / merge / verification progress
4. 当前架构规范
5. 早期 handoff / progress / 探索稿

如果搜索结果来自 2026-05-20 之前，并且出现 Supabase、Vercel、staging COS、新加坡服务器等关键词，默认先当作历史资料处理。

## 搜索命中后的处理规则

- 如果旧文档说“当前 Supabase 状态”，只理解为该文件写作日期当时的当前状态。
- 如果旧文档要求配置 `NEXT_PUBLIC_SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_DB_URL`，不要直接套用到当前主线；当前优先检查 `APP_DATABASE_URL`、`DATABASE_URL`、`WORKER_DATABASE_URL`。
- 如果旧文档要求配置 `COS_SECRET_ID` / `COS_BUCKET` 作为新上传默认，不要直接套用到当前主线；当前新写入优先检查 `STORAGE_PROVIDER=aliyun_oss` 和 `ALIYUN_OSS_*`。
- 如果旧文档提到 Vercel 限制、Vercel env、Vercel deploy，不要直接套用到当前国内服务器 release。
- 如果需要保留历史事实，不重命名旧文件；只在关键旧文档顶部加状态 banner，或在本索引中标明历史层级。
