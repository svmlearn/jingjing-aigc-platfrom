# Apify 最小可验证调用清单

## 1. 这份文档解决什么问题

当前我们需要确认的不是：

- `Apify` 能不能跑爬虫

而是：

- 它能不能让我们在 `V0.1-A` 里，以 API 方式接住：
  - `detail`
  - `creator`
  - `comments`

这份文档只回答一个很实际的问题：

> 能不能把帖子链接或博主主页链接直接传给 `Apify`，然后拿回结构化结果？

结论先写在前面：

- **可以**
- 但不是“通用接口天然就懂小红书链接”
- 而是“通用运行接口 + 某个支持该输入 schema 的 actor”

---

## 2. 先把接口关系讲清楚

`Apify` 有两层：

1. 平台通用运行接口
2. 具体 actor 的输入 schema

### 2.1 平台通用运行接口

`Apify` 官方 API 文档说明：

- 运行 actor 的通用接口是  
  `POST https://api.apify.com/v2/acts/[actor_id]/runs`
- 也支持同步返回结果的接口  
  `POST https://api.apify.com/v2/acts/[actor_id]/run-sync-get-dataset-items`

这层接口只负责：

- 启动某个 actor
- 接收输入参数
- 返回 run 信息或 dataset items

它**不负责**理解“小红书帖子链接”本身。

### 2.2 具体 actor 的输入 schema

真正决定“能不能直接丢链接进去抓”的，是 actor 自己定义的输入参数。

比如某个 actor 如果支持：

- `postUrls`
- `profileUrls`
- `mode`

那我们就可以把帖子链接或主页链接作为 JSON body 传进去。

所以准确说法应该是：

- `Apify` 的通用运行接口可以承接请求
- 具体抓什么、怎么抓，看 actor 的输入 schema

---

## 3. 当前最值得验证的调用模式

### 3.1 模式 A：异步运行

适合：

- 长任务
- 批量任务
- 需要 webhook / 轮询

调用方式：

```bash
curl -X POST "https://api.apify.com/v2/acts/ACTOR_ID/runs?token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ ...input... }'
```

返回值重点看：

- `runId`
- `defaultDatasetId`

后续流程：

1. 调用 run 接口启动任务
2. 轮询 run 状态
3. 用 `defaultDatasetId` 拉结果

### 3.2 模式 B：同步运行并直接拿结果

适合：

- 单条链接验证
- 小批量验证
- 后台里“点一下立即试跑”的场景

调用方式：

```bash
curl -X POST "https://api.apify.com/v2/acts/ACTOR_ID/run-sync-get-dataset-items?token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ ...input... }'
```

注意：

- `Apify` 官方文档写明，同步方式会最多等待 `300 seconds`
- 超过这个时间，更适合切回异步运行

## 4. 小红书三类能力的最小验证方案

## 4.1 `detail`

目标：

- 输入单条帖子链接
- 返回正文、标题、作者、互动字段等

当前可验证 actor 方案：

- `huggable_quote/xiaohongshu-all-in-one-scraper`
- `easyapi/all-in-one-rednote-xiaohongshu-scraper`

推荐先用的最小 payload：

```json
{
  "mode": "postDetail",
  "postUrls": [
    "https://www.xiaohongshu.com/explore/670a46a50000000024017580"
  ]
}
```

第二轮实测后的补充：

- 小红书 `detail` 应优先传页面自然生成的完整链接
- 也就是尽量保留 `xsec_token` / `xsec_source` 等参数
- 裸 `note_id` 链接可能导致 actor run 成功但业务字段很空

如果用 `huggable_quote` 这个 all-in-one actor，也支持带：

```json
{
  "sessionCookie": "a1=...; web_session=..."
}
```

最小同步调用示例：

```bash
curl -X POST "https://api.apify.com/v2/acts/huggable_quote~xiaohongshu-all-in-one-scraper/run-sync-get-dataset-items?token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "postDetail",
    "postUrls": [
      "https://www.xiaohongshu.com/explore/670a46a50000000024017580"
    ]
  }'
```

预期最少验收字段：

- `postUrl`
- `id`
- `title`
- `description` 或 `content`
- `user`
- 互动字段，如点赞/评论/收藏/分享中的一部分

---

## 4.2 `creator`

目标：

- 输入博主主页链接
- 返回主页信息或帖子列表

这里建议拆成两类验证：

1. `profile`
2. `userPosts`

因为业务上我们真正要的是：

- 先拿到博主主页基础信息
- 再拿到该博主帖子列表

### 方案 1：主页资料

可验证 actor：

- `easyapi/rednote-xiaohongshu-profile-scraper`
- `huggable_quote/xiaohongshu-all-in-one-scraper` 的 `profile` 模式

最小 payload：

```json
{
  "profileUrls": [
    "https://www.xiaohongshu.com/user/profile/6784ba7f00000000080191fb"
  ]
}
```

### 方案 2：博主帖子列表

可验证 actor：

- `easyapi/rednote-xiaohongshu-user-posts-scraper`
- `huggable_quote/xiaohongshu-all-in-one-scraper` 的 `userPosts` 模式

最小 payload：

```json
{
  "profileUrls": [
    "https://www.xiaohongshu.com/user/profile/639946a0000000002702b173"
  ],
  "maxItems": 20
}
```

最小同步调用示例：

```bash
curl -X POST "https://api.apify.com/v2/acts/easyapi~rednote-xiaohongshu-user-posts-scraper/run-sync-get-dataset-items?token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "profileUrls": [
      "https://www.xiaohongshu.com/user/profile/639946a0000000002702b173"
    ],
    "maxItems": 20
  }'
```

预期最少验收字段：

- `profileUrl`
- 用户基本信息，如 `nickname` / `userId`
- 帖子列表
- 帖子标题或封面信息
- 至少一种互动字段

---

## 4.3 `comments`

目标：

- 输入单条帖子链接
- 返回评论和至少一层回复

可验证 actor：

- `easyapi/rednote-xiaohongshu-comments-scraper`
- `huggable_quote/xiaohongshu-all-in-one-scraper` 的 `comments` 模式
- `easyapi/all-in-one-rednote-xiaohongshu-scraper` 的 `comment` 模式

最小 payload：

```json
{
  "postUrls": [
    "https://www.xiaohongshu.com/explore/6764f52c000000000900c655?xsec_token=ABQuGdhHV4zPI_3lR2iWdS9VxX_4RmI3bUSh394ppVitk=&xsec_source=pc_search&source=web_explore_feed"
  ],
  "maxItems": 30
}
```

最小同步调用示例：

```bash
curl -X POST "https://api.apify.com/v2/acts/easyapi~rednote-xiaohongshu-comments-scraper/run-sync-get-dataset-items?token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "postUrls": [
      "https://www.xiaohongshu.com/explore/6764f52c000000000900c655?xsec_token=ABQuGdhHV4zPI_3lR2iWdS9VxX_4RmI3bUSh394ppVitk=&xsec_source=pc_search&source=web_explore_feed"
    ],
    "maxItems": 30
  }'
```

第二轮实测后的推荐：

- 当前更推荐先测：
  - `easyapi/all-in-one-rednote-xiaohongshu-scraper`
  - `mode = comment`
- `huggable_quote/xiaohongshu-all-in-one-scraper` 的 `comments` 模式本轮返回了空 dataset
- `easyapi/rednote-xiaohongshu-comments-scraper` 对 `maxItems` 有最低限制，本轮也出现过空结果
- 所以小红书评论不要只按 actor 名字判断，要按实测结果选 actor

预期最少验收字段：

- `postUrl`
- 评论正文
- 评论用户信息
- 时间字段
- 至少一层 `sub_comments` 或回复结构

## 5. 当前最值得记住的 3 个现实约束

### 5.1 这个接口不是“小红书专用 API”

它是：

- `Apify` 平台的通用 actor 运行接口

所以不能理解成：

- 只要给 `run actor` 接口丢一个链接，就一定能抓

真正生效的是：

- 你选中的 actor 是否支持该链接类型和对应字段

### 5.2 同步模式更适合 PoC，不适合所有正式任务

因为官方文档明确写了：

- 同步接口最多等 `300 seconds`

所以：

- 单条链接验证很适合
- 批量导入、全量导入、失败重试，最终还是更适合异步模式

### 5.3 中文社媒 actor 很多是 `Maintained by Community`

这意味着：

- `Apify` 平台本身是成熟的
- 但小红书 / 抖音 actor 的稳定性，仍需要逐个验证

当前我们不能直接把它当成“已确认稳定主方案”。

---

## 6. 当前对我们项目的实际判断

如果只看“能不能先接 API，不先自建服务器”，答案是：

- **可以尝试，而且值得先试**

如果只看“能不能直接传帖子链接 / 主页链接进去”，答案也是：

- **可以，前提是选对 actor**

但如果要把它升级成：

- `V0.1-A` 确认主方案

还差最后一步：

- 真实试跑 `detail / creator / comments`

也就是要验证：

1. 成功率
2. 返回字段是否够用
3. 评论是否完整
4. 是否依赖 cookie
5. 成本是否可接受

---

## 7. 我给当前项目的操作建议

当前最务实的试跑顺序：

1. 先用同步接口各测 1 条
2. 通过后再切异步接口测批量
3. 小红书优先验证：
   - `postDetail`
   - `userPosts`
   - `comments`
4. 如果评论或主页稳定性差，再对比：
   - `Bright Data`
   - 本地浏览器桥接
   - 自建 Worker
