# 2026-04-28 热点抓取与咨询 Agent 优化待验证事项

## 1. 文档定位

这是一份后续任务记录和探索验证清单，不是正式 PRD。

当前判断：

1. 先完成 V2.2 与 M 同学开发成果的合并验收。

### 3.1 平台覆盖

需要实测确认：

| 平台 | 单帖详情 | 评论 | 博主主页 | 博主全部内容 | 搜索 / 热点 | 视频内容 | 备注 |
|---|---|---|---|---|---|---|---|
| 小红书 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 当前重点平台 |
| 抖音 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 当前重点平台 |
| TikTok | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 如果 TikHub 支持，可列入备选 |
| 其他平台 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 以 Dashboard/API 实际列表为准 |

### 3.2 单个帖子详情字段

输入单条帖子链接，至少要验证能否拿到：

- 平台与原始链接。
- 平台侧帖子 ID 或稳定唯一标识。
- 作者 ID、作者昵称、主页链接、头像。
- 标题、正文 / 文案、话题标签。
- 发布时间。
- 图片列表、封面图、视频地址。
- 点赞、收藏、评论、转发等互动指标。
- 评论列表、评论作者、评论正文、点赞数、回复结构。
- 原始返回包，便于放入 `trace_payload` 排查字段变化。

失败判定：

- 只有空 metadata，没有正文 / 作者 / 媒体。
- 同一类链接字段结构频繁变化，无法稳定映射。
- 视频或图片只有不可访问的短期链接，且无法刷新。

### 3.3 博主内容追踪

需要验证：

- 是否支持输入博主主页 URL 或作者 ID。
- 是否能拿到主页资料：昵称、简介、粉丝、获赞、作品数等。
- 是否能分页抓取作品列表。
- 是否支持抓取历史全部内容，还是只能抓近期内容。
- 是否提供 cursor / page token / since 参数，方便增量同步。
- 是否能稳定去重。
- 是否有频率限制、账号限制、cookie / token 依赖。

### 3.4 视频能力

需要验证：

- 是否能识别帖子类型：图文 / 视频 / 混合。
- 是否返回视频播放地址、封面、时长、清晰度、文件大小。
- 是否返回字幕、逐字稿或 ASR 结果。
- 如果不返回逐字稿，是否至少能拿到可下载视频，用后续 ASR 服务转写。
- 视频地址是否可长期访问；如有过期时间，需要记录刷新策略。

### 3.5 热点 / 搜索能力

需要验证：

- 是否支持关键词搜索。
- 是否支持平台热榜 / 趋势榜 / 话题榜。
- 是否支持按行业、地域、发布时间、互动量排序。
- 是否能拿到足够字段让我们判断“爆款”：互动量、评论量、发布时间、作者体量。
- 是否能批量拉取结果并稳定分页。

### 3.6 稳定性与成本

同一批样本至少连续测试 3 轮，记录：

- 成功率。
- 字段完整度。
- 返回结构稳定性。
- 响应耗时。
- 失败错误码。
- 是否强依赖 cookie / session。
- 额度、并发、单价和套餐限制。

建议每个平台准备：

- 3 条普通单帖链接。
- 2 条评论较多的帖子链接。
- 2 个博主主页链接。
- 1 组关键词或热点榜样本。

## 4. 落库与复利工程设想

### 4.1 当前已有承接点

当前项目已有这些数据承接点：

- `import_jobs`：记录一次导入 / 抓取任务。
- `source_items`：记录帖子、素材、原始内容。
- `imported_comments`：记录评论与回复。
- `material_workbench_references`：记录素材中心送入图文 / 视频工作台的引用关系。
- `content_drafts`：记录图文 / 视频生成产物及输入快照。
- `knowledge_documents` / `knowledge_chunks`：承接 RAG 知识文档和切块。
- `agent_runtime_snapshots`：预留 Agent 运行快照。

### 4.2 用户输入链接后的理想链路

```text
用户输入帖子链接
  -> 创建 import_job
  -> 调用抓取 API
  -> upsert source_items
  -> 写入 imported_comments
  -> 媒体文件按需入 COS / asset_objects
  -> 自动打标签：平台、行业、内容类型、互动指标、来源
  -> 可在素材中心检索
  -> 图文 / 视频工作台引用并生成新内容
  -> 新内容产物继续写回 content_drafts / 资产表
```

关键原则：

- 不只把原文拼进 prompt，要正式落库。
- 原始 payload 保留在 `trace_payload`，方便供应商字段变化时排查。
- 平台 ID 和 URL 都要参与去重。
- 评论和互动数据要保留抓取时间，避免把旧热度当实时热度。
- 图文 / 视频工作台引用素材时，应写引用关系，方便复盘“这篇内容参考了哪些爆款”。

### 4.3 后续可能需要补的能力

- 内容资产标签体系：行业、门店类型、选题、内容结构、爆点、拍摄手法。
- 热度快照表：记录同一帖子多次抓取的点赞 / 评论 / 收藏变化。
- 博主追踪任务：定时抓取指定博主新内容。
- Agent 读资产库 tool：按行业 / 选题 / 热度 / 平台检索参考内容。
- 工作台产物读取 tool：让咨询 Agent 知道已经生成过什么图文和视频，避免重复建议。

## 5. 咨询 Agent RAG 方法论素材

### 5.1 待收集主题

- 如何选题。
- 如何日常积累素材。
- 九宫格法如何结合本地生活商家场景。
- 短视频脚本结构：开头钩子、冲突、展示、行动号召。
- 拍摄方法：分镜、景别、B-roll、口播、探店、门店服务过程。
- 爆款拆解：标题、封面、评论区需求、用户痛点。
- 账号定位：人设、服务半径、目标客户、转化路径。
- 发布复盘：数据看板、评论提炼、下次选题迭代。

### 5.2 入库原则

- 优先沉淀“方法论摘要 + 来源链接 + 适用场景”，避免把外部长内容原文整篇搬进知识库。
- 切块时按方法单元拆分，而不是按固定长度硬切。
- 每个 chunk 尽量带元数据：
  - `method`
  - `scenario`
  - `platform`
  - `industry`
  - `content_type`
  - `source_url`
  - `confidence`
- 适合平台全局复用的方法进入平台知识集。
- 行业强相关内容进入行业知识集。
- 未验证的方法论先放探索，不直接挂线上 Agent。

## 6. 咨询 Agent 后续优化方向

### 6.1 Skills

候选 skill：

- 选题诊断 skill。
- 本地生活九宫格选题 skill。
- 评论区需求提炼 skill。
- 爆款拆解 skill。
- 短视频拍摄脚本 skill。
- 图文种草文案 skill。
- 一周内容日历规划 skill。
- 已发布 / 已生成内容复盘 skill。

### 6.2 Tools

候选 tool：

- `read_merchant_profile`：读取商家 / 门店资料。
- `retrieve_knowledge_base`：检索方法论和平台知识。
- `read_source_items`：读取已导入帖子 / 爆款内容 / 评论。
- `read_content_calendar`：读取内容日历。
- `read_article_drafts`：读取图文工作台产物。
- `read_video_scripts`：读取视频工作台产物。
- `update_strategy_snapshot`：更新定位、客群、卖点、内容策略。
- `generate_article_brief` / `generate_video_brief`：生成工作台输入。

### 6.3 Loop 与上下文工程

后续目标不是让模型自由乱调工具，而是做受控业务 loop：

```text
理解用户输入
  -> 判断是否需要追问
  -> 检索商家资料 / 方法论 / 内容资产
  -> 更新策略快照
  -> 输出一个明确下一步
  -> 必要时生成图文 / 视频 brief
  -> 记录运行快照
```

需要设计：

- 每轮最多工具调用次数。
- 工具失败后的降级回答。
- 何时追问、何时直接给方案。
- 会话上下文压缩策略。
- 长期商家记忆与短期会话记忆边界。
- Agent 调试台如何展示本轮加载了哪些 prompt、skill、knowledge、tools 和资产。
