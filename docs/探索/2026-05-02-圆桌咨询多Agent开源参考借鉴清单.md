## 2. 产品结论

圆桌咨询第一版不采用自由 swarm，也不做多个 Agent 互相无限讨论。

第一版建议采用：

```text
主持人编排
-> 资产盘点官
-> 技能洞察官
-> 营销策略官
-> 主持人汇总
```

核心机制是：

```text
固定顺序专家链
+ 每阶段多轮问诊
+ 每阶段结构化产物
+ 下阶段只读取必要摘要
+ 最终回写现有 strategySnapshot
```

TTS 只作为文本消息的播放/转换形式，不进入核心业务真相源。

## 4. PRD 建议新增章节

后续《圆桌咨询 PRD》建议增加一节：

```text
开源参考与借鉴边界
```

章节内容建议包含：

1. 采用的产品模式：固定顺序专家链。
2. 主要参考：
   - CrewAI Sequential Process：顺序任务与阶段产物。
   - LangGraph Supervisor：主持人调度专家。
   - OpenAI Agents SDK：handoff、session、tracing 命名。
   - Mahilo / Agency Swarm：上下文共享和通信边界。
   - ChatDev / Agent Spec：阶段、角色、产物配置化。
3. 明确不采用：
   - 不做自由 swarm。
   - 不让专家互相无限聊天。
   - 不把所有历史消息无差别塞给下一个专家。
   - 不把 TTS 当业务真相源。
4. 第一版落地边界：
   - 专家顺序写死或配置在服务端常量。
   - 阶段输出必须结构化保存。
   - 下阶段读取上一阶段摘要，而不是全量 transcript。
   - 最终只通过主持人回写现有策略快照。

## 5. 建议的数据抽象

```text
roundtable_session
  consultation_session_id
  mode = roundtable
  current_phase
  status

roundtable_phase
  phase_key = asset | skill | marketing | synthesis
  agent_role
  status
  input_context
  output_summary
  started_at
  completed_at

roundtable_message
  phase_key
  agent_role
  role = user | assistant | system
  content
  transcript_source = text | voice_transcript
  tts_asset_id optional

roundtable_handoff
  from_phase
  to_phase
  handoff_summary
  included_context_keys
  excluded_context_reason
```

第一版也可以不建独立表，先落在现有：

```text
consultation_messages.visible_summary
consultation_events.payload
consultation_sessions.strategy_snapshot
```

但 PRD 需要明确：无论是否独立建表，阶段产物必须可恢复、可回放、可审计。

## 6. 下一步进入 PRD 时要确认的问题

1. 第一版是否只支持一套固定专家链：资产盘点官、技能洞察官、营销策略官、主持人。
2. 每个专家阶段如何结束：用户点击“进入下一位专家”，还是系统判断信息足够后提示确认。
3. 阶段摘要是否允许用户手动修改后再交给下一位专家。
4. 圆桌咨询结果是否直接覆盖现有 `merchant_strategy_assets`，还是先生成候选策略让用户确认。
5. 历史记录里，圆桌咨询是显示成一条咨询会话，还是按专家阶段展开。
