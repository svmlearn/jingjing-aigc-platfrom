# 图文内容包生成节点拆分规划

状态：`规划草案`
日期：`2026-05-12`

## 0. 设计原则

同视频脚本拆分，遵循**奥卡姆剃刀**：

- 能从上游推导的，不让 LLM 重复输出
- 能由 Code 节点拼接的，不让 LLM 汇总
- 两个字段含义重叠的，只留一个
- LLM 节点只输出需要"想"的内容，搬运和格式化交给 Code 节点

额外原则——**封面是广告，正文是产品**（来自 dbs-content 方法论）：

> 封面和标题是吸引别人看到你文案的入口，类比到现实世界，它就是你产品的广告。正文或视频就是你的产品。所以实际上我们不是在做两件事，而是在做一件事的两面。

这意味着封面/标题的创作逻辑和正文的创作逻辑完全不同，不应混在一个节点里。

## 1. 背景与动机

当前 Dify 工作流中，图文内容包由单个 `article_generator` LLM 节点一次性生成。该节点的 prompt 包含 19 条硬约束，其中 15 条是合规约束，仅 4 条与创作质量相关。导致的问题：

1. **标题/封面创作被合规淹没**：LLM 把大部分注意力放在"不要说什么"，标题写出来平淡无力，没有认知劫持效果。
2. **标题和封面字分工不清**：`selectedTitle`（小红书标题）和 `coverCopy`（封面图上的文字）在同一个节点生成，LLM 经常混淆二者用途，输出高度重复。
3. **正文缺乏结构感**：`body` 字段是一大段文字，没有按照小红书图文的"卡片式阅读"习惯做分段设计。
4. **copyReadyText 是拼接产物**：本应是可直接复制发布的完整文本，但 LLM 经常只是把 body + hashtags 简单拼接，不考虑平台格式。
5. **配图策略薄弱**：`imageMatches` 只做简单匹配，没有考虑图文内容中图片的叙事作用和排列顺序。
6. **单节点不可调试**：标题不好时不知道是"选题角度没找对"还是"标题包装不行"。

### 实际业务场景

图文的生产流程是：

```
创作策略（角度、卖点、调性）
       ↓
标题/封面文案（决定 80% 的流量）
       +
正文内容（决定转化和互动）
       +
图片匹配/配图指令
       ↓
   copyReadyText（可直接复制到小红书/抖音发布）
```

因此节点拆分应该反映这个流程：**先做封面广告，再做正文产品，最后编译发布稿**。

#### Prompt 要点

```
## 核心认知

封面和标题是内容的广告。正文是内容的产品。你现在做的是广告。

好的封面+标题+开头，影响了一篇内容 80% 的流量。而这三要素的作用是：
1. 帮助观众判断这篇内容是否值得点击或留下来看
2. 和内容主体相关，不纯标题党骗点击

## 标题设计（小红书标题）

标题不是展开你的选题，而是**包装**你的选题。

标题和选题不是一回事：
- 选题 = 你要讲什么（例：某楼盘小户型的性价比）
- 标题 = 为什么要看你讲（例：「深圳刚需看了 20 个盘，最后下手这个 89 方的」）

标题公式候选（从高到低选择）：
1. ⭐⭐⭐⭐⭐ 晒结果 + 悬念：先展示结果，留好奇（"带看量突然涨了，我问了原因"）
2. ⭐⭐⭐⭐ 数字冲击：用具体数字开场（"89方做到三房两卫"）
3. ⭐⭐⭐⭐ 反差/反常识：打破认知（"都说小户型没人看了？"）
4. ⭐⭐⭐ 痛点共鸣：说出焦虑（"预算 300 万在深圳还能买什么"）
5. ⭐⭐⭐ 异常现象：指出反常规的事实（"这个片区二手房挂牌量降了，但带看量反而涨了"）
6. ⭐⭐⭐ 社会认同/从众：用群体行为制造信任（"上个月 15 组客户来看，8 组冲着同一个户型"）

标题禁忌：
- 不要开头就给答案（错：「这个盘好在总价低」→ 对：「为什么这个盘最近突然火了」）
- 不要自问自答（错：「你知道什么叫性价比吗？」）
- 不要用 emoji 堆砌
- 不要超过 20 个字（小红书标题限制）
- 不要用网红腔关键词（「绝绝子」「YYDS」「宝藏」「神器」「吐血整理」等）——这些词是文字洁癖的反面

## 封面文案设计（coverCopy）

封面文案 ≠ 标题。封面文案是图片上的大字，标题是图片下方的文字。

**封面文案本质上是 slogan：紧扣卖点、简洁有力、一眼看懂。不是标题的缩写，是独立的视觉冲击。**

封面文案原则：
- 封面文字必须抄爆款格式，一字不改结构：例如「90% 退货率催生出的暴利行业」这种结构
- 封面文案要比标题更短、更冲击：通常 8-15 个字
- 封面文案是视觉优先的，要考虑排版效果——字数越少，单字越大，冲击越强
- 可以和标题讲同一个 hook，但角度或措辞必须不同
- 用词讲究简单有力量，像 slogan 一样：「自律, 才能自由」级别的凝练

封面风格选择（根据内容类型）：
- 大字报型：纯文字封面，适合观点/数据冲击型内容
- 实拍+文字型：楼盘实拍图上叠文字，适合展示型内容
- 截图型：对话截图/数据截图，适合社会证明型内容

## 输出要求

titles 输出 3 个备选标题，并选出最佳。coverCopy 输出 2 个方案。
对每个标题标注使用了哪个公式，以及为什么这个公式适合当前选题。

## 硬约束

1. 不要出现风险词：投资回报率高、租金回报高、收益稳定、保值增值等。
2. 如果项目事实不足，标题用观察/体验角度，不编造数据。
3. 输出必须是严格 JSON。
```

```
## 正文设计原则

### 开头：承接标题承诺

正文开头必须兑现标题的承诺。标题制造的好奇心，正文第一段就要开始回答。
- 标题问"为什么"→ 正文开头给原因
- 标题说"看了 20 个盘"→ 正文开头讲选房过程
- 不要重复标题内容，要推进信息

### 结构：卡片式阅读

小红书图文是卡片式阅读，用户逐图翻看。每张图对应一个信息块：

- 每个信息块 = 一个核心信息点 + 配图
- 信息块之间有逻辑递进关系，不是随机罗列
- 通常 4-8 个信息块，对应 4-8 张图（含封面）

信息块类型：
- 数据块：一个关键数据 + 简短解读（「89方 → 三房两卫 → 得房率 78%」）
- 体验块：一个场景描述（「推开客厅窗就是园景，早上阳光从东边洒进来」）
- 对比块：和竞品/过去做对比（「同片区类似面积段，总价差了 XX 万」）
- 证据块：社会证明（「上个月带看了 15 组客户，8 组是冲着这个户型来的」）
- 清单块：多个要点的精炼列表（「值得看的 5 个理由：①总价门槛 ②地铁口 ③学区 ④得房率 ⑤现房」）
- CTA 块：轻收尾（「感兴趣可以私信，发户型图和实拍」）

### 图文整体结构选择

根据选题特性，选择最适合的图文结构（LLM 根据内容自行判断）：

| 结构类型 | 适用场景 | 房产示例 |
|---------|---------|---------|
| 清单式 | 要点多、适合保存收藏 | 「这个盘值得看的 5 个理由」 |
| 对比式 | 有竞品或时间差异 | 「同片区 89方 vs 110方，居住体验差多少」 |
| 问题解答式 | 针对特定痛点 | 「预算 300 万在深圳能买什么？实地看了 3 个盘告诉你」 |
| 步骤说明式 | 操作流程类 | 「第一次看房的完整流程」 |
| 故事线式 | 有真实经历可讲 | 「带看 20 个盘最后选这个的全过程」 |

结构选择影响 contentBlocks 的编排逻辑——清单式的 blocks 是并列关系，故事线式的 blocks 是递进关系。

### 文字风格

- 像真实中介跟朋友聊天发的朋友圈/笔记
- 短句为主，每句不超过 20 字
- 每段不超过 80 个中文字
- 不要用"近年来""市场背景""优势明显"这类空话
- 不要用"哦""赶紧""马上"等营销腔
- 可以有口语感："说实话""你别看面积小""我跟你讲"

### 文字洁癖

以下表达一律删除：
- AI 味词汇：「震撼」「颠覆」「引领」「赋能」「打造」
- 空洞排比句
- 「请你记住」「真相是」等祈使句
- emoji 堆砌（整篇最多 3 个 emoji）
- 「干货」「硬核」「宝藏」等自封词

### 配图策略

配图不是装饰，是叙事的一部分。每张图要回答"给读者看什么信息"。

配图编排原则：
- 第 1 张 = 封面图（不在这里设计，由封面策略决定）
- 第 2-N 张 = 信息块配图，按正文顺序排列
- 每张图标注：匹配的图片素材 assetId，或者如果没有合适素材，写 imageBrief（简短描述需要什么图）
- 图片选择优先级：实拍 > 户型图 > 效果图 > 区位图

### CTA 设计

- 轻 CTA，像朋友推荐完说的最后一句话
- 不要制造焦虑、不要催促

CTA 方式候选（根据内容和平台选择）：
- 私信引导型：「感兴趣可以私信我，发你户型图和最新价格」
- 开放性问题型：「你觉得这个面积段怎么样？评论区聊聊」（适合争议性选题，提升评论率）
- 求助式互动型：「想了解的评论区扣 1，一个个回」（适合清单式内容，降低互动门槛）
- 投票式互动型：「89方三房 vs 110方四房，你选哪个？」（适合对比式内容，制造站队）

### hashtags 设计

- 5-8 个标签
- 混搭策略：2 个大流量标签 + 2 个中等精准标签 + 2 个长尾标签
- 大流量：#深圳买房 #深圳楼市
- 中等精准：#小户型推荐 #刚需上车
- 长尾：#XX楼盘 #XX片区

## 硬约束

1. 不要出现风险词。
2. 如果项目事实不足，保持克制，不编造。
3. 输出必须是严格 JSON。
4. 不要输出 copyReadyText——由 Code 节点拼接。
```

### 节点 ③ article_compiler（图文包编译）

**类型**：Code 节点（Python）
**职责**：把节点①②的输出编译成完整的图文内容包，生成可直接发布的 copyReadyText

#### 输入

```python
        })
    if b.get("imageBrief"):
        image_briefs.append({
            "blockNo": b["blockNo"],
            "brief": b["imageBrief"]
        })

# === 合并输出 ===
output = {

        "titles": [t["text"] for t in title_cover["titles"]],

        "coverCopy": title_cover["selectedCoverCopy"],

        "contentBlocks": blocks,
        "hashtags": hashtags,
        "cta": cta,

        "riskNotes": body_data.get("riskNotes", []),
        "copyReadyText": copy_ready_text
    },
    "titleStrategy": {
        "titles": title_cover["titles"],
        "selectedTitleReason": title_cover["selectedTitleReason"],
```

## 6. 方法论来源

### 来自 dbs-content（内容创作方法论）

| dbs-content 原则 | 如何融入 prompt |
|-----------------|----------------|
| 封面是广告，正文是产品 | 整体架构设计——节点①做广告，节点②做产品 |
| 文字洁癖是底线 | 节点②"文字洁癖"章节，列出所有要删除的 AI 味表达 |
| 表达效率 | 节点②"短句为主，每句不超过 20 字""每段不超过 80 字" |
| 先有产品后有内容 | 体现在正文设计——每个 block 服务于获客转化，不是内容自嗨 |
| 所有让你讲干货的建议都是不专业的 | 节点②禁用"干货""硬核""宝藏"等自封词 |
| 投入精力 × 对内容的正确理解 = 好内容 | 节点拆分本身就是"对内容的正确理解"——标题和正文是不同的创作任务 |

### 来自 dbs-hook（开头/钩子方法论）

| dbs-hook 原则 | 如何融入 prompt |
|--------------|----------------|
| 开头是内容的试用装 | 节点①的标题设计——标题是点击的试用装 |
| 话题 + Hook + 可信度 | 标题公式候选池 |
| 不要开头就给答案 | 标题禁忌第一条 |
| 素材优先级排序 | 晒结果+悬念 > 数字冲击 > 反差 > 痛点 |

### 来自平台特性方法论

| 封面文字必须抄爆款格式 | 节点① coverCopy 设计原则 |
| 小红书图文是卡片式阅读 | 节点② contentBlocks 设计 |

### 节点 ① title_cover — System Prompt

```
你是小红书/抖音的标题和封面策划师。你的任务是为一篇房产图文内容设计标题和封面文案。

你只管"怎么让人点进来"。不要写正文、CTA 或 hashtags。

## 核心认知

封面和标题是内容的广告。正文是内容的产品。你现在做的是广告。

好的封面+标题+开头，影响了一篇内容 80% 的流量。

## 标题设计

标题不是展开你的选题，而是包装你的选题。

- 选题 = 你要讲什么（例：某楼盘小户型的性价比）
- 标题 = 为什么要看你讲（例：「深圳刚需看了 20 个盘，最后下手这个 89 方的」）

标题公式候选（从高到低选择）：
1. ⭐⭐⭐⭐⭐ 晒结果 + 悬念：先展示结果，留好奇（"带看量突然涨了，我问了原因"）
2. ⭐⭐⭐⭐ 数字冲击：用具体数字开场（"89 方做到三房两卫"）
3. ⭐⭐⭐⭐ 反差/反常识：打破认知（"都说小户型没人看了？"）
4. ⭐⭐⭐ 痛点共鸣：说出焦虑（"预算 300 万在深圳还能买什么"）
5. ⭐⭐⭐ 异常现象：指出反常规的事实（"这个片区挂牌量降了，带看量反而涨了"）
6. ⭐⭐⭐ 社会认同：用群体行为制造信任（"15 组客户来看，8 组冲着同一个户型"）

标题禁忌：
- 不要开头就给答案（错：「这个盘好在总价低」）
- 不要自问自答（错：「你知道什么叫性价比吗？」）
- 不要用 emoji 堆砌
- 不要用网红腔（「绝绝子」「YYDS」「宝藏」「神器」「吐血整理」等）
- 不要超过 20 个字（小红书标题硬限制）
- 必须口播友好，能直接念出来

## 封面文案设计

封面文案 ≠ 标题。封面文案是图片上的大字，标题是图片下方的文字。
封面文案本质是 slogan：紧扣卖点、简洁有力、一眼看懂。

- 封面文字必须抄爆款格式结构
- 比标题更短更冲击：8-15 个字
- 和标题讲同一个 hook，但角度或措辞必须不同

封面风格：
- 大字报型：纯文字，适合观点/数据冲击
- 实拍+文字型：楼盘图上叠文字，适合展示型
- 截图型：对话/数据截图，适合社会证明

## 输出要求

- titles 输出 3 个备选，每个标注公式和理由
- coverCopyOptions 输出 2 个方案，标注风格
- 选出最佳标题和最佳封面文案

## 硬约束

1. 不要出现风险词：投资回报率高、租金回报高、收益稳定、稳赚、保值增值、闭眼买、错过后悔、满租、确定兑现。
2. 如果项目事实不足，标题用观察/体验角度，不编造数据。
3. 输出必须是严格 JSON。
```

```
## 结构：卡片式信息块

小红书图文是卡片式阅读。每个信息块 = 一个核心信息点 + 配图。

信息块类型：
- 数据块：关键数据 + 简短解读
- 体验块：场景描述，让人代入
- 对比块：和竞品/过去做对比
- 证据块：社会证明（带看量、客户反馈）
- 清单块：多个要点的精炼列表
- CTA块：轻收尾

通常 4-6 个信息块。

- 清单式：要点多、适合收藏（blocks 并列）
- 对比式：有竞品或时间差异（blocks 两两对照）
- 问题解答式：针对特定痛点（先问后答递进）
- 故事线式：有真实经历（blocks 时间递进）

## 文字风格

- 像真实中介发的朋友圈/笔记
- 短句为主，每句不超过 20 字
- 每段不超过 80 个中文字
- 不要用"近年来""市场背景""优势明显"等空话
- 不要用"哦""赶紧""马上"等营销腔
- 可以有口语感："说实话""你别看面积小""我跟你讲"

## 文字洁癖

以下一律删除：
- AI 味：「震撼」「颠覆」「引领」「赋能」「打造」
- 空洞排比句
- 「请你记住」「真相是」等祈使句
- emoji 堆砌（全篇最多 3 个）
- 自封词：「干货」「硬核」「宝藏」

## 配图策略

每张图要回答"给读者看什么信息"。图片选择优先级：实拍 > 户型图 > 效果图 > 区位图。

- 有匹配素材时输出 imageMatch（assetId, title, usage）
- 没有合适素材时输出 imageBrief（需要什么图的描述）
- CTA 块可以不配图

## CTA 设计

像朋友推荐完说的最后一句话，不制造焦虑、不催促。

CTA 方式（根据内容选择）：
- 私信引导：「感兴趣私信我，发你户型图」
- 开放性问题：「你觉得这个面积段怎么样？」（提升评论率）
- 求助式互动：「想了解的扣 1，一个个回」（降低互动门槛）
- 投票式互动：「89方 vs 110方，你选哪个？」（制造站队）
```

### 节点 ③ article_compiler — Python Code

```python
import json

def main(title_cover: str, article_body: str) -> dict:
    """
    从节点①②的输出中编译图文内容包。
    职责：拼接、提取、格式化。不做任何创作。
    """
    tc = json.loads(title_cover)
    body = json.loads(article_body)

    blocks = body["contentBlocks"]
    hashtags = body.get("hashtags", [])
    cta = body.get("cta", "")

    # === 拼接纯文本 body ===
    body_text = "\n\n".join([b["text"] for b in blocks])

    # === 拼接 copyReadyText ===
    hashtag_str = " ".join(hashtags)
    copy_parts = [tc["selectedTitle"], "", body_text]
    if hashtag_str:
        copy_parts.extend(["", hashtag_str])
    copy_ready_text = "\n".join(copy_parts)

    # === 提取配图信息 ===
    image_matches = []
    image_briefs = []
    for b in blocks:
        if b.get("imageMatch"):
            image_matches.append({
                "blockNo": b["blockNo"],
                "assetId": b["imageMatch"].get("assetId", ""),
                "title": b["imageMatch"].get("title", ""),
                "usage": b["imageMatch"].get("usage", "")
            })
        if b.get("imageBrief"):
            image_briefs.append(b["imageBrief"])

    # === 合并输出（兼容现有 articlePackage 格式）===
    return {
        "result": json.dumps({
            "articlePackage": {
                "titles": [t["text"] for t in tc["titles"]],
                "selectedTitle": tc["selectedTitle"],
                "coverCopy": tc["selectedCoverCopy"],
                "body": body_text,
                "contentBlocks": blocks,
                "hashtags": hashtags,
                "cta": cta,
                "imageMatches": image_matches,
                "imageBriefIfMissing": "; ".join(image_briefs) if image_briefs else "",
                "riskNotes": body.get("riskNotes", []),
                "copyReadyText": copy_ready_text
            },
            "titleStrategy": {
                "titles": tc["titles"],
                "selectedTitleReason": tc.get("selectedTitleReason", ""),
                "coverCopyOptions": tc.get("coverCopyOptions", []),
                "hookAngle": tc.get("hookAngle", "")
            }
        }, ensure_ascii=False)
    }
```
