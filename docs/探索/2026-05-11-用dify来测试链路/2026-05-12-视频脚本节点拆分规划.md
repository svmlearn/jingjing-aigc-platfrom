# 视频脚本生成节点拆分规划

状态：`规划草案`
日期：`2026-05-12`

## 0. 设计原则

**奥卡姆剃刀**：如无必要，不增加字段。

- 能从 `sceneType` 推导的，不让 LLM 输出（uploadRequired、assetSourceHint 等）
- 能由 Code 节点计算的，不让 LLM 汇总（summary、requiredUploads 列表等）
- 两个字段含义重叠的，只留一个（filmingGuide.script 和 voiceover 只留 voiceover）
- LLM 节点只输出需要"想"的内容，搬运和整理交给 Code 节点

## 1. 背景与动机

当前 Dify 工作流中，视频脚本由单个 `video_script_generator` LLM 节点一次性生成。该节点的 prompt 包含 15 条硬约束，其中 13 条是合规约束，仅 2 条与创作质量相关。导致的问题：

1. **创意被合规淹没**：LLM 把大部分注意力放在"不要说什么"，而非"怎么讲好这个故事"。
2. **画面描述笼统**：`visualGoal` 输出类似"展示项目整体面貌"，无法指导素材检索和拍摄。
3. **缺少前 3 秒钩子设计**：短视频最关键的留存设计完全没有规则。
4. **口播指导缺失**：中介不知道在哪拍、怎么站、说什么。
5. **单节点不可调试**：输出不好时不知道是"故事没想好"还是"镜头没拆对"。

### 实际业务场景

视频的生产流程是：

```
中介拍一段口播（自己手机拍）
       +
专业视频素材库（线下摄影团队拍的楼盘素材）
       ↓
   worker 自动剪辑拼接成片
```

因此脚本**不需要专业影视术语**（运镜方式、景别缩写等），而需要：
- 给中介：大白话的拍摄任务
- 给 worker：可执行的剪辑指令 + 素材检索关键词
- 给前端渲染：结构化 JSON，不同字段在不同端展示

## 2. 改动范围

只改 `video_script_generator` 这一个节点。将其拆分为 3 个节点，其余节点不动。

### 当前工作流

```
开始 → 任务理解 → 知识库检索 → 创作策略规划 → 图文内容包生成
                                      ↓
                              ┌───────────────┐
                              │video_script_   │  ← 拆分这个
                              │generator(LLM)  │
                              └───────────────┘
                                      ↓
                              质量评审 → [违规改写] → 最终结果编译 → 结束
```

### 改后工作流

```
开始 → 任务理解 → 知识库检索 → 创作策略规划 → 图文内容包生成
                                      ↓
                         ┌────────────────────┐
                         │ ① video_narrative   │  LLM - 视频叙事结构
                         │   (视频叙事结构)     │
                         └─────────┬──────────┘
                                   ↓
                         ┌────────────────────┐
                         │ ② scene_breakdown   │  LLM - 分镜拆解
                         │   (分镜与素材策略)   │
                         └─────────┬──────────┘
                                   ↓
                         ┌────────────────────┐
                         │ ③ delivery_compiler │  Code - 执行指令编译
                         │   (交付物编译)       │
                         └─────────┬──────────┘
                                   ↓
                              质量评审 → [违规改写] → 最终结果编译 → 结束
```

## 3. 节点详细设计

---

### 节点 ① video_narrative（视频叙事结构）

**类型**：LLM 节点
**职责**：只管"讲什么故事、怎么讲"，不管具体镜头执行

#### 输入

| 来源 | 字段 | 说明 |
|------|------|------|
| creative_strategy 输出 | `videoPlan` | 创作策略中的视频方向 |
| creative_strategy 输出 | `mustUseFacts` | 必须使用的项目事实 |
| creative_strategy 输出 | `mustAvoidClaims` | 必须规避的风险主题 |
| article_generator 输出 | `copyReadyText` | 仅用于提炼口播语气，不复写 |
| 开始节点 | `calendar_task_json` | 任务上下文（主题、目标受众、平台） |

#### Prompt 要点

```
你是短视频内容策划师。你的任务是为一条房产短视频设计叙事结构。

你只需要想清楚"讲什么故事、用什么节奏打动观众"，不需要拆具体镜头。

规则：
1. 必须设计前 3 秒钩子：用悬念、痛点、反常识或视觉冲击抓住注意力。
2. 全片要有情绪起伏，不能从头到尾一个调。
3. 叙事弧线一般是：好奇 → 认同 → 心动 → 行动（可根据主题调整）。
4. 语气像真实本地中介跟朋友聊天，不像广告公司硬广。
5. 不要出现风险词（投资回报率高、租金回报高、收益稳定、保值增值等）。
6. 如果项目事实不足，保持克制，不编造。
```

#### 输出 JSON

```jsonc
{
  "hook": {
    "strategy": "反常识",              // 悬念 | 痛点 | 反常识 | 视觉冲击 | 数字冲击
    "openingLine": "都说小户型没人看了？这个盘打了所有人的脸"
  },
  "narrativeArc": ["好奇", "认同", "心动", "行动"],
  "storyOutline": "以'小户型回归'为切入，先用反常识钩住，再用真实客户视角讲三个核心卖点（总价门槛、配套成熟、户型实用），最后轻CTA收尾",
  "estimatedDuration": "35-45秒",
  "bgmDirection": "轻快现代感，节奏适中",
  "toneOfVoice": "像朋友聊天推荐，真诚不夸张",
  "voiceoverDraft": "都说小户型没人看了，但最近这个盘的小户型我带看量反而涨了。89方做到三房两卫，楼下就是地铁口，商业配套走路5分钟。感兴趣的可以私信我，发你户型图和实拍"
}
```

**精简说明**（奥卡姆剃刀）：

| 砍掉的字段 | 原因 |
|-----------|------|
| `hook.whyItWorks` | 分析性文字，不指导执行 |
| `narrativeArc[].purpose` | 节拍名本身已自解释，purpose 是废话 |
| `targetSceneCount` | 节点②自己决定用几个镜头 |
| `voiceoverDraft` 拆分 | 不需要分 opening/body/closing，一段完整文字即可 |
| `complianceReminder` | creative_strategy.mustAvoidClaims 已有，不重复传递 |

### 节点 ② scene_breakdown（分镜拆解与素材策略）

**类型**：LLM 节点
**职责**：把叙事结构拆成具体镜头，标注每个镜头的类型、画面描述、素材需求

#### 输入

| 来源 | 字段 | 说明 |
|------|------|------|
| video_narrative 输出 | 全部 | 叙事结构、钩子、弧线、口播梗概 |
| creative_strategy 输出 | `mustUseFacts` | 项目事实 |
| 开始节点 | `image_assets_json` | 可用图片素材（视频素材不在此输入，由 worker 从素材库检索） |

#### Prompt 要点

```
你是短视频分镜编排师。你的任务是把视频叙事结构拆解成可执行的逐镜头脚本。

这些镜头最终会由 worker 自动剪辑。中介只需要拍口播部分，其他画面从专业视频素材库中选取。

规则：
1. 每个镜头必须标注类型：口播 / 素材 / 文字卡。
2. 画面描述必须具体到"10个人看完想到的画面基本一样"的程度。
   - 好：「小区入口的航拍画面，从高处缓缓下降，能看到整个小区绿化带和右侧的商业街」
   - 差：「展示项目整体面貌」
3. 口播镜头要给中介实操级指导：在哪拍、什么姿态、准备什么道具。
4. 素材镜头的 assetQuery 要写成视频素材库能搜到的关键词组合。
5. 第一个镜头必须承接叙事结构中的钩子设计，3秒内抓住注意力。
6. 转场用通俗语言：直接切 / 渐变过渡 / 声音先入画面后跟。
7. 全片节奏要有快慢变化——展示画面可以快切（每个1-2秒），口播段落给足时间（5-8秒）。
8. 字幕是独立文案，不是画面描述的重复，要适合在手机上阅读。
9. 不要出现风险词。
```

#### 输出 JSON

**精简说明**（奥卡姆剃刀）：

| 砍掉的字段 | 原因 |
|-----------|------|
| `uploadRequired` | `sceneType=口播` → true，其余 → false，100% 可推导 |
| `uploadReason` | `sceneType` 本身就是原因 |
| `assetSourceHint` | `sceneType` 本身就是来源提示 |
| `assetQuery`（口播镜头的空值） | 口播镜头不输出此字段，避免输出空字符串 |
| `subtitle`（口播镜头的空值） | 口播字幕由语音自动生成，不输出此字段 |

**字段条件出现规则**：

| 字段 | 口播 | 素材 | 文字卡 |
|------|------|------|--------|
| `visualDescription` | 有 | 有 | 无 |
| `voiceover` | 有（口播台词） | 可选（画外音） | 无 |
| `subtitle` | 无 | 有 | 有（主要内容） |
| `assetQuery` | 无 | 有 | 无 |
| `filmingGuide` | 有 | 无 | 无 |
| `fallbackVisual` | 无 | 有 | 无 |
| `transition` | 有 | 有 | 有 |
| `pacing` | 有 | 有 | 有 |

### 节点 ③ delivery_compiler（交付物编译）

**类型**：Code 节点（Python）
**职责**：把 scene_breakdown 的输出拆分成两套交付物 JSON，供前端按角色渲染

#### 输入

| 来源 | 字段 | 说明 |
|------|------|------|
| video_narrative 输出 | 全部 | 叙事结构（BGM、调性等全片级信息） |
| scene_breakdown 输出 | 全部 | 完整分镜数据 |

#### 逻辑（伪代码）

核心职责：从 scenes 中**推导**出节点②刻意不输出的汇总字段，再按角色拆分交付物。

```python
narrative = node_inputs["video_narrative"]
scenes = node_inputs["scene_breakdown"]["scenes"]
risk_notes = node_inputs["scene_breakdown"]["riskNotes"]

# === 从 sceneType 推导汇总 ===
filming_scenes = [s for s in scenes if s["sceneType"] == "口播"]
asset_scenes = [s for s in scenes if s["sceneType"] == "素材"]
text_scenes = [s for s in scenes if s["sceneType"] == "文字卡"]

# === 交付物 A：给中介的拍摄任务单 ===
member_delivery = {
    "tasks": [
        {
            "taskNo": i + 1,
            "sceneNo": s["sceneNo"],
            "script": s["voiceover"],           # 口播台词从 voiceover 取，不重复存
            "location": s["filmingGuide"]["location"],
            "posture": s["filmingGuide"]["posture"],
            "props": s["filmingGuide"]["props"],
            "tips": s["filmingGuide"]["tips"]
        }
        for i, s in enumerate(filming_scenes)
    ]
}

# === 交付物 B：给 worker 的剪辑指令 ===
worker_delivery = {
    "storyOutline": narrative["storyOutline"],
    "bgm": narrative["bgmDirection"],
    "toneOfVoice": narrative["toneOfVoice"],
    "estimatedDuration": narrative["estimatedDuration"],
    "scenes": scenes,                           # 直接透传完整分镜，worker 按 sceneType 处理
    "teamAssetQueries": [s["assetQuery"] for s in asset_scenes]
}

# === 合并输出 ===
output = {
    "videoScript": {
        "narrative": narrative,
        "scenes": scenes,
        "riskNotes": risk_notes
    },
    "memberDelivery": member_delivery,
    "workerDelivery": worker_delivery
}
```

| `workerDelivery.type` | 同上，只有一种类型 |
| `videoScript.summary` | 前端/质量评审自己 count scenes 即可 |

## 4. 节点依赖关系

```
creative_strategy ──┬──→ article_generator（不变）
                    │
                    ├──→ ① video_narrative（可与 article_generator 并行）
                    │         │
                    │         ↓  输出: hook, narrativeArc, storyOutline, bgm, toneOfVoice, voiceoverDraft
                    │
                    └──→ ② scene_breakdown（等 ① 完成）
                              │  输入: ①全部 + creative_strategy.mustUseFacts + image_assets_json
                              │
                              ↓  输出: scenes[], riskNotes[]（仅此二字段，无汇总）
                              │
                         ③ delivery_compiler（Code，等 ② 完成，零延迟）
                              │  输入: ①全部 + ②全部
                              │  推导: 从 sceneType 计算上传清单、素材清单、汇总统计
                              │
                              ↓  输出: videoScript + memberDelivery + workerDelivery
                              │
                         quality_review（输入改为 ③.videoScript）
```

### 节点 ① video_narrative — System Prompt

```
你是短视频叙事策划师。你的任务是为一条房产短视频设计叙事结构。

你只管"讲什么故事、用什么节奏打动人"。不要拆具体镜头，不要写完整文案。

## 钩子设计（最重要）

开头是内容的试用装。不能假设观众看了标题或封面。前 3 秒必须独立建立吸引力。

钩子公式：话题（讲什么）+ Hook（为什么要看）+ 可信度（为什么信你）
示例：「我去年涨粉 200 万，靠的就是搞清楚选题和标题的区别」

素材优先级（从高到低选择 hook 素材）：
1. ⭐⭐⭐⭐⭐ 晒结果 + 反转：先展示成绩，再制造好奇（"最近这个盘小户型带看量反而涨了，很多人问我为什么"）
2. ⭐⭐⭐⭐ 数据冲击：用大数字或对比数字开场（"89方做到三房两卫"）
3. ⭐⭐⭐⭐ 反差/转变：认知反差制造好奇（"都说小户型没人看了？"）
4. ⭐⭐⭐ 痛点 + 悬念：说出焦虑，留住答案（"深圳刚需看了 20 个盘没下手的，问题可能出在这"）

钩子禁忌：
- 不要开头就给答案（错：「这个盘好在总价低」→ 对：「为什么这个盘最近突然火了」）
- 不要自问自答（错：「你知道什么叫性价比吗？」）
- 必须口播友好，能直接念出来，不要书面语

## 叙事弧线

全片要有情绪起伏。常见弧线：
- 好奇 → 认同 → 心动 → 行动（标准种草）
- 痛点 → 共鸣 → 解法 → 行动（解决问题型）
- 反常识 → 解释 → 证据 → 行动（认知刷新型）

根据主题选择合适的弧线，不要千篇一律。

## 空间动线（房产视频特有）

房产视频的叙事线 = 空间动线。好的房产视频不是展示一个个孤立房间，而是展示空间之间的关系——"从这里走进去是什么""从这扇窗看出去是什么"。

设计 storyOutline 时，要规划一条观众能代入的空间路径，例如：
- 小区入口 → 园林通道 → 楼栋大堂 → 室内客厅 → 卧室 → 阳台望出去
- 或者：周边街道 → 商业配套 → 小区入口 → 样板间

这条动线走顺了，观众自然代入"住进去"的感觉。不要随机跳跃场景。

## 口播稿梗概

写一段完整的口播稿梗概（不是最终稿，是给下游节点的方向）。要求：
- 像真实中介跟朋友聊天，不像广告公司写的
- 短句为主，每句不超过 20 字
- 不要用"近年来""随着市场""实现梦想"这类空话
- 不要用"哦""赶紧""马上抢"这类营销腔
- 可以有口语感："说实话""你猜怎么着""我跟你讲"

## 硬约束

1. 不要出现风险词：投资回报率高、租金回报高、收益稳定、保值增值、稳赚、满租、确定兑现。
2. 如果项目事实不足，保持克制，不编造具体数据。用"可以实地看看""建议结合预算了解"替代。
3. 输出必须是严格 JSON。
```

### 节点 ② scene_breakdown — System Prompt

```
你是短视频分镜编排师。你的任务是把视频叙事结构拆成可执行的逐镜头脚本。

背景：中介只拍口播部分（手机自拍），其他画面从专业视频素材库选取，最后由 worker 自动剪辑。

## 镜头类型

每个镜头必须标注 sceneType，只有三种：
- 口播：中介对着镜头说话，需要本人拍摄
- 素材：从视频素材库检索，专业摄影团队拍好的
- 文字卡：纯文字/数据展示画面

## 画面描述原则

画面描述是这个脚本最核心的字段。标准：让 10 个人看完文字后，脑海中形成的画面基本一致。

好的描述（具体、可执行）：
- 「小区正门航拍，镜头从高处缓缓下降，能看到大门、两侧绿化和右侧商业街」
- 「样板间客厅全景，阳光从左侧落地窗洒进来，能看到沙发、茶几和餐厅区域」
- 「中介站在售楼处沙盘旁，面对镜头自然说话，背景是沙盘」

差的描述（抽象、无法执行）：
- ❌ 「展示项目整体面貌」
- ❌ 「体现生活便利性」
- ❌ 「营造温馨居家氛围」

自检：每条 visualDescription 写完后检查是否覆盖了以下至少三项：
- WHO：画面中有谁/什么主体
- WHAT：在做什么/什么状态
- WHERE：在什么场景/位置
- WHEN：什么光线/时段（如"阳光洒进来""傍晚亮灯"）
- HOW：什么视角/氛围（如"从高处俯瞰""从门框望进去"）

## 字幕文案原则

字幕不是画面描述的重复，是观众在手机上看到的文案。要求：
- 像人说话，不像广告词
- 一句话一个信息点，不要塞太多
- 可以有口语化表达：「真的绝了」「这个我服」
- 不要写「震撼」「惊艳」「颠覆」这类空洞感叹词
- 不要用 emoji

## 素材检索关键词（assetQuery）

assetQuery 是给视频素材库搜索用的。要求：
- 用空格分隔的中文关键词组合
- 包含：场景 + 特征 + 视角，如「样板间 客厅 落地窗 阳光 通透」
- 不要写句子，只写关键词

## 口播拍摄指导（filmingGuide）

仅 sceneType=口播 时输出。给中介大白话指导：
- location：在哪拍（售楼处/样板间/小区门口）
- posture：什么姿态（站着/边走边说/坐着）
- props：需要准备什么（工牌/户型图/沙盘）
- tips：2-3 条实操提示，像同事提醒的话

tips 候选池（根据场景选用，不要每次全写）：
- 构图类：「不要站在房间正中央，站在角落或门框边，画面更有纵深感」「可以利用门框当天然画框，人在门框里说话，背景是房间」
- 拍摄类：「手机横屏拍，画质调到 1080p 以上」「找光线好的位置，脸上不要有阴影」「开头和结尾各多录 2 秒，方便剪辑」
- 表达类：「语速放慢，像跟朋友聊天」「拍两遍，选自然的那条」「不要背稿，看一眼要点然后用自己的话说」

一致性要求：如果一个视频有多段口播（比如开头一段、结尾一段），中介的穿着和整体形象要保持一致，建议一次拍完所有口播段落。

## 节奏控制

全片节奏要有快慢交替：
- 素材展示画面：快切（pacing=快，每个 1-3 秒），制造丰富感
- 口播段落：正常或慢（pacing=正常/慢，5-10 秒），留足表达时间
- 文字卡：正常（pacing=正常，3-5 秒），确保能读完
- 不能全片一个节奏，快慢交替才有观感

## 转场

只用三种，通俗表达：
- 直接切：大多数情况用这个
- 渐变过渡：情绪转换时用（如从素材展示切到口播总结）
- 声音先入画面后跟：口播声音先出来，画面还停在上一个素材上，再切到口播画面

## 字段条件出现规则

不要输出无意义的空字段：
- 口播镜头：输出 voiceover + filmingGuide，不输出 assetQuery / subtitle / fallbackVisual
- 素材镜头：输出 subtitle + assetQuery + fallbackVisual，voiceover 仅在有画外音时输出
- 文字卡：输出 subtitle，不输出 assetQuery / voiceover / filmingGuide / fallbackVisual

## 硬约束

1. 第一个镜头必须承接叙事结构中的钩子，3 秒内抓注意力。
2. 不要出现风险词。
3. 输出必须是严格 JSON，顶层只有 scenes 数组和 riskNotes 数组。
4. 不要输出 summary、requiredUploads、optionalTeamVideoAssets 等汇总字段（由 Code 节点计算）。
```

{{creative_strategy.mustUseFacts}}

{{image_assets_json}}

### 节点 ③ delivery_compiler — Python Code

```python
import json

def main(video_narrative: str, scene_breakdown: str) -> dict:
    """
    从节点①②的输出中编译交付物。
    职责：推导、拆分、整理。不做任何创作。
    """
    narrative = json.loads(video_narrative)
    breakdown = json.loads(scene_breakdown)
    scenes = breakdown["scenes"]
    risk_notes = breakdown.get("riskNotes", [])

    # === 从 sceneType 推导分类 ===
    filming_scenes = [s for s in scenes if s["sceneType"] == "口播"]
    asset_scenes = [s for s in scenes if s["sceneType"] == "素材"]

    # === 交付物 A：给中介的拍摄任务单 ===
    member_delivery = {
        "tasks": []
    }
    for i, s in enumerate(filming_scenes):
        guide = s.get("filmingGuide", {})
        member_delivery["tasks"].append({
            "taskNo": i + 1,
            "sceneNo": s["sceneNo"],
            "script": s.get("voiceover", ""),
            "location": guide.get("location", ""),
            "posture": guide.get("posture", ""),
            "props": guide.get("props", []),
            "tips": guide.get("tips", [])
        })

    # === 交付物 B：给 worker 的剪辑指令 ===
    worker_delivery = {
        "storyOutline": narrative.get("storyOutline", ""),
        "bgm": narrative.get("bgmDirection", ""),
        "toneOfVoice": narrative.get("toneOfVoice", ""),
        "estimatedDuration": narrative.get("estimatedDuration", ""),
        "scenes": scenes,
        "teamAssetQueries": [
            s["assetQuery"] for s in asset_scenes if s.get("assetQuery")
        ]
    }

    # === 合并输出 ===
    return {
        "result": json.dumps({
            "videoScript": {
                "narrative": narrative,
                "scenes": scenes,
                "riskNotes": risk_notes
            },
            "memberDelivery": member_delivery,
            "workerDelivery": worker_delivery
        }, ensure_ascii=False)
    }
```
