Pixelle-Video × 小红书AI剪辑视频：从素材理解到自动剪辑的 knowhow

这个页面把两个开源项目拆成产品流程：它们怎么运行、怎么找素材、怎么理解素材、怎么生成脚本、怎么排剪辑时间线、怎么做转场和渲染，以及我们应该如何吸收进自己的视频工作台和 worker。

产品经理读法

先看“它解决什么问题”

Pixelle-Video 更像从主题生成一条新视频；小红书AI剪辑视频更像拿已有素材剪成片。

再看“它怎么做判断”

重点看素材从哪里来、系统理解了什么、这些理解结果怎样影响脚本、分组和剪辑。

最后看“我们怎么改造”

不要直接合并代码，而是把 knowhow 装进本项目的脚本确认、素材中心、video job 和 worker 合同里。

一句话结论：Pixelle-Video 适合做“无素材快速生成”，小红书AI剪辑视频适合做“有素材自动剪辑”，本项目要做的是把两者变成可控、可解释、可验收的视频生产链路。

Pixelle-Video：生成型视频工厂

适合从主题、脚本或少量商家素材快速做出一条模板化视频。核心不是剪已有长素材，而是把文案、画面、配音和模板串成一条线性流水线。

01 输入
用户输入主题、固定文案或上传素材 快速创作 tab 输入主题或脚本；自定义素材 tab 上传图片/视频，并填写标题、意图、目标时长。
02 内容
LLM 生成标题、旁白、画面提示词 主题模式下生成 narrations；固定文案模式下切分脚本；需要画面时再为每段生成 image prompt。
03 素材
ComfyUI/RunningHub 生成图片或视频 `image_*.json` 生成图片，`video_*.json` 生成视频；上传素材模式会先用视觉工作流生成素材描述。
04 定时
TTS 先生成音频，音频时长决定镜头长度 这是 Pixelle 的关键 knowhow：旁白不是贴上去的装饰，而是整个镜头时长的时钟。
05 包装
HTML 模板渲染每个镜头画面 模板决定横竖屏、标题、字幕、背景图/视频、品牌样式。它把“画面设计”从剪辑代码里抽出来。
06 合成
FFmpeg 生成片段、拼接、加 BGM 每个 frame 变成一个 segment，最后线性拼接。BGM 支持 loop/once 和音量调节。

小红书AI剪辑视频：素材理解型剪辑 Agent

这个项目是 FireRed-OpenStoryline 整理版。它的强项是把剪辑拆成一组工具节点，由 Agent 根据用户目标调度。

01 搜/传素材
用户上传素材，或通过 Pexels 搜索补充素材 Web 侧支持会话级素材上传；`search_media` 可按关键词、横竖屏、数量、时长搜索下载 Pexels 素材。
02 建索引
load_media 为素材分配 ID 并读取元数据 图片读取宽高；视频读取时长、宽高、fps、音频信息。每个素材得到 `media_0001` 这种 ID。
03 切镜头
split_shots 用 TransNetV2 + FFmpeg 切出 clip 视频按场景边界切分，并限制最短/最长时长；图片作为单个 clip 进入后续流程。
04 看懂素材
understand_clips 用 VLM 生成 caption 和美学分 识别主体、动作、表情、场景、视角、氛围、画质、光影、构图和稳定性，并生成 overall 总结。
05 筛选分组
filter_clips 和 group_clips 决定保留哪些镜头、如何叙事排序 先按质量和用户要求筛选，再把镜头组织成段落 group，为脚本和时间线做准备。
06 生成制作元素
脚本、配音、BGM、转场、字幕样式分别由节点生成 `generate_script` 写旁白和字幕；`generate_voiceover` 生成 TTS；`select_bgm` 选音乐并算鼓点；`generate_ai_transition` 可生成镜头间 AI 转场。
07 时间线
plan_timeline 生成 video/subtitle/voiceover/bgm 多轨时间线 配音时长、素材时长、BGM 鼓点共同决定每个镜头出现多久、从原素材截哪一段。
08 渲染
render_video 用 MoviePy 拼画面、叠字幕、混音、导出 mp4 最终输出包含画面轨、字幕轨、配音轨和 BGM 轨，不只是简单拼接。

素材链路

Pixelle-Video 的素材链路

  • AI 生成图片/视频是主力素材。
  • 用户上传素材主要在 `custom_media` 流程里使用。
  • BGM 来自本地 `bgm/` 文件夹。
  • 素材更偏“当前任务使用”，不是长期素材中心。

小红书AI剪辑视频的素材链路

  • 用户上传图片/视频到 session media 目录。
  • Pexels 可按关键词、横竖屏、数量和时长搜索补充素材。
  • BGM、字体、脚本模板来自 `resource/`。
  • 素材经过 load、切分、理解、筛选、分组后进入时间线。
对本项目来说，素材链路应该回到 COS 和 `asset_objects`。两个开源项目的本地文件目录只能作为执行缓存，不能成为长期真相源。

语义理解

基础信息

  • 图片：宽高、格式。
  • 视频：时长、fps、宽高、是否有音频。
  • 这一步回答“素材是什么文件”。

画面理解

  • Pixelle：图片/视频理解工作流生成描述。
  • OpenStoryline：VLM 输出 caption 和 aes_score。
  • 这一步回答“画面里有什么、好不好看”。

剪辑理解

  • 筛选相似或低质量片段。
  • 把镜头按叙事目标分组。
  • 根据 group 生成脚本和时间线。
问题 Pixelle-Video 小红书AI剪辑视频 我们应如何产品化
系统理解了素材什么？ 上传素材时生成图片/视频描述。 镜头级 caption、美学分、overall、ASR 文本。 沉淀为素材中心的 AI 标签、镜头、质量分和可用场景。
理解结果影响什么？ 影响 LLM 为 scene 分配哪个 asset。 影响筛选、分组、脚本、BGM 和时间线。 让用户看到“为什么用这段素材”，并允许人工改。
缺什么？ 缺镜头切分、长期素材画像和复杂筛选。 缺业务合同、长期资产库和稳定产品边界。 由 app 建合同，由 worker 执行，由素材中心积累认知。

剪辑时间线

Pixelle 的 storyboard

一个视频由多个 frame 顺序组成。每个 frame 包含旁白、画面提示词、图片/视频、模板渲染图和单段视频。

frame 1 frame 2 frame 3 concat BGM

OpenStoryline 的多轨 timeline

一个视频由 video、subtitles、voiceover、bgm 多条轨道组成。每条轨道都有 source_window 和 timeline_window。

video track subtitle track voiceover track bgm track render
剪辑对象 产品解释 对用户有什么价值
source_window 从原始素材里截哪一段 可以解释为什么这段素材只用了 2 秒
timeline_window 在最终成片第几秒出现 支持后续调整顺序、节奏和字幕时间
voiceover duration 配音真实时长 让画面跟着旁白走，减少错位
beats BGM 鼓点 让镜头切换更有节奏感

能力对比

能力 Pixelle-Video 小红书AI剪辑视频 融合判断
主题生成视频 强 弱 用 Pixelle 做无素材快创。
素材理解 中 强 用 OpenStoryline 的切分、caption、美学分。
素材搜索 基本没有 Pexels 搜索 可做补充素材，但要处理版权和品牌一致性。
字幕 HTML 模板镜头级字幕 时间线字幕轨 快创用模板字幕，可编辑视频用字幕轨。
BGM 手动选择 + loop/once 语义推荐 + beat 分析 OpenStoryline 的 BGM knowhow 更适合产品化。
转场 以拼接为主 fade + AI 转场视频 AI 转场放增强版，不放 MVP 门槛。
渲染 FFmpeg 简洁稳定 MoviePy 多轨灵活 worker 可按任务类型选择 renderer。

融合改造路线

MVP
先把“有脚本 + 有素材 -> 生成可预览视频”跑顺。 使用现有 video_edit_jobs、COS、worker。脚本必须用户确认；素材必须来自素材中心或上传到 COS；worker 不重写业务语义，只做制作执行。
增强版
加入素材理解和可解释剪辑计划。 引入镜头切分、caption、美学分、overall；工作台展示 AI 如何理解素材；生成 video/subtitle/voiceover/bgm 多轨计划，支持制作修订。
长期版
做混合生成和高级效果。 真实素材不足时用 Pixelle 式 AI 生成补充镜头；支持 ASR 粗剪、AI 转场、多平台比例适配、品牌模板和素材资产复利。
推荐架构：Pixelle-Video 做 AI 生成补充能力，OpenStoryline 做素材理解和剪辑计划，本项目 app/worker 负责业务合同、权限、数据回写和验收。
