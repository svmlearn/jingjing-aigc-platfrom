# 视频剪辑开源项目融合调研需求记录

记录日期：2026-05-11

## 1. 需求背景

用户希望研究并结合两个开源项目的能力，用于后续改造本项目的视频生产、素材理解、自动剪辑和工作台流程。

这次不是单纯做代码接入，而是先把两个项目的核心 knowhow 拆清楚：

- 它们各自如何运行
- 它们如何组织视频生成或剪辑流程
- 它们如何找素材、管理素材、理解素材
- 它们如何做语义识别、画面理解、素材匹配
- 它们如何生成剪辑方案、转场、字幕、音乐和最终视频
- 哪些能力可以被本项目借鉴、复用、重构或产品化

用户身份是产品经理，不希望直接阅读代码细节，而是希望用流程图、模块说明、产品化语言理解项目机制，方便后续设计改造方案。

## 3. 调研目标

本次调研目标是产出一份面向产品经理的“视频项目 knowhow 拆解与融合参考”。

重点不是解释代码怎么写，而是解释：

- 用户输入什么
- 系统经过哪些阶段
- 每个阶段做了什么判断
- 每个阶段依赖哪些数据、模型、素材或外部服务
- 哪些环节是自动化，哪些环节需要人工确认
- 最终视频是怎样一步步被组织、剪辑和渲染出来的
- 两个项目能力如何取长补短，并改造成适合本项目的产品流程

## 4. 必须回答的核心问题

### 4.1 项目如何运行

每个项目都需要解释：

- 项目入口是什么
- 本地如何启动
- 是否有 Web 页面、API 服务、worker、命令行工具
- 依赖哪些环境、模型、配置文件、第三方服务
- 启动后用户能看到什么、能操作什么
- 一次完整任务从哪里开始、在哪里结束

输出方式要避免只写命令，要补充“这一步在产品流程里意味着什么”。

### 4.2 总流程如何走

需要为每个项目画出完整流程：

1. 用户输入需求
2. 系统理解主题或脚本
3. 生成视频结构或分镜
4. 寻找、上传、生成或选择素材
5. 理解素材语义
6. 匹配素材与脚本、分镜或镜头
7. 生成剪辑时间线
8. 添加转场、字幕、配音、BGM、特效
9. 渲染预览视频
10. 支持修订或重新生成
11. 导出最终视频

如果某个项目缺少某些环节，需要明确写出“项目没有做”或“通过外部服务完成”，不要假设它已经具备完整闭环。

### 4.3 如何找素材

需要拆清楚：

- 素材来源是用户上传、本地资源库、线上搜索、爬虫、素材平台、AI 生成，还是项目自带模板
- 素材是否有分类、标签、元数据
- 项目是否支持按主题、关键词、脚本、分镜去检索素材
- 素材如何被缓存、存储、复用
- 素材是否经过质量筛选、去重、版权或可用性判断
- 找不到素材时如何降级

产品视角需要特别关注：

- 素材复用能力能否变成“商家资产库”
- 能否接入本项目已有的 COS 媒体资产
- 是否能服务小红书、抖音内容生产场景

### 4.4 如何理解素材语义

需要拆清楚项目是否具备以下能力：

- 图片理解
- 视频帧理解
- OCR 识别
- ASR 语音转文本
- 画面物体、人物、场景识别
- 镜头切分
- 情绪、风格、氛围识别
- embedding 向量检索
- 标签生成
- 脚本和素材之间的语义匹配

如果项目只是简单依赖文件名、人工标签或固定模板，也要明确说明。

产品视角需要解释：

- 系统到底“理解”了素材的哪些信息
- 哪些理解结果会影响剪辑决策
- 哪些理解结果只是展示或辅助检索
- 哪些环节可替换为更强的视觉理解模型

### 4.5 如何生成剪辑方案

需要拆清楚：

- 项目是否有“剪辑计划”或“时间线”概念
- 一个视频由哪些片段组成
- 每个片段如何决定时长、顺序、画面、文案、字幕、配音和音乐
- 是否支持脚本到镜头、镜头到素材、素材到时间线的映射
- 是否支持自动裁剪、自动拼接、自动缩放、自动适配比例
- 是否支持平台尺寸要求，例如 9:16 竖屏、1:1、16:9
- 是否支持预览后人工修改

需要把技术对象翻译成产品对象，例如：

- timeline = 剪辑时间线
- scene = 分镜/段落
- asset = 素材
- render job = 渲染任务
- template = 视频模板或版式规则

### 4.6 如何做转场、字幕、配音、BGM 和特效

需要拆清楚：

- 转场是固定规则、模板规则、随机规则，还是根据语义自动选择
- 字幕从哪里来，是脚本文案、ASR、人工输入，还是模型生成
- 配音是否自动生成，是否可选音色，是否和字幕对齐
- BGM 如何选择，是否按主题、情绪、节奏匹配
- 是否有音量压低、节拍对齐、淡入淡出等处理
- 是否支持封面、标题、贴纸、动效、品牌元素
- 最终渲染使用什么引擎或服务

产品视角需要说明：

- 哪些是可配置规则
- 哪些是自动推断
- 哪些适合在我们的工作台里开放给用户编辑

## 5. 最终 HTML 展示需求

调研完成后，希望做一个 HTML 展示页面，面向产品经理阅读。

建议页面结构：

1. 总览页：两个项目一句话定位、适合借鉴什么
2. 项目 A 流程图：Pixelle-Video 从输入到导出的全流程
3. 项目 B 流程图：待确认项目从输入到导出的全流程
4. 对比页：素材、语义理解、剪辑、转场、渲染、人工修订能力对比
5. Knowhow 拆解页：把关键机制翻译成产品语言
6. 融合建议页：哪些能力适合放进本项目的视频工作台和 worker
7. 风险页：不能直接复用、依赖重、闭环缺失、版权和成本风险
8. 改造路线页：MVP、增强版、长期版

HTML 需要满足：

- 非工程人员也能看懂
- 用流程图、卡片、泳道图、对比表展示
- 少写代码术语，多写产品流程和业务含义
- 关键代码路径可以附在角落，但不作为主体
- 能明确看到“系统每一步为什么这样做”

## 9. 初步理解的目标结论

用户最终想得到的不是“两个 GitHub 项目分别是什么”，而是：

- 它们背后做视频自动化的完整方法论
