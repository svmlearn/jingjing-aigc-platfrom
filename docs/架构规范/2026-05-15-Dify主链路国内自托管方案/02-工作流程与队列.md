# 02 工作流程与队列

## 摘要

本分册定义 Dify 主链路从内容日历到成员端内容展示的工作流。核心规则是：

```text
前台创建 batch
-> 系统展开 jobs
-> 队列单个消费
-> 调 Dify
-> 解析 final_result_json
-> 落 content_drafts / content_variants
-> 成员端查看图文和视频脚本
```

当前阶段不做多并发、不做自动剪辑、不依赖 Vercel serverless。

## 工作流程

### 1. 创建生成批次

入口：

```text
POST /api/content-generation/batches
```

职责：

- 校验当前用户的商家 / 团队权限。
- 根据日期、天数、成员范围创建 `content_generation_batches`。
- 将日历条目和成员展开为 `content_generation_jobs`。
- 写入每个 job 的 `input_snapshot`。
- 更新 `daily_content_tasks` 里的生成状态为 `pending`。

硬门禁：

- 只允许 owner 为 `active_members` 批量创建。
- 普通成员只能为自己创建。
- `days` 当前不超过 7。
- 创建 batch 只创建队列，不同步等待 Dify。

### 2. 单队列消费 Dify job

入口：

```text
POST /api/content-generation/jobs/run-next
```

当前实现：

- 通过 `CONTENT_GENERATION_WORKER_SECRET` 或登录态校验访问。
- 每次 claim 一个 `pending` job。
- 调用 Dify workflow。
- 成功后落库并标记 job。

当前阶段执行规则：

- 单实例消费。
- 单并发消费。
- 一个 job 结束后再取下一个。
- 不做多 worker 抢占。
- 不做批量 claim。

推荐部署形态：

```text
国内自托管 Node/API
-> cron / systemd timer / 单实例 worker script
-> POST /api/content-generation/jobs/run-next
```

注意：

- 这个消费器不是视频 worker。
- 不要把 Dify 队列逻辑塞进 `video-worker`。
- 服务器拓扑暂不锁定；等腾讯云资源购买后再决定单机混跑或拆机。

### 3. 调用 Dify workflow

调用：

```http
POST {DIFY_BASE_URL}/workflows/run
Authorization: Bearer <DIFY_API_KEY>
Content-Type: application/json
```

当前默认：

```text
DIFY_BASE_URL=https://api.dify.ai/v1
DIFY_WORKFLOW_RESPONSE_MODE=streaming
DIFY_WORKFLOW_VERSION=v3.1
```

请求输入：

- `calendar_task_json`
- `viral_references_json`
- `image_assets_json`
- `fallback_knowledge_text`
- `extra_requirement`
- `member_profile_json`
- `account_profile_json`

硬门禁：

- `DIFY_API_KEY` 只从服务端环境变量读取。
- 日志不得打印 Authorization header。
- `user` 必须能稳定追溯到 job，例如 `member-<memberUserId>` 或 `job-<jobId>`。
- Dify 返回以 `outputs.final_result_json` 为准。
- Dify workflow run id 必须记录到 job。

### 4. 解析和落库

成功路径：

```text
outputs.final_result_json
-> parseDifyFinalJson
-> note variant
-> video_script variant
-> daily_content_tasks 回写
-> content_generation_jobs.succeeded
```

落库要求：

- 一个成功 job 对应一份 `content_drafts`。
- 同一 draft 下至少包含：
  - 小红书 `note` variant。
  - 抖音 `video_script` variant。
- `content_drafts.input_snapshot` 保存 Dify 输入、输出摘要、job id、workflow run id。
- `content_generation_jobs.output_json` 保存可追溯输出。
- `content_generation_jobs.quality_review` 保存质量风险摘要。

硬门禁：

- 关键字段缺失时，不创建可投产 `video_script`。
- `video_script.script_text` 必须非空。
- `video.scenes[]` 必须映射为结构化分镜并持久化。
- Dify 原始总包不进入 `video_edit_jobs.input_payload`。

### 5. 成员端查看

成员端只读已落库结果：

- 图文标题、正文、封面文案、图片。
- 视频脚本、分镜、口播、字幕、拍摄指导。
- 分镜是否要求成员上传素材。

硬门禁：

- 成员只能看到自己所属团队 / 自己任务范围内的内容。
- `requiresUserUpload` 是 UI 控制字段，不作为面向用户的大段解释文本。
- 不展示 Dify debug 原始对象。
- 不展示已删除的旧质量字段。

### 6. 用户确认并点击 AI 剪辑

Dify 队列到这里已经结束。

后续视频链路由用户动作触发：

```text
成员端 / 视频工作台
-> 用户确认脚本
-> reviewStatus = approved
-> 用户点击 AI 剪辑 / 生成视频
-> POST /api/video-edit-jobs
```

硬门禁：

- Dify job 成功后不得自动创建 `video_edit_jobs`。
- 未确认脚本不得创建正式视频任务。
- 点击 AI 剪辑前视频服务器不消费任何任务。

## 状态机

### content_generation_batches

当前状态：

```text
pending
running
completed
completed_with_errors
canceled
```

规则：

- 任一 job 开始后，batch 可进入 `running`。
- 全部 job 成功后进入 `completed`。
- 存在失败但队列已处理完，进入 `completed_with_errors`。
- 用户取消后进入 `canceled`，不再 claim 未开始 job。

### content_generation_jobs

当前状态：

```text
pending
running
succeeded
failed_retryable
failed_manual
canceled
```

失败分类：

- `failed_retryable`：Dify 网络失败、timeout、429、5xx、临时不可用。
- `failed_manual`：schema 缺关键字段、Dify key 无效、输入上下文缺失、反复重试仍失败。

当前阶段：

- 可先保守地人工重试。
- 不引入复杂退避调度。
- 不做多并发重试。

## 工作边界

app / API 负责：

- 创建 batch / jobs。
- 权限判断。
- 组织 Dify inputs。
- 调 Dify API。
- 解析 final JSON。
- 写业务表。
- 展示 job 进度和内容结果。

content-generation 消费器负责：

- 顺序触发 `run-next`。
- 保证同一时刻只处理一个 job。
- 记录日志和错误。

不负责：

- 不渲染视频。
- 不调用 OpenStoryline。
- 不上传成片。
- 不修改已确认脚本。

video-worker 负责：

- 只消费 `video_edit_jobs`。
- 不消费 `content_generation_jobs`。
- 不调用 Dify。
- 不理解 Dify 原始 JSON。

## 检查功能

队列检查：

- 是否存在长期 `running` 的 Dify job。
- 是否存在 `pending` 堆积但消费器未运行。
- 是否存在 `succeeded` job 缺 draft / variant。
- 是否存在 `failed_retryable` 未被记录错误类型。
- 是否存在重复 idempotency key 的有效 job。

日志检查：

- 每次 run-next 记录 job id、workflow run id、耗时、状态。
- 不记录 Dify key。
- 不记录完整私有 COS 签名 URL。
- Dify 原始输出如需留痕，进入 DB JSON 字段，不直接刷到通用日志。

## 纠错功能

- 消费器挂掉：重启单实例消费器，不批量补跑。
- Dify timeout：标记 `failed_retryable`，人工或后续脚本单条重试。
- schema 失败：保存原始输出，进入 adapter 修复。
- 落库一半失败：job 保留失败状态，避免前台展示半成品。
- batch 数量不对：从 `content_generation_jobs` 反算并修正 batch 统计。

## 板块验收

通过标准：

- 创建 batch 后只产生 generation jobs，不调用 video worker。
- `run-next` 一次只处理一个 job。
- Dify 成功后只产生 draft / variants / task 回写。
- 成员端能看到脚本。
- 未点击 AI 剪辑前不存在对应 `video_edit_jobs`。
