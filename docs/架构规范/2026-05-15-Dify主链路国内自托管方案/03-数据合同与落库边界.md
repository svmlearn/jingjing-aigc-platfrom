# 03 数据合同与落库边界

## 摘要

本分册定义 Dify final JSON 如何进入数据库，以及它和视频执行合同之间的隔离关系。

核心原则：

```text
Dify JSON 是内容生成结果
content_drafts / content_variants 是业务真相源
video_edit_jobs.input_payload 是视频执行合同
```

三者不能混用。

## Dify final_result_json 合同

当前主线只接受 V3.1 精简结构：

```json
{
  "status": "passed",
  "article": {},
  "video": {},
  "quality": {
    "riskTerms": []
  }
}
```

允许进入主业务输出的顶层字段：

- `status`
- `article`
- `video`
- `quality`

必须拒绝或转 legacy 的旧字段：

- `workflowVersion`
- `articlePackage`
- `titleStrategy`
- `videoScript`
- `memberDelivery`
- `workerDelivery`
- `qualityReview`
- `trace`
- `saveHints`
- `debug`
- `quality.status`
- `quality.pass`
- `quality.blockingReasons`
- `quality.missingInputs`

说明：

- 旧 fixture / adapter 如果仍需要兼容，必须先转换成 V3.1 精简结构。
- `workflow_run_id` 由 Dify API 响应外层记录到 job，不回灌进 final JSON 主输出。
- debug / trace 可以保存在 `input_snapshot` 或内部日志字段，但不作为成员端主输出。

## 图文落库合同

Dify `article` 映射到 `note` variant：

| Dify 字段 | 落库位置 | 说明 |
| --- | --- | --- |
| `article.title` | `content_variants.title` | 图文标题 |
| `article.copyText` | `content_variants.body_text` | 图文正文 |
| `article.coverCopy` | `content_drafts.input_snapshot.difyFinalJson.article.coverCopy` | 封面文案，当前可先放 snapshot |
| `article.images[].cosPath` | 成员端 imageAssets / snapshot | 可转 `/api/media/cos-preview` 或后续资产关系 |
| `article.images[].role` | snapshot / imageAssets role | 控制封面图、正文图排序 |

硬门禁：

- `article.title` 非空。
- `article.copyText` 非空。
- `article.images` 可为空，但不能因空图片导致落库失败。
- 图片缺失不恢复旧的 `imageBriefIfMissing` 主字段；缺素材作为素材池 / 运营待办处理。

## 视频脚本落库合同

Dify `video` 映射到 `video_script` variant：

| Dify 字段 | 落库位置 | 说明 |
| --- | --- | --- |
| `video.storyOutline` | `script_text` 和 snapshot | 故事线 |
| `video.estimatedDuration` | `script_text` 和 snapshot | 预计时长 |
| `video.bgm` | `script_text` / production config 建议 | BGM 方向 |
| `video.toneOfVoice` | `script_text` / snapshot | 口吻 |
| `video.scenes[]` | `content_variants.production_scenes` | 结构化分镜 |
| `video.scenes[].voiceover` | `script_text` / `production_scenes.voiceover` | 口播 |
| `video.scenes[].subtitle` | `production_scenes.subtitle` | 字幕 |
| `video.scenes[].assetQuery` | `production_scenes.materials` 或 scene query | 素材召回线索 |

当前必须补齐的真实表字段：

```sql
content_variants.production_scenes jsonb not null default '[]'::jsonb
```

如果不加该字段，Dify 的结构化分镜只会留在 `script_text` 或 snapshot 中，后续创建视频任务时会退化成文本关键词提取，影响素材匹配和 ProductionDirective 质量。

## content_drafts.input_snapshot

每个 Dify 成功 job 创建 draft 时，`input_snapshot` 必须保存：

- `source = dify_daily_task_generation`
- `contentGenerationJobId`
- `batchId`
- `dailyTaskId`
- `taskDate`
- `calendarItemId`
- `workflowProvider = dify`
- `workflowVersion`
- `difyWorkflowRunId`
- `difyInputs`
- `difyFinalJson`
- `difyRawOutputs`，可选
- `memberProfileSnapshot`
- `accountProfileSnapshot`
- `materialRefs`
- `knowledgeRefs`

硬门禁：

- snapshot 是追溯用，不是 worker input。
- snapshot 可以包含 Dify 原始输出，但不得原样复制到 `video_edit_jobs.input_payload`。
- snapshot 不得包含 `DIFY_API_KEY`、COS secret、数据库连接串。

## content_generation_jobs

job 必须记录：

- `input_snapshot`
- `output_json`
- `quality_review`
- `dify_workflow_run_id`
- `content_draft_id`
- `article_variant_id`
- `video_variant_id`
- `status`
- `error_message`

硬门禁：

- `status = succeeded` 时，至少有 `content_draft_id` 和 `video_variant_id`。
- `failed_manual` 时必须有可读错误。
- `failed_retryable` 时必须能区分 timeout / 429 / 5xx / 网络类错误。
- 不允许吞掉错误后把 job 标为 succeeded。

## video_edit_jobs.input_payload 隔离

AI 剪辑执行合同只能由 app payload builder 生成。

允许字段：

- `source`
- `executionMode`
- `script`
- `productionDirective`
- `productionConfig`
- `materialContext`
- `input_assets`
- `assembled_from_owner_type`
- `assembled_from_owner_id`
- `assembled_at`
- `render_mode`
- `revisionContext`，制作修订时可选

禁止字段：

- `outputs`
- `final_result_json`
- `article`
- `video`
- `quality`
- `difyRawOutputs`
- `difyInputs`
- `workflowRun`
- `workflowVersion`
- `debug`

硬门禁：

- Dify 来源和非 Dify 来源都必须复用同一个 `buildVideoEditJobInputPayload`。
- worker 不得通过 `workflowProvider` 判断如何执行。
- worker 只看 `script`、`productionDirective`、`productionConfig`、`materialContext`、`input_assets`。

## 旧链路兼容

保持不变：

- 旧脚本制作 agent 生成的 `video_script` 可以继续确认和剪辑。
- 手工创建 / 测试草稿可以继续确认和剪辑。
- 非 Dify `video_script` 不应被 Dify schema gate 阻断。

变化：

- 新生成默认逐步走 Dify。
- Dify 失败或关闭时，旧链路仍可作为兼容辅路。
- 最终进入 video worker 的合同完全一致。

## 工作边界

Dify adapter 负责：

- schema gate。
- 字段映射。
- 质量风险压缩。
- 创建 note / video_script variant 的输入。

content draft repository 负责：

- 真实持久化 draft。
- 真实持久化 variants。
- 真实读取 `production_scenes`。

video job payload builder 负责：

- 校验 approved script。
- 读取结构化分镜。
- 生成 scene asset queries。
- 规范化 COS input assets。
- 生成 worker 合同。

worker 不负责：

- 解析 Dify JSON。
- 修正 Dify schema。
- 判断 Dify 质量。
- 重新生成脚本语义。

## 检查功能

建议测试：

- Dify normal fixture -> note + video_script。
- Dify empty scenes -> schema failed，不创建可投产 variant。
- Dify blocked / invalid status -> 不创建可投产视频。
- Dify article images empty -> 仍可创建图文和视频脚本。
- Dify source video_script approve -> create video job。
- create video job payload 不包含 Dify 顶层字段。
- 非 Dify video_script approve -> create video job 仍通过。

数据库检查：

```sql
select id
from content_variants
where variant_type = 'video_script'
  and coalesce(script_text, '') = '';
```

```sql
select id
from content_variants
where variant_type = 'video_script'
  and jsonb_array_length(coalesce(production_scenes, '[]'::jsonb)) = 0;
```

## 纠错功能

- 旧 adapter 要求 `quality.pass`：已废弃旧测试并删除旧实验入口。
- production scenes 丢失：补 migration 和 repository 映射。
- Dify 原始字段进入 video payload：阻断测试，回退到 adapter 层修。
- job succeeded 但没有 variant：标记数据不一致，补偿落库或回滚状态。
- 重复生成：按 idempotency key 或 workflow run id 排查，不覆盖旧版本。

## 板块验收

通过标准：

- Dify V3.1 精简 JSON 是当前唯一主合同。
- 真实 DB 能保存结构化 `production_scenes`。
- Dify 成功只落内容，不自动剪辑。
- 用户点击 AI 剪辑后生成的 payload 与旧链路 payload 外壳一致。
