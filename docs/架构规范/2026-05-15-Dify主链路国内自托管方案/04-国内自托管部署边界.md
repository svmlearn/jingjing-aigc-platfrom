# 04 国内自托管部署边界

## 摘要

本分册定义 Dify 主链路未来离开 Vercel 后的国内自托管部署边界。

当前只锁定方向，不锁定具体拓扑：

```text
腾讯云大陆优先
自托管 Next.js / Node API
国内 PostgreSQL
国内 COS
独立 Dify 队列消费入口
video-worker / OpenStoryline / FireRed 仍走既有容器链路
```

服务器是单机混跑还是拆机，等资源购买后再决定。

## 目标结构

目标生产结构：

```text
备案域名 / 国内 IP
-> Nginx / HTTPS
-> Next.js app + Node API
-> 国内 PostgreSQL
-> 国内腾讯 COS
-> content-generation 队列消费器
-> video-worker / openstoryline-engine / firered-openstoryline
```

保留为历史参考：

- Vercel
- Supabase Cloud
- 新加坡服务器

这些可以继续用于开发、旧 staging、回滚参考，但不作为国内正式运行前提。

## 云资源决策

当前默认：

- 云厂商：腾讯云大陆优先。
- 对象存储：腾讯 COS。
- 数据库：国内 PostgreSQL，优先同云同地域或低延迟区域。
- 服务器：国内 Linux，Ubuntu 22.04 优先。

暂不锁定：

- 单机混跑还是拆 Web/API 和 worker。
- 是否同机运行 content-generation 消费器。
- 是否引入 PM2 / systemd / Docker Compose 的最终方式。

硬门禁：

- 不跨云随意混搭服务器、对象存储、数据库，除非有明确成本和排障理由。
- 生产环境不依赖 Vercel `maxDuration`。
- 国内正式域名接入前必须考虑 ICP 备案。
- 当前阶段不因未备案阻塞 IP 级技术验证。

## 服务拆分边界

### Next.js / Node API

负责：

- 商家端 / 成员端页面。
- 登录与权限。
- 创建 Dify batch / jobs。
- 暴露 `run-next` 入口。
- 解析 Dify 输出并落库。
- 创建视频任务。
- 成片预览 / 下载签名。

不负责：

- 长时间渲染视频。
- 直接执行 OpenStoryline。
- 在前端持有 Dify key 或 COS 永久 key。

### content-generation 队列消费器

负责：

- 单实例顺序触发 `POST /api/content-generation/jobs/run-next`。
- 记录本地日志。
- 不做多并发。

可选形态：

- systemd service + timer。
- cron。
- 独立 Node/Python 脚本。
- Docker service。

硬门禁：

- 同一环境只启动一个消费器实例。
- 不批量 claim。
- 不直接写数据库绕过 API，除非后续专门改为内部 worker SDK。
- 不调用 OpenStoryline。

### video-worker

负责：

- 轮询 / claim `video_edit_jobs`。
- 校验 `input_payload`。
- 调 OpenStoryline / FireRed。
- 上传结果到 COS。
- 回写 `video_edit_jobs` 和 `asset_objects`。

不负责：

- Dify workflow 调用。
- 内容日历 batch / job。
- Dify JSON schema gate。

## 环境变量

### Dify

必需：

```text
DIFY_API_KEY
DIFY_BASE_URL
DIFY_WORKFLOW_RESPONSE_MODE
DIFY_WORKFLOW_TIMEOUT_SECONDS
DIFY_WORKFLOW_VERSION
CONTENT_GENERATION_WORKER_SECRET
```

默认建议：

```text
DIFY_BASE_URL=https://api.dify.ai/v1
DIFY_WORKFLOW_RESPONSE_MODE=streaming
DIFY_WORKFLOW_VERSION=v3.1
```

硬门禁：

- `DIFY_API_KEY` 不写入 `.env.example` 的真实值。
- 不在文档中记录真实 key。
- 不在日志中输出 header。
- `CONTENT_GENERATION_WORKER_SECRET` 必须是强随机值。

### 数据库

国内目标：

```text
APP_DATABASE_URL / DATABASE_URL / WORKER_DATABASE_URL
```

过渡环境可能仍存在：

```text
SUPABASE_DB_URL
SUPABASE_SERVICE_ROLE_KEY
```

硬门禁：

- 国内正式链路应逐步从 Supabase Cloud 迁到国内 PostgreSQL。
- 权限最终收口在 Node API 层和数据库策略层。
- 数据库连接串不写入仓库。

### COS / 视频 worker

必需：

```text
COS_SECRET_ID
COS_SECRET_KEY
COS_BUCKET
COS_REGION
OPENSTORYLINE_BASE_URL
FIRERED_OPENSTORYLINE_BASE_URL
FIRERED_PROVIDER_KEY
OPENSTORYLINE_LLM_*
OPENSTORYLINE_VLM_*
TTS_*
```

硬门禁：

- 浏览器上传只能拿临时凭证。
- 服务器永久密钥只在服务端。
- 成片预览 / 下载必须走服务端签名或稳定 app route。

## 部署流程

### Phase 0：接口和本地合同

目标：

- 本地或 staging 证明 Dify -> variant -> AI 剪辑合同成立。
- 不要求国内资源已经买好。

验收：

- mock Dify job 成功。
- 真实 Dify 1 条 smoke 可选。
- payload 快照不含 Dify 原始总包。

### Phase 1：国内服务器 readiness

目标：

- 国内服务器能跑 app / API。
- 国内 PostgreSQL 可连接。
- 国内 COS 可上传 / 下载。
- content-generation 单队列消费器可运行。

验收：

- `/api/health` 或等价 health 可访问。
- Dify env 脱敏检查 present。
- COS roundtrip 成功。
- 数据库 migration 成功。

### Phase 2：Dify 真实链路

目标：

- 国内自托管 API 调真实 Dify。
- job 落库。
- 成员端可查看。

验收：

- `content_generation_jobs.status = succeeded`
- `dify_workflow_run_id` 非空。
- note / video_script 变体存在。
- 未自动创建 `video_edit_jobs`。

### Phase 3：用户触发 AI 剪辑

目标：

- 用户确认脚本。
- 点击 AI 剪辑。
- video-worker 执行。

验收：

- `video_edit_jobs` 只在点击后出现。
- worker 进入 OpenStoryline。
- 成片回 COS。
- 页面可预览 / 下载。

## 运维检查

部署后检查：

```bash
docker compose ps
```

脱敏 env 检查：

```bash
awk 'BEGIN{FS="="} /^[A-Za-z_][A-Za-z0-9_]*=/ {
  key=$1;
  val=substr($0,index($0,"=")+1);
  if (key ~ /^DIFY_/ || key == "CONTENT_GENERATION_WORKER_SECRET") {
    print key "=" (val == "" ? "missing" : "present")
  }
}' .env
```

禁止：

- `cat .env` 贴到聊天、文档、工单。
- 把服务器密码写进 handoff。
- 把 provider key 写进 progress。

## 纠错功能

- 国内 API 访问慢：先查 Nginx / Node / DB / COS 分段耗时，不直接归因 Dify。
- Dify 调用慢：记录 workflow run id 和耗时，保留 streaming / polling 证据。
- COS 上传失败：区分 CORS、STS、bucket、region、key prefix。
- video-worker 空跑：检查是否真的创建了 `video_edit_jobs`，不要查 Dify job。
- Dify 队列不动：检查 content-generation 消费器，不查 video-worker。

## 板块验收

通过标准：

- 文档不再要求 Vercel。
- 文档不锁死服务器拓扑。
- Dify 队列和 video-worker 是两个不同职责。
- 腾讯云大陆是默认路线，但保留资源购买后补细节。
