# 06 测试、验收、纠错与上线

## 摘要

没有通过本分册，不进入国内 staging；没有国内真实链路证据，不声明生产可用。

验收不是只看 Dify 是否返回文本，而是看完整业务链路：

```text
创建 batch
-> 队列消费 Dify
-> 落库
-> 成员端看到脚本
-> 用户确认
-> 点击 AI 剪辑
-> video-worker 出片
-> COS / DB 回写
```

## 测试矩阵

### A. Dify API 合同

硬门禁：

- `DIFY_API_KEY` 只在服务端。
- `response_mode` 当前默认 streaming。
- 返回必须能提取 `outputs.final_result_json`。
- 记录 `workflow_run_id`。

检查：

- mock final JSON。
- 真实 Dify 1 条 smoke。
- Dify timeout。
- Dify 5xx / 429。
- Dify 返回不含 final_result_json。

纠错：

- API 失败：`failed_retryable`。
- key 无效：`failed_manual`。
- final JSON 缺失：`failed_manual`，保留 raw outputs。

### B. final JSON schema

硬门禁：

- 顶层只允许 `status/article/video/quality`。
- 拒绝旧字段回流。
- `video.scenes[]` 非空。
- scene 必须有 `sceneNo`、`timeRange`、`durationSec`、`title`、`visualDescription`。

检查：

- 正常 fixture。
- 空 scenes fixture。
- 旧 V3.0 总包 fixture。
- 缺 images fixture。
- 风险词 fixture。

纠错：

- 旧字段：legacy 转换或 schema failed。
- 缺关键字段：不创建可投产 `video_script`。
- 缺图片：不阻断视频脚本落库。

### C. 落库

硬门禁：

- 成功 job 有 draft。
- 成功 job 有 note variant。
- 成功 job 有 video_script variant。
- `video_script.script_text` 非空。
- `video_script.production_scenes` 持久化。

检查：

- 查询 `content_generation_jobs`。
- 查询 `content_drafts.input_snapshot`。
- 查询 `content_variants`。
- 刷新页面后仍能读到脚本和分镜。

纠错：

- variant 缺失：job 不得标记 succeeded。
- scenes 丢失：补 migration / repository。
- snapshot 缺追溯信息：补 input snapshot。

### D. 队列

硬门禁：

- 当前只单队列单并发。
- `run-next` 一次只处理一个 job。
- 不批量 claim。
- 不依赖 Vercel 长函数作为正式目标。

检查：

- 创建 3 个 jobs，连续调用 3 次 `run-next`。
- 每次只推进 1 个 job。
- 消费器停止时 pending 保留。
- 消费器恢复后继续处理。

纠错：

- 多个 job 同时 running：检查 claim 逻辑和消费器实例数。
- job 卡 running：人工标记 retryable 或补 stale sweep。
- batch 计数错：从 jobs 重算。

### E. 视频触发

硬门禁：

- Dify 成功后没有 `video_edit_jobs`。
- 用户确认脚本前不能创建 `video_edit_jobs`。
- 用户点击 AI 剪辑后才创建。
- payload 不含 Dify 原始总包。

检查：

- Dify succeeded 后查 video job 数量。
- 未 approved 调 `POST /api/video-edit-jobs`，应失败。
- approved 后点击，创建 pending job。
- payload 快照检查 forbidden fields。

纠错：

- 自动创建 video job：立即阻断。
- 未确认也创建：修 app gate。
- payload 污染：修 payload builder 或 adapter。

### F. video-worker / OpenStoryline

硬门禁：

- worker payload 校验失败不进入渲染。
- final video 缺失不标记 succeeded。
- 成功结果必须回写 COS 和 `asset_objects`。

检查：

- 真实素材 job。
- 无素材脚本 fallback job，如允许。
- COS 下载失败。
- OpenStoryline 失败。
- 上传结果失败。

纠错：

- download / engine / upload 分层记录。
- retry 不重复插入不可区分 asset。
- 成功后预览 / 下载重新签名。

### G. 国内自托管

硬门禁：

- API 在国内服务器可访问。
- 数据库在国内 PostgreSQL 或目标数据库。
- COS 在国内 bucket。
- Dify key present 但不打印。
- content-generation 消费器可启动和停止。

检查：

- `/api/health`。
- DB migration。
- COS roundtrip。
- Dify env 脱敏检查。
- `docker compose ps` 或服务状态。

纠错：

- API 不通：查 Nginx / firewall / Node。
- DB 不通：查连接串 / 白名单 / SSL。
- COS 不通：查 region / bucket / CORS / STS。
- Dify 不通：查 outbound network / key / base URL。

## Completion Gate

只有同时满足以下条件，才能说“Dify 到 AI 剪辑国内主链路通过”：

1. 国内自托管 API 能创建 Dify batch。
2. 单队列消费器能消费 1 个真实 Dify job。
3. Dify final JSON 成功解析。
4. `content_drafts` 和 `content_variants` 落库。
5. `video_script` 有非空脚本和结构化分镜。
6. 成员端能查看该脚本。
7. Dify 成功后没有自动创建 `video_edit_jobs`。
8. 用户确认脚本后才能创建视频任务。
9. 用户点击 AI 剪辑后创建 `video_edit_jobs`。
10. video-worker 领取并调用 OpenStoryline/FireRed。
11. 成片上传 COS。
12. `video_edit_jobs.status = succeeded`。
13. `asset_objects` 有成片资产。
14. 前台能预览 / 下载。
15. progress 文档记录证据。

## 上线顺序

1. 先补数据合同：`production_scenes` migration 和 repository 映射。
2. Dify V3.1 mapper 已统一为当前主线，旧 adapter 口径已清理。
3. 跑 mock Dify 到落库测试。
4. 跑真实 Dify 1 条 smoke。
5. 接单队列消费器。
6. 国内服务器接口部署。
7. 用户确认脚本到 video job 的门禁测试。
8. video-worker 真实出片。
9. 写 progress / handoff。
10. 才能考虑国内 staging 给产品验收。

## 回滚策略

- Dify adapter 异常：关闭 Dify feature flag，保留旧脚本链路。
- Dify 队列异常：停 content-generation 消费器，不影响 video-worker。
- video-worker 异常：暂停 AI 剪辑，不影响 Dify 内容生成。
- 国内部署异常：回到旧 staging 验证，不声明国内可用。
- schema migration 异常：停止写入新 Dify job，先修 repository 和迁移。

## 板块验收

通过标准：

- 所有测试都有命令或可复现步骤。
- 所有失败都有状态和纠错动作。
- Completion Gate 没过时，不写“已完成”。
- 文档明确区分 Dify 链路通过和视频出片通过。
