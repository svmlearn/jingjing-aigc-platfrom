# 2026-05-26 素材标签与检索路由打法

## 1. 当前结论

当前素材库不是靠自由文本标签作为主路由，而是靠一组结构化字段决定“这个素材能被谁用”：

| 字段 | 作用 | 当前取值 |
| --- | --- | --- |
| `platform` | 内容平台来源 | `xiaohongshu` / `douyin` |
| `materialType` | 素材内容形态 | `article` / `video` |
| `sourceKind` | 素材来源 | `uploaded` / `benchmark` |
| `usageType` | 素材用途标签 | `text_knowledge` / `viral_reference` / `image_asset` / `video_asset` |
| `retrievalTargets` | 可进入的检索池 | `copy_context` / `script_context` / `article_image_asset` / `video_edit_asset` |
| `status` | 可用状态 | `ready` / `parsing` / `failed` / `archived` |

核心打法：

- 爆款/对标内容是“文案与脚本参考”，不是剪辑素材。
- 项目图片素材只给图文配图或后续生图参考。
- 项目视频素材只给 AI 剪辑 worker 使用。
- `status=failed` 或 `status=archived` 的素材不进入任何检索池。
- `image_asset` 和 `video_asset` 必须 `status=ready` 才进入对应检索池。

## 2. 四类用途标签

### 2.1 `viral_reference`

用于爆款内容、对标内容、用户手动录入的内容链接。

典型来源：

- 小红书笔记链接。
- 抖音视频链接。
- TikHub 抓取的对标内容。
- 用户通过素材中心录入的平台内容链接。

字段打法：

```json
{
  "sourceKind": "benchmark",
  "usageType": "viral_reference",
  "retrievalTargets": ["copy_context", "script_context"],
  "status": "ready"
}
```

可用于：

- 图文标题、正文结构、CTA、话题标签参考。
- 视频脚本 hook、口播结构、分镜节奏参考。

不可用于：

- 图文配图文件。
- AI 剪辑 worker 的视频输入素材。

### 2.2 `text_knowledge`

用于纯文本知识。当前 `MaterialUsageType` 已包含该值，但用户知识库主链路更多走 `knowledge_documents / knowledge_chunks`，不是素材库主入口。

字段打法：

```json
{
  "usageType": "text_knowledge",
  "retrievalTargets": ["copy_context", "script_context"],
  "status": "ready"
}
```

可用于：

- 图文文案生成。
- 视频脚本生成。
- 咨询台读取用户知识库和平台方法论。

不可用于：

- 图文图片资产。
- AI 剪辑 worker 视频资产。

### 2.3 `image_asset`

用于项目图片素材。

典型来源：

- 用户信息 / 用户知识库里的项目媒体素材上传入口。
- 户型图、样板间图、项目实景图、配套图。

字段打法：

```json
{
  "materialCategory": "project_media_asset",
  "assetType": "image",
  "materialType": "article",
  "sourceKind": "uploaded",
  "usageType": "image_asset",
  "retrievalTargets": ["article_image_asset"],
  "status": "ready"
}
```

可用于：

- 图文配图。
- 后续生图参考。

不可用于：

- 视频脚本文案参考。
- AI 剪辑 worker 的视频素材输入。

### 2.4 `video_asset`

用于项目视频素材。

典型来源：

- 用户信息 / 用户知识库里的项目媒体素材上传入口。
- 项目实拍、样板间、周边配套、转场 B-roll、销售口播片段。

字段打法：

```json
{
  "materialCategory": "project_media_asset",
  "assetType": "video",
  "materialType": "video",
  "sourceKind": "uploaded",
  "usageType": "video_asset",
  "retrievalTargets": ["video_edit_asset"],
  "status": "ready"
}
```

可用于：

- AI 剪辑 worker 的素材检索。
- 按脚本分镜匹配画面素材。

不可用于：

- 图文配图。
- 文案/脚本参考内容。

当前 main 注意点：

- 项目视频素材创建时默认 `status=parsing`。
- `video_asset` 在 `status=parsing` 时不会进入 `video_edit_asset` 检索池。
- 只有状态变为 `ready` 后，才应该具备 `retrievalTargets=["video_edit_asset"]`。

## 3. 检索池规则

| `retrievalTarget` | 消费方 | 接收的 `usageType` | 说明 |
| --- | --- | --- | --- |
| `copy_context` | 图文生成 | `text_knowledge`, `viral_reference` | 文案、标题、结构、表达参考 |
| `script_context` | 视频脚本生成 | `text_knowledge`, `viral_reference` | hook、口播、分镜节奏参考 |
| `article_image_asset` | 图文配图 | `image_asset` | 项目图片素材 |
| `video_edit_asset` | AI 剪辑 worker | `video_asset` | 项目视频素材 |

禁止混用：

- `viral_reference` 不进入 `video_edit_asset`。
- `image_asset` 不进入 `script_context`。
- `video_asset` 不进入 `copy_context` 或 `article_image_asset`。
- `parsing / failed / archived` 的图片或视频资产不进入实际资产检索池。

## 4. 入库字段落点

素材库当前复用 `source_items` 表。

入库时会写入：

```text
source_items.structure_summary
source_items.trace_payload
source_items.engagement_snapshot
source_items.body_text / script_text
source_items.is_selected_for_rewrite
```

关键字段会重复写在 `structure_summary` 和 `trace_payload` 中，便于列表读取、检索和后续兼容：

```json
{
  "structure_summary": {
    "materialType": "video",
    "materialStatus": "ready",
    "materialSourceKind": "uploaded",
    "materialUsageType": "video_asset",
    "retrievalTargets": ["video_edit_asset"]
  },
  "trace_payload": {
    "materialLibrary": true,
    "materialSourceKind": "uploaded",
    "materialUsageType": "video_asset",
    "retrievalTargets": ["video_edit_asset"],
    "materialAnalysis": {
      "materialCategory": "project_media_asset",
      "assetType": "video",
      "fileName": "example.mp4",
      "mimeType": "video/mp4",
      "userNote": "项目大门、沙盘、样板间"
    }
  }
}
```

`trace_payload.materialLibrary=true` 是素材库列表筛选的关键条件。

## 5. 用户填写标签的建议格式

当前代码没有独立的自由标签字段，用户在项目媒体素材上传时主要填写：

- 标题 `title`
- 说明 `note`
- 文件信息 `fileName / mimeType / sizeBytes`
- 系统自动识别的 `assetType=image|video`

如果需要在 `note` 里人工补充标签，推荐使用中文逗号、顿号、空格都能让检索命中，但为了后续可机器化解析，建议统一写成逗号分隔：

```text
项目大门, 沙盘讲解, 样板间, 周边商圈, 低总价, 刚需客户
```

不建议写成：

```text
#项目大门#沙盘讲解#样板间
```

原因：

- 当前检索会对文本做通用分词和中英文 token 命中，不依赖 `#`。
- 逗号分隔更容易后续转成结构化数组。
- 空格也能被检索切词，但中文短语之间用逗号更清楚。

## 6. 当前上传入口的自动打法

### 6.1 普通链接素材

接口：

```text
POST /api/materials
```

输入：

```json
{
  "platform": "xiaohongshu",
  "url": "https://..."
}
```

当前自动标记为：

```json
{
  "sourceKind": "uploaded",
  "usageType": "viral_reference",
  "retrievalTargets": ["copy_context", "script_context"]
}
```

### 6.2 项目媒体素材

接口：

```text
POST /api/materials/project-media
```

图片素材自动标记：

```json
{
  "materialCategory": "project_media_asset",
  "assetType": "image",
  "usageType": "image_asset",
  "retrievalTargets": ["article_image_asset"],
  "status": "ready"
}
```

视频素材当前 main 自动标记：

```json
{
  "materialCategory": "project_media_asset",
  "assetType": "video",
  "usageType": "video_asset",
  "retrievalTargets": [],
  "status": "parsing"
}
```

说明：

- 代码创建视频项目素材时会传入期望的 `retrievalTargets=["video_edit_asset"]`。
- 但路由归一化会因为 `status=parsing` 把实际检索目标过滤为空。
- 这意味着视频文件物理上传成功后，如果没有后续索引或 ready 回写，页面仍会表现为“识别中”，worker 也不会把它当作可用素材。

## 7. 检索排序规则

素材检索先按 `retrievalTarget` 过滤，再按分数排序。

主要加分项：

| 加分项 | 说明 |
| --- | --- |
| 命中 `retrievalTarget` | 有明确目标时基础加分最高 |
| `usageType` 适配 | 例如 `video_edit_asset` 命中 `video_asset` |
| query 完整命中 | 查询词完整出现在素材标题、说明、分析字段中 |
| query 分词命中 | 中文会切 2-4 字短词，提高短语召回 |
| 来源优先 | 图文/视频资产检索时优先用户上传素材；文案/脚本参考时对标素材优先 |
| 最近入库 | 新上传素材有轻量加分 |

检索文本来源包括：

- `title`
- `description`
- `creatorName`
- `engagementLabel`
- `platform`
- `materialType`
- `sourceKind`
- `usageType`
- `status`
- `retrievalTargets`
- `analysisPayload` 内的字符串和数字字段

## 9. 素材包人工标签打法

本节参考本地素材包：

```text
D:\Desktop\测试素材\cos素材库入库包_20260522_厂房招商_标签修正版_20260524_180838
```

该包体现的是“商家团队素材库 V1”的人工入库打法：先把素材库路由字段打对，再把单条素材的检索标签打准。前者决定素材能不能被 worker 用，后者决定 worker 查某个画面时会不会误召回。

结构化切分、`merchant_media_assets / merchant_media_clips` JSON、审核 CSV、导入 SQL 和未来自动打标门禁，以 `2026-05-26-商家视频素材切分与标签数据标准.md` 为准。本节保留素材路由和人工标签思路。

### 9.1 入库范围先分清

同一个素材包里可以同时存在“商家素材库素材”和“成员上传素材”，但两者不能混入同一条入库链路。

厂房招商修正版里的边界是：

- 27 条商家素材进入 `merchant_media_assets / merchant_media_clips`。
- 3 条口播素材只作为 `member_upload_only`，记录在 `metadata/member_upload_assets.*`。
- 成员口播素材不写入 `merchant_media_assets / merchant_media_clips`，也不作为商家团队素材库公共资产。

对应到当前素材库路由：

```json
{
  "asset_scope": "merchant_media_library",
  "usageType": "video_asset",
  "retrievalTargets": ["video_edit_asset"],
  "status": "ready"
}
```

成员上传口播素材应作为本次视频任务输入，而不是团队素材库资产：

```json
{
  "asset_scope": "member_upload_only",
  "importRule": "Do not import into merchant_media_assets / merchant_media_clips"
}
```

### 9.2 标签只描述“画面可见内容”

单条 clip 的标签按 Pexels 逻辑处理：优先描述画面里能直接看到的主体、场景、设施、动作、构图用途。

应该写进单条 clip 的内容：

- 可见空间：一楼、六楼、架空层、园区入口、周边道路。
- 可见设施：消防管线、消防栓、配电箱、电梯、食堂、宿舍、公寓、停车位。
- 可见构图：大开间、柱网、通道纵深、楼梯视角、外景扫拍、标识特写。
- 可见人物：无明显人物、少量远景人物、真人入镜。

不要把整盘业务卖点都塞到每条 clip：

- `2000 平米`
- `到楼板 5.56 米`
- `到梁 5 米`
- `一个厂 3 个车位`
- `两栋宿舍 + 一栋公寓`
- `近地铁站`
- `近物流园`
- `可生产 / 可仓储 / 可办公改造`

这些业务事实应该留在包级 `factoryFacts`、项目资料、asset metadata 或脚本文案知识里。只有当画面能直接证明该事实时，才允许成为单条 clip 的强检索标签。

### 9.3 用 `role:` 标记素材角色

`role:` 用来告诉检索和剪辑系统“这条素材属于哪一类画面资产”。厂房招商修正版当前使用的角色包括：

```text
role:factory_first_floor
role:factory_mezzanine
role:factory_sixth_floor
role:traffic_location
role:park_entrance
role:park_amenity
role:environment_mountain
```

命名原则：

- `role:` 是稳定分类，不写一次性口语。
- 同一类画面复用同一个 `role:`，不要一会写“一楼厂房”，一会写“厂房一层空间”。
- `role:` 不替代中文检索标签，仍要保留可读的中文场景词。

示例：

```text
role:factory_first_floor、一楼厂房、厂房内部、绿色环氧地坪、柱网
```

### 9.4 用 `lens:` 标记剪辑用途

`lens:` 用来告诉 worker “这条素材适合怎么用”。厂房招商修正版当前使用的用途包括：

```text
lens:primary_showcase
lens:detail_proof
lens:amenity_proof
lens:environment_context
lens:environment_proof
lens:interior_showcase
lens:location_context
lens:opening_context
lens:signage_proof
lens:structure_detail
lens:transition_detail
```

常用含义：

| `lens` | 用法 |
| --- | --- |
| `lens:primary_showcase` | 主展示镜头，例如一楼大开间、柱网纵深 |
| `lens:detail_proof` | 细节证明镜头，例如消防栓、配电箱、采光窗 |
| `lens:amenity_proof` | 配套证明镜头，例如食堂、电梯、宿舍、公寓 |
| `lens:location_context` | 区位上下文，例如周边道路、路口 |
| `lens:environment_context` | 环境上下文，例如园区外部环境 |
| `lens:environment_proof` | 环境证明镜头，例如明确可见的平峦山远景 |
| `lens:opening_context` | 开场建立空间的镜头，例如园区入口 |
| `lens:signage_proof` | 标识证明镜头，例如消防疏散图、导览图 |
| `lens:structure_detail` | 结构细节，例如梁板、架空层、夹层结构 |
| `lens:transition_detail` | 转场/动线镜头，例如楼梯、出入口、走廊 |
| `lens:interior_showcase` | 室内展示镜头，例如六楼办公装修空间 |

剪辑时的优先级建议：

- 主空间展示优先查 `lens:primary_showcase`。
- 卖点证明补镜优先查 `lens:detail_proof / lens:amenity_proof / lens:signage_proof`。
- 开头和转场优先查 `lens:opening_context / lens:transition_detail / lens:location_context`。

### 9.5 多层标签字段分工

修正版包里的 `metadata/tag_review.csv` 和 `merchant_media_clips.json` 使用了多组标签字段。建议沿用这个分工：

| 字段 | 用途 |
| --- | --- |
| `title` | 给人看的短标题，说明这条素材是什么 |
| `description` | 一句话描述画面可见内容 |
| `tags` | 综合检索标签，包含 `role:`、`lens:` 和关键中文词 |
| `industryTags` | 行业标签，例如工业地产、工业园区、厂房租赁 |
| `sceneTags` | 场景/空间标签，例如一楼、厂房内部、园区入口 |
| `shotTags` | 镜头语言/构图用途，例如室内扫拍、证明镜头、标识特写 |
| `peopleTags` | 人物情况，例如无明显人物、少量远景人物、真人入镜 |
| `qualityTags` | 质量与审核状态，例如真实拍摄、预览帧复核、待人工最终确认 |
| `queryHints` | 面向检索召回的自然语言短语 |
| `tagConfidence` | 标签置信度，预览帧复核阶段一般不要写满分 |
| `review_notes` | 人工复核说明，记录为什么加/删某些标签 |

当前项目代码还没有完整结构化自由标签字段时，可以先把这些信息放进 `trace_payload.materialAnalysis` 或对应 metadata 中；真正用于路由的仍然是 `usageType / retrievalTargets / status`。

```text
tags：成员上传、真人口播、出镜讲解、招商讲解、talking_head、竖屏
qualityTags：成员素材、不进入商家素材库、需按成员上传链路处理
```

### 9.7 人工复核要求

素材包生成后至少做这几类校验：

- 商家素材数量和 clip 数量一致，例如厂房包为 27 条商家素材、27 条 merchant clip。
- 成员上传素材数量单独统计，例如 3 条口播素材，只进 member upload 清单。
- `tag_review.csv` 只包含商家素材，不混入成员口播。
- `all_asset_tags.csv` 可以包含商家素材 + 成员素材总览，但必须有 `asset_scope` 区分。
- 每条商家 clip 至少有 3 个以上有效检索标签。
- 每条素材都有 `role:` 和 `lens:`，便于 worker 按场景和用途检索。
- 基于预览帧打标时，`tagSource` 要说明来源，例如 `visual_preview_3frame_pexels_style_tag_revision`。
- `qualityTags` 中保留 `待人工最终确认`，不要把预览帧判断写成最终事实。

### 9.8 典型错误

容易导致误召回的错误打法：

- 每条一楼素材都写 `2000平 / 层高5.56米 / 生产仓储办公`。
- 停车位素材同时写宿舍、公寓、食堂、电梯。
- 道路环境素材直接写近地铁、近物流园，但画面里没有直接证据。
- 平峦山公园周边道路和平峦山山体远景混成同一类标签。
- 成员口播素材进入商家公共素材库，导致后续其他成员/任务误用。
- 只有中文卖点，没有 `role:` 和 `lens:`，worker 无法区分主画面、证明镜头和转场镜头。

## 10. 后续建议

为了让“标签打法”更稳定，后续可以补三个增强点：

1. 增加结构化自由标签字段，例如 `materialTags: string[]`，由前端 note 或解析 worker 生成。
2. 视频上传完成后，在 `/api/media/complete` 或索引 worker 中回写 `status=ready` 和 `retrievalTargets=["video_edit_asset"]`。
3. 对视频素材增加更细的片段级标签，例如 `sceneTags / speakerTags / locationTags / shotTags`，供 worker 做分镜匹配。

当前阶段不要把所有标签都塞进标题；标题用于人看，`note / materialAnalysis` 用于检索，`usageType / retrievalTargets / status` 用于路由。
