# V0.1 ApifyProviderAdapter 接口设计草案

## 1. 设计目的

`Apify` 不能直接散落在页面代码里调用。

我们需要一个中间层：

```text
ImportJob -> ProviderAdapter -> Apify Actor -> NormalizedResult -> Database
```

这个中间层暂时命名为：

- `ApifyProviderAdapter`

它的目的：

- 隔离不同 actor 的输入差异
- 固化字段映射
- 统一错误处理
- 未来方便替换 `Bright Data` 或自建 Worker

---

## 2. 当前不做复杂抽象

第一版不要设计成很重的插件系统。

只需要满足：

- 能跑小红书
- 能跑抖音
- 能落到当前数据表
- 后续能换供应商

所以推荐采用：

```text
ImportProvider
  └── ApifyProviderAdapter
```

而不是一开始做：

- 多供应商自动路由
- 动态 actor 配置后台
- 复杂 provider marketplace

---

## 3. 核心类型草案

## 3.1 平台与导入类型

```ts
type Platform = 'xiaohongshu' | 'douyin';

type ImportType =
  | 'detail'
  | 'creator'
  | 'comments';
```

当前 schema 里还有 `search`，但 `V0.1-A` 可以先不接。

---

## 3.2 导入请求

```ts
type ImportRequest = {
  platform: Platform;
  importType: ImportType;
  url: string;
  options?: {
    includeComments?: boolean;
    maxItems?: number;
    maxComments?: number;
  };
};
```

说明：

- `detail`：`url` 是帖子链接
- `creator`：`url` 是主页链接
- `comments`：`url` 是帖子链接

---

## 3.3 Provider run

```ts
type ProviderRun = {
  provider: 'apify';
  actorId: string;
  runId: string;
  datasetId: string;
  status: 'READY' | 'RUNNING' | 'SUCCEEDED' | 'FAILED' | 'ABORTED' | 'TIMED-OUT';
  usageTotalUsd?: number;
  raw?: unknown;
};
```

建议保存到：

- `import_jobs.log_payload`

---

## 3.4 标准化来源内容

```ts
type NormalizedSourceItem = {
  platform: Platform;
  sourceType: 'detail' | 'creator' | 'search' | 'manual_text';
  externalItemId?: string;
  sourceUrl: string;
  creatorId?: string;
  creatorName?: string;
  title?: string;
  bodyText?: string;
  scriptText?: string;
  engagementSnapshot?: Record<string, unknown>;
  structureSummary?: Record<string, unknown>;
  tracePayload: unknown;
};
```

对应数据库：

- `source_items`

---

## 3.5 标准化评论

```ts
type NormalizedComment = {
  externalCommentId?: string;
  parentExternalCommentId?: string;
  authorName?: string;
  content: string;
  likeCount?: number;
  replyCount?: number;
  publishedAt?: string;
  tracePayload?: unknown;
};
```

对应数据库：

- `imported_comments`

当前 `imported_comments` schema 里没有 `trace_payload` 字段。  
如果后续要保留评论原始包，可以考虑补字段：

```sql
alter table imported_comments
add column trace_payload jsonb not null default '{}'::jsonb;
```

这个不是第一版硬要求，但建议加。

## 5. Actor 路由规则

## 5.1 小红书

```ts
const xiaohongshuActorMap = {
  detail: {
    actorId: 'huggable_quote~xiaohongshu-all-in-one-scraper',
    input: (url: string) => ({
      mode: 'postDetail',
      postUrls: [url],
      maxItems: 1,
    }),
  },
  creator: {
    actorId: 'easyapi~rednote-xiaohongshu-user-posts-scraper',
    input: (url: string, maxItems = 20) => ({
      profileUrls: [url],
      maxItems,
    }),
  },
  comments: {
    actorId: 'easyapi~all-in-one-rednote-xiaohongshu-scraper',
    input: (url: string, maxItems = 30) => ({
      mode: 'comment',
      postUrls: [url],
      maxItems,
    }),
  },
};
```

补充：

- 小红书 `profile` 可在后续作为 `creator` 的前置补充
- 当前 `creator` 第一目标是拿帖子列表，所以先路由到 `userPosts`

## 5.2 抖音

```ts
const douyinActorMap = {
  detail: {
    actorId: 'easyapi~douyin-video-downloader',
    input: (url: string) => ({
      links: [url],
    }),
  },
  comments: {
    actorId: 'natanielsantos~douyin-comments-scraper',
    input: (url: string, maxItems = 30) => ({
      postUrls: [url],
      maxCommentsPerPost: maxItems,
      maxRepliesPerComment: 1,
    }),
  },
};
```

抖音 `creator` 暂时不在第一批强制接入。  
如果后续要做，再找对应 actor。

## 6. 字段标准化规则

## 6.1 小红书 detail -> source_items

```ts
function normalizeXhsDetail(item: any): NormalizedSourceItem {
  return {
    platform: 'xiaohongshu',
    sourceType: 'detail',
    externalItemId: item.id,
    sourceUrl: item.postUrl,
    creatorId: item.user?.userId,
    creatorName: item.user?.nickname,
    title: item.title,
    bodyText: item.description || item.content,
    scriptText: item.content || undefined,
    engagementSnapshot: {
      likes: item.likes,
      comments: item.comments,
      collects: item.collects,
      shares: item.shares,
    },
    structureSummary: {
      type: item.type,
      tags: item.tags,
      imageCount: Array.isArray(item.images) ? item.images.length : 0,
      hasVideo: Boolean(item.video),
      ipLocation: item.ipLocation,
      createTime: item.createTime,
    },
    tracePayload: item,
  };
}
```

## 6.2 小红书 comments -> imported_comments

```ts
function normalizeXhsComments(item: any): NormalizedComment[] {
  const main = item.comment;
  if (!main?.content) return [];

  const parent: NormalizedComment = {
    externalCommentId: main.id,
    authorName: main.user_info?.nickname,
    content: main.content,
    likeCount: Number(main.like_count || 0),
    replyCount: Number(main.sub_comment_count || 0),
    publishedAt: main.create_time
      ? new Date(Number(main.create_time)).toISOString()
      : undefined,
    tracePayload: main,
  };

  const replies = (main.sub_comments || []).map((reply: any) => ({
    externalCommentId: reply.id,
    parentExternalCommentId: main.id,
    authorName: reply.user_info?.nickname,
    content: reply.content,
    likeCount: Number(reply.like_count || 0),
    replyCount: 0,
    publishedAt: reply.create_time
      ? new Date(Number(reply.create_time)).toISOString()
      : undefined,
    tracePayload: reply,
  }));

  return [parent, ...replies];
}
```

## 6.3 抖音 detail -> source_items

```ts
function normalizeDouyinDetail(item: any): NormalizedSourceItem {
  const result = item.result || item;

  return {
    platform: 'douyin',
    sourceType: 'detail',
    externalItemId: result.id || item.id,
    sourceUrl: item.url,
    creatorName: result.author || item.author,
    title: result.title || item.title,
    bodyText: result.title || item.title,
    engagementSnapshot: {},
    tracePayload: item,
  };
}
```

## 7. ImportJob 状态机

推荐状态：

```text
pending
running
succeeded
partial
failed
```

状态含义：

| 状态 | 含义 |
|---|---|
| `pending` | 已创建，还没调用 Apify |
| `running` | Apify run 已启动 |
| `succeeded` | 主要内容已成功入库 |
| `partial` | 正文成功，但评论或部分列表失败 |
| `failed` | 主要内容失败，不能进入改写 |

---

## 8. 错误类型

建议内部错误码：

```ts
type ImportErrorCode =
  | 'INVALID_INPUT'
  | 'PROVIDER_AUTH_FAILED'
  | 'PROVIDER_RATE_LIMITED'
  | 'PROVIDER_MEMORY_LIMIT'
  | 'PROVIDER_RUN_FAILED'
  | 'EMPTY_DATASET'
  | 'LOW_QUALITY_RESULT'
  | 'NORMALIZATION_FAILED';
```

错误处理建议：

| 错误 | 是否可重试 | 用户提示 |
|---|---|---|
| `INVALID_INPUT` | 否 | 链接格式不支持 |
| `PROVIDER_MEMORY_LIMIT` | 是 | 当前导入繁忙，请稍后重试 |
| `EMPTY_DATASET` | 视情况 | 未抓到内容，请换完整链接 |
| `LOW_QUALITY_RESULT` | 视情况 | 内容字段不完整，建议重新复制链接 |
| `PROVIDER_RUN_FAILED` | 是 | 服务商执行失败，可重试 |

## 9. 质量校验

run 成功后不要直接认为导入成功。

必须做最小质量校验：

## 9.1 detail

至少满足：

- 有 `externalItemId`
- 有 `sourceUrl`
- `title` 或 `bodyText` 至少有一个
- `creatorName` 尽量有

如果只有 `id / url`，标记：

- `LOW_QUALITY_RESULT`

## 9.2 comments

至少满足：

- dataset item 数量大于 `0`
- 至少一条 comment 有 `content`

否则：

- 如果正文成功，整体任务可标记 `partial`

---

## 10. 并发策略

第一版建议：

```text
global_import_concurrency = 1
merchant_import_concurrency = 1
default_max_comments = 30
default_creator_posts = 20
```

原因：

- 免费/低阶 Apify 套餐有 actor 内存并发限制
- 评论任务成本波动较大
- V0.1-A 重点是先跑通闭环，不是追求吞吐

---

## 11. 是否需要新增表

第一版可以不新增表，先用：

- `import_jobs.log_payload`
- `source_items.trace_payload`

但建议给 `imported_comments` 增加：

```sql
trace_payload jsonb not null default '{}'::jsonb
```

原因：

- 评论字段会变
- 后续做评论洞察时，原始数据很有价值

---

## 12. 当前推荐默认值

```ts
const importDefaults = {
  xiaohongshu: {
    maxCreatorPosts: 20,
    maxComments: 30,
    requireFullUrl: false,
    preferFullUrl: true,
  },
  douyin: {
    maxComments: 30,
  },
};
```

`requireFullUrl` 暂时不强制为 `true`。

原因：

- 用户可能只会贴裸链接
- 我们可以先尝试
- 如果结果低质量，再提示用户换完整链接

---

## 13. 一句话结论

第一版实现时，不要在页面里直接写 Apify 调用。

应该先实现：

> `ApifyProviderAdapter + ImportJob 状态机 + 结果质量校验`

这样未来不管换 `Bright Data`，还是补自建 `Worker`，都不会推翻上层产品逻辑。
