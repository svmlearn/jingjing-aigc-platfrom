# 03 商家团队素材库与标签

## 摘要

商家团队素材库只接收商家端确认入库的素材。用户端 / 成员端临时上传素材不入库、不切片、不标签化、不长期保存。

## 依据

外部依据：

- OWASP 文件上传建议必须做认证、授权、类型校验和存储隔离。
- Pexels API 本身不要求我们返回内部标签；标签是私有检索层能力，外部只需要 Pexels-like 响应。
- GitHub / Supabase 多租户讨论中的共同经验是：tenant / merchant 字段应在业务查询中显式出现，不能只寄托于 RLS；因此素材表必须直接带 `merchant_id` 并建索引。
- 预签名上传社区经验表明，上传完成不等于内容可信；素材入库前必须通过媒体解析和安全检查。

项目依据：

- 当前视频工作台临时制作素材已通过 `content_draft` / `asset_objects` 支撑当前任务。
- 当前素材库逻辑已有 `material_workbench_references` 和 `merchant_id` 边界。
- 新增私有素材库应避免污染当前 `content_draft` 临时素材链路。

## 专业社区经验落地规则

这里的“参考 Pexels”只参考请求 / 响应外壳，不照搬 Pexels 的公共素材池模式。GitHub / Supabase 多租户讨论、上传安全经验和 agent-skills 的渐进式实现方法在本板块落成以下规则：

- 素材表直接保存 `merchant_id` 并建索引；不要通过 join 临时推导商家归属后再过滤。
- 标签是内部召回字段，不是 Pexels response 的必需字段；OpenStoryline 不需要知道我们的标签体系。
- 入库前先做确定性媒体解析，再做 LLM / VLM 标签；宽高、时长、方向不能由模型猜。
- 标签生成必须有置信度和人工纠错入口；低置信度素材不能自动进入高优先级召回。
- 用户端 / 成员端临时素材即使在 COS 中存在，也不能被 `merchant_media_*` 引用。
- 按 agent-skills 的 incremental implementation，先用少量 fixture 跑通入库和标签合同，再扩大到批量处理。

## 工作边界

新增表建议：

```text
merchant_media_assets
- id
- merchant_id
- uploaded_by_user_id
- media_type
- source_cos_key
- original_filename
- mime_type
- file_size_bytes
- status
- failure_reason
- created_at
- updated_at
```

```text
merchant_media_clips
- id
- asset_id
- merchant_id
- media_type
- cos_key
- thumb_cos_key
- description
- tags
- industry_tags
- scene_tags
- shot_tags
- people_tags
- quality_tags
- tag_confidence
- tag_source
- orientation
- duration_seconds
- width
- height
- status
- failure_reason
- created_at
- updated_at
```

入库来源：

- 允许：商家端素材库上传、商家端明确“加入团队素材库”。
- 禁止：成员端任务临时素材、视频工作台当前草稿素材、voice profile audio、worker 输出成片。

入库状态机：

```text
uploaded
-> validating
-> processing
-> tagging
-> ready
```

失败 / 纠错状态：

```text
validation_failed
processing_failed
tagging_failed
needs_reclip
needs_retag
quarantined
archived
```

## 硬门禁

入库门禁：

- 必须有 `merchant_id`。
- 必须来自商家端素材库入口或显式入库动作。
- 必须记录上传操作者 `uploaded_by_user_id`。
- 必须完成 COS 对象存在检查。
- 必须通过文件类型、大小、时长上限检查。
- 必须使用幂等 key，避免同一对象重复入库。
- 必须记录 `source = merchant_upload` 或等价字段，禁止来源不明素材入库。
- 必须记录 `processing_trace_id` 或等价字段，能追踪一次上传、切片、标签、入库全链路。

切片门禁：

- 视频宽高、时长、方向必须来自真实媒体解析，不允许由 LLM 猜。
- clip 生成失败不得写 `ready`。
- 缩略图缺失时不得进入 Pexels-compatible ready 池。
- LLM 标签失败时允许 `tagging_failed`，但不得参与自动召回。
- 切片 worker 必须可重试；同一 `asset_id + clip_index` 重试不得生成重复 ready clip。

标签门禁：

- `description` 必须非空。
- `tags` 至少 3 个。
- `tag_confidence` 低于阈值时不得自动 ready，进入 `needs_review` 或 `needs_retag`。
- `orientation` 必须是 `portrait` 或 `landscape`。
- `duration_seconds`、`width`、`height` 必须非空。
- 标签必须来自已验证的媒体内容，不能只根据文件名或商家输入生成。

## 检查功能

自动检查：

- ready asset 是否至少有一个 ready clip。
- ready clip 的 COS 对象和缩略图是否存在。
- 标签是否为空、重复、过长。
- `tag_confidence` 是否缺失，低置信度标签是否误入 ready。
- LLM 标签和文件类型是否冲突，例如图片 clip 却有 duration。
- 是否有 `content_draft` 临时素材进入 `merchant_media_*`。
- 同一 COS key 是否重复入库。
- ready clip 是否缺少 `merchant_id` 索引条件。
- 是否存在 `tagging_failed` 仍参与检索。

抽检：

- 每批至少抽查 5 条标签。
- 标签必须能解释画面主体、场景和镜头类型。
- 不确定内容不得写成确定事实。

## 纠错功能

- 标签不准：标记 `needs_retag`，重新跑 VLM / LLM。
- 切片不准：标记 `needs_reclip`，重跑切片。
- COS 缺失：标记 `missing_object`，从检索池下架。
- 误入库：标记 `wrong_source`，从 `merchant_media_*` 移除，必要时删除 COS 对象。
- 内容敏感或授权不明：标记 `quarantined`，不参与召回。
- 重复入库：保留一条 canonical 记录，其余标记 `duplicate`。
- worker 半途失败：保留原 asset，删除半成品 clip，重试从 `processing` 开始。

## 板块验收

- 商家端上传 3-10 个视频 / 图片后能生成 `merchant_media_assets` 和 `merchant_media_clips`。
- 每个 ready clip 都有真实宽高、方向、时长、缩略图、description、tags。
- 标签抽检能解释“为什么这个素材会被某个 query 召回”。
- 用户端 / 成员端临时素材不会产生 `merchant_media_assets` 或 `merchant_media_clips`。
- 错误素材可下架、重切、重打标。
