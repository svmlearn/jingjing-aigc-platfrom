V2.7 Context Slimming Review

咨询 Agent 上下文工程瘦身实现复评

基于 bf7b438 feat: slim consultation agent context payload、V2.7 PRD 和 Claude Code reference 的对照结论： 主模型的 user JSON 已经明显变轻，但冗余没有完全消失，一部分从 user JSON 转移到了 system prompt 和 JSON tool loop 的状态消息里。

方向对 移除了主 user JSON 中的 contextInjection、toolResults、skillDisclosure、budget、expertTraffic。
还偏重 system prompt 仍携带大量流程型规则，JSON tool loop 仍重复传 observations 摘要。
下一步 把 budget 从报告改成执行器，把工具结果压缩放到消息预处理管线，而不是业务 payload。
核心思想 当前实际 冗余回流 Claude Code 对照 修改后形态 收口清单

01 Principle

PRD 里的瘦身核心不是少几个字段，而是分清三条边界

主模型只看当前业务决策必要上下文；工具协议只承载真实工具结果；debug/runtimeSnapshot 保留完整工程痕迹，但不参与主模型判断。

核心判断
LLM 可见 只给本轮必要事实

merchant、userMessage、round、expertRouting、strategySnapshot、currentKnowledgeMatches。

Tool 协议 工具结果保持消息流权威

native 路径用 role=tool，JSON 路径用 tool_result。失败、跳过、拒写都必须原样回到模型。

Debug 内部 完整上下文只留给排查

budget、完整历史命中、skillDisclosure、expertTraffic、omission trace 都属于 runtimeSnapshot。

04 Claude Code Reference

从 Claude Code 对照出来的可借鉴方法

这里不是照搬 Claude Code，而是提炼对咨询 Agent 有用的工程原则：消息流是事实源，压缩发生在 API 前处理管线，debug 边界不混入业务 payload。

参考方法
1
API 前先做上下文预处理管线 pipeline
Claude Code 在发 API 前依次做工具结果预算、snip、microcompact、collapse、autocompact。咨询 Agent 现在只有 budget report，还缺真正的 pipeline。
2
旧工具输出只压缩消息，不改写事实源 microcompact
Claude Code 的 MicroCompact 是把旧工具结果替换成占位符，原始内容仍在 transcript/debug 中。咨询 Agent 也应该压缩旧 tool result，而不是额外塞 observations 摘要。
3
tool_use / tool_result 必须保持成对 已部分做到
当前 selectMessagesForChatCompletion 已避免简单 slice 破坏 native tool pair，这是正确方向。下一步应在这个选择器里加入 token/字符预算和工具结果压缩。
4
静态 prompt 和动态 prompt 应该分层 cache friendly
Claude Code 用动态边界区分静态规则和每轮上下文。咨询 Agent 现在每轮拼一大段 system 字符串，后续可把稳定规则、工具协议、业务 intent 规则拆成独立 sections。

07 Closeout Checklist

建议给下一位实现 Agent 的收口清单

这份清单可以直接作为下一轮小补丁任务边界。重点是少改，但改到真正符合 PRD 思想。

可执行
优先级 改动项 验收口径 建议文件
P0 压缩 native/json tool loop system prompt 的日历与检索流程规则。 保留“工具结果诚实性”和“团队内容已生成时修改前确认”两类硬规则，其余改成简短判断原则。 consultation-service.ts
P0 移除或极简化 JSON tool loop 的 observations。 不再重复传每个工具 summary；只保留状态名列表，要求模型读取已有 tool_result。 runtime.ts
P1 删除或降级旧 ContextInjection builder。 主代码不再导出旧大对象；如需保留，只能改名为 legacy debug 并测试确保不可用于主 prompt。 context.ts
P1 把 budget report 升级为 context preflight enforcer。 超限字段实际裁剪或 omit；debug 记录裁剪前后长度和原因。 context.ts、ai-runtime.ts
P2 补 payload 级单测，而不是只做源码字符串断言。 mock createChatCompletion，断言最终 messages 中没有 contextInjection/toolResults/skillDisclosure/budget/expertTraffic，且没有重复 observations summary。 consultation-service.test.ts
一句话结论

这次实现已经把“主 user JSON 大对象”瘦下来了，方向是对的；但还没有完成“上下文工程瘦身”。真正完成的标志是： 流程规则不再长期压住模型、工具结果不再被重复摘要、budget 能实际裁剪、旧 ContextInjection 不再有回归入口。
